## 一、项目结构一句话

这个项目不是常规前后端分离框架项目。

它现在的核心结构非常直接：

- 前端主文件：`public/index.html`
- 后端主文件：`api/index.js`
- 测试文件：`tests/*.test.js`

也就是说：

- 前端基本都堆在一个大文件里
- 后端接口和业务规则也主要堆在一个大文件里

## 四、当前代码组织的真实特点

### 1. 前端是单页大文件

不是 React，不是 Vue，不是组件化工程。

优点：

- 直接
- 改一个页面速度快

缺点：

- 文件很大
- 上下文耦合强
- 搜索定位很重要
- 改一处容易影响别处

### 2. 后端是单入口大文件

不是严格分层架构。

优点：

- 规则集中
- 搜索方便

缺点：

- 接口、领域逻辑、数据处理混在一起
- 改规则要特别小心联动

### 3. 测试是 Node assert 风格

不是大型测试框架那种结构。

优点：

- 简单直接

缺点：

- 需要你自己先找对应测试文件

## 六、改代码时的实操建议

### 1. 先搜函数名，不要盲翻大文件

优先用全文搜索定位：

- 页面名
- 渲染函数
- 弹窗函数
- 后端构造函数
- 对应测试名

### 2. 先看测试，再改实现

因为这个项目很多行为已经被测试固定住了。

### 3. 前端改展示，后端改规则

不要在前端偷偷补后端应该负责的业务规则。

### 4. 遇到“状态不对”，先看是不是前端推导状态

比如排课的 `已结束`，一部分是前端根据时间推出来的。

### 5. 遇到“余额不对”，不要只看列表页

先查：

- 购买 / 订单
- 权益账户 / 会员账户
- 流水
