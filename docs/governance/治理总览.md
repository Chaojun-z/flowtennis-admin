## 1. 本文件解决什么问题

本文件只做一件事：让新 agent、新开发、新协作者知道当前治理文档应该按什么顺序读，哪些是生效规则，哪些是业务规则，哪些只是历史记录。

它不修改任何业务口径，不替代任何需求文档，不替代测试结果。

## 2. 当前治理分三段

### 2.1 开工前

1. 先读硬规则：
   - `/Users/shaobaolu/Desktop/FlowTennis/AGENTS.md`
   - `/Users/shaobaolu/Desktop/FlowTennis/flowtennis-mgmt-main/AGENTS.md`
2. 再读任务相关业务规则：
   - PRD 正本：`docs/prd/source/`
   - 数据口径正本：`docs/FlowTennis全平台数据口径总表.md`
   - 核心数据字典：`docs/平台核心数据字典.md`
   - 核心表关系：`docs/核心表关系图.md`
3. 动代码前做影响面检查：
   - `docs/数据口径变更检查清单.md`
   - 本次会影响哪些页面、接口、表、指标、测试，必须先说明。

### 2.2 开工时

1. 只改本次需求范围内的文件，不顺手重构。
2. 命中财务、课包、权益、订场、会员、生产写入时，按高风险任务处理。
3. 代码改动必须和承诺、验收、测试一一对应。
4. 如果发现旧文档和当前规则冲突，不能自行选旧口径，必须标明冲突并以当前硬规则和 PRD 正本为准。

### 2.3 开工后

1. 普通变更至少跑对应测试。
2. 财务相关变更必须跑 `npm run guard:finance`。
3. 发布级变更必须跑 `npm run guard:release`。
4. 生产写入、导入、修数完成后，不能只看数据库，必须核对线上接口和前端展示。
5. 未验证的范围必须明确写“未验证”，不得用“已完成”覆盖。

## 4. 当前优先级

1. 用户最新明确指令。
2. 根目录 `AGENTS.md`。
3. 仓库 `AGENTS.md`。
4. PRD 正本 `docs/prd/source/`。
5. 数据口径正本 `docs/FlowTennis全平台数据口径总表.md`。
6. 本治理目录。
7. 普通说明文档、历史报告和旧方案。

## 5. 更新原则

1. 影响架构，才更新架构文档。
2. 影响字段、指标、状态、数据关系，才更新口径和字典。
3. 影响页面、流程、验收，才更新 PRD。
4. 普通页面需求只更新对应 PRD、影响面记录和测试映射。
5. 旧方案不直接删除，先在文档状态清单中标记状态和替代入口。
