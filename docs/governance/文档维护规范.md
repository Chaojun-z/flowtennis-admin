# FlowTennis 文档维护规范

> 文档类型：治理规范
> 状态：生效
> 版本：2026-08-24
> 生效日期：2026-08-24
> 最后审查日期：2026-08-24
> 维护人：FlowTennis 项目负责人
> 唯一依据：用于规范文档状态和维护方式，不改变业务口径。
> 替代文档：无

## 1. 所有正式文档必须有状态信息

新增或升级为正式依据的 Markdown 文档，标题下必须写：

```md
> 文档类型：硬规则 / PRD 正本 / 数据口径 / 业务规则 / 执行流程 / 审计报告 / 历史记录
> 状态：生效 / 草案 / 已废弃 / 历史记录
> 版本：YYYY-MM-DD 或语义版本
> 生效日期：YYYY-MM-DD
> 最后审查日期：YYYY-MM-DD
> 维护人：负责人或角色
> 唯一依据：本文能决定什么，不能决定什么
> 替代文档：无 / 被哪个文档替代
```

## 2. 状态定义

| 状态 | 含义 | 能否作为开发依据 |
| --- | --- | --- |
| 生效 | 当前规则或正本 | 可以 |
| 草案 | 方案讨论中，尚未执行 | 不可以直接作为开发依据 |
| 部分过期 | 方向仍可参考，但当前事实或命令已经变化 | 只能按文内最新状态说明使用 |
| 历史记录 | 只记录当时情况或事故复盘 | 只能参考原因，不能覆盖当前规则 |
| 已废弃 | 明确不再使用 | 不可以 |

## 3. 文档类型定义

| 类型 | 用途 |
| --- | --- |
| 硬规则 | agent 和开发必须遵守的红线 |
| PRD 正本 | 页面、流程、功能、验收标准 |
| 数据口径 | 字段、指标、状态、计算规则 |
| 业务规则 | 业务链路、表关系、履约模型 |
| 执行流程 | 开发、测试、发布、修数、回滚 |
| 审计报告 | 某次只读检查结果 |
| 历史记录 | 旧方案、旧阶段结论、事故复盘 |

## 4. 修改规则

1. 不允许同一条规则在多个文档里各写一套不同版本。
2. 旧文档如果过期，先标状态和替代入口，不直接删除。
3. 改 PRD 必须同步检查数据口径、测试门禁和影响页面。
4. 改数据口径必须同步检查字段字典、读模型、页面展示和回归测试。
5. 改发布流程必须同步检查 `package.json`、CI 配置和实际命令。
6. 历史审计报告不能直接变成当前规则，必须迁移到正式规则文档后才生效。

## 5. 每次需求是否要改三大文档

不需要每个需求都同时修改架构、数据口径和业务规则。

正确规则：

1. 影响架构，才更新架构文档。
2. 影响字段、指标、状态、数据关系，才更新口径和字典。
3. 影响业务流程，才更新业务逻辑或 PRD。
4. 普通页面需求只更新对应 PRD、影响面记录和测试映射。
