# 数据口径变更检查清单

> 用途：所有新需求、bug 修复、页面调整、导入修数、报表改动，在动代码前先过这张清单。
> 第一事实源：`docs/business-rules/FlowTennis全平台数据口径总表.md`。
> 文档类型：执行流程
> 状态：生效
> 版本：2026-08-24
> 生效日期：2026-08-24
> 最后审查日期：2026-08-24
> 维护人：FlowTennis 项目负责人
> 唯一依据：口径相关变更的开工前检查清单；具体字段和指标定义仍以数据口径总表为准。
> 替代文档：无

## 1. 是否触发口径检查

只要命中任一项，就必须按本文档执行：

- 字段名变化：例如姓名、手机号、来源、校区、跟进人、成交教练、课包归属教练。
- 指标变化：例如总成交、转化率、复购率、续购率、总收入、已入账、待履约。
- 页面新增统计卡片、筛选、导出字段、排序字段。
- 财务、课包、权益、会员储值、订场消费、核销、退款、作废、补差。
- 数据清洗、导入、修数、历史回填。

## 2. 开发前检查

- [ ] 数据口径总表已更新或确认无需更新
- [ ] 平台核心数据字典已更新或确认无需更新
- [ ] 旧字段 -> 标准字段映射已确认
- [ ] 口径 ID、字段名、公式、时间口径、去重规则、排除规则已确认
- [ ] 财务金额口径、课包核销与权益口径、数据质量与异常排除口径已检查

## 3. 实现检查

- [ ] 统一读模型已更新或确认无需更新
- [ ] 页面没有新增临时计算口径
- [ ] 页面只读取统一层结果或统一访问器
- [ ] API 没有新增一套页面专用口径
- [ ] 如使用摘要缓存，已加入内容矛盾自检，不能只靠版本号判断缓存可信
- [ ] 缓存命中时仍能证明页面字段来自统一读模型最终输出，而不是直接展示缓存原字段
- [ ] 历史字段只作为兼容别名，不作为新标准字段继续扩散
- [ ] 线索成交类型如涉及陪打，已同步到成交类型字典、线索筛选、成交信息和排课入口
- [ ] 新增一级课程类型时，已同步到课程类型唯一字典、课程产品、课包产品、购买、权益、排课、教练课时统计、飞书同步规则
- [ ] 专项课如涉及水平和主题，已使用 `skillLevelMin/skillLevelMax/specialTopic/courseDisplayName`，没有把专项课归入小班课
- [ ] 线索成交类型包含课程/陪打/订场/订场会员时，已补齐对应学员、订场用户、会员账户身份，且未自动生成财务流水
- [ ] 第三方导入、飞书排课同步如需自动匹配或自动建档，姓名必须精确命中；`2人/4 人/多人/朋友/家长/学员/待定/未知` 等人数或占位文本必须进入人工确认
- [ ] 历史重复账号处理已先产出 dry-run 清单；合并、拆分、删除、改名不得和功能代码混在同一次写入里

## 4. 测试检查

- [ ] 跨页面一致性测试已补充或确认不涉及
- [ ] 已补充线上出过问题的反例测试，不能只测正常样本
- [ ] 自动导入/自动建档已覆盖姓名包含关系反例，例如 `理想团课` 不得命中 `理想`，`2人/4 人` 不得建成线索或学员
- [ ] 涉及摘要缓存时，已覆盖“缓存版本正确但内容矛盾”的失败样本
- [ ] 涉及日期时，已覆盖未来日期不得进入历史统计或最近记录的样本
- [ ] 同一客户同时课包 + 订场 + 储值时，总成交只算 1 人
- [ ] 陪打进教练工作量，不进教练课时量
- [ ] 线索成交为陪打或订场+陪打时，可以进入排课且课程类型为陪打
- [ ] 会员订场补差进总收入和场地收入，不重复计入会员储值收入
- [ ] 线索池顶部、留存与转化、经营分析对同一批样本出同一结果
- [ ] 退款、作废、测试、零权益、孤儿记录进入对应排除或异常规则

## 5. 提交前检查

- [ ] 本次是否影响统一口径已在提交说明或 PR 描述中写明
- [ ] 影响口径时，已写明口径 ID、影响页面、测试文件
- [ ] 涉及财务时，已运行财务门禁或说明不涉及财务计算
- [ ] 没有把修数脚本和功能开发混在同一次交付里
- [ ] 需要线上验收时，已验证线上静态脚本或接口包含本次提交的新代码标记
- [ ] 未完成线上生效验证前，最终汇报不得写“线上已修复”

## 6. 线索池 / 历史学员 / 在期学员专项门禁

只要触达线索池、历史学员、在期学员任一页面、接口、读模型、筛选、分页、顶部统计或摘要重建，就必须逐项检查：

- [ ] 是否触达线索池、历史学员、在期学员任一页面
- [ ] 是否核对三页 15 个顶部数字同源
- [ ] 学员指标是否只来自教学学员统一读模型最终输出
- [ ] 线索池是否没有自行计算 `historicalStudents`、`activeStudents`、`trialAttended`、`trialAttendedToFormalPurchase`
- [ ] 首屏、筛选、顶部统计是否未扫描 `ft_schedule`、`ft_purchases`、`ft_entitlements`、`ft_entitlement_ledger`、`ft_membership_benefit_ledger`、`ft_feedbacks` 大表
- [ ] GET 页面接口是否没有写库，打开页面不会自动新增、补写或改变 `ft_leads` 数量
- [ ] 筛选后顶部是否基于完整筛选结果，不是当前页 15 条
- [ ] 历史学员 / 在期学员列表 `total` 是否等于对应顶部总数
- [ ] `hasTrialAttended=false` 是否不会被明细里的“体验”文字反推覆盖
- [ ] 摘要重建是否先 dry-run，再确认线上实例，再写入，再摘要-only 复核
- [ ] 摘要重建报告是否没有生产学员明细，且没有提交到仓库
- [ ] 是否已运行 `node tests/customer-center-summary-fact-calibration.test.js`
- [ ] 是否已运行 `node tests/customer-center-filter-consistency.test.js`
- [ ] 是否已运行 `node tests/leads-safe-server-pagination.test.js`
- [ ] 是否已运行 `node tests/leads-view.test.js`
- [ ] 是否已运行 `node tests/page-data-requirements.test.js`
- [ ] 是否已运行 `node tests/lifecycle-standard-metrics.test.js`
- [ ] 是否已运行 `npm test`
- [ ] 任一项未通过时，是否已停止提交并明确说明未完成；不得说“完成、彻底解决、数据正确、速度已达标”
