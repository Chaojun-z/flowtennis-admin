# FlowTennis 自动化治理门禁说明

> 文档类型：执行流程
> 状态：生效
> 版本：2026-08-24
> 生效日期：2026-08-24
> 最后审查日期：2026-08-24
> 维护人：FlowTennis 项目负责人
> 唯一依据：说明当前已经自动执行的治理门禁，不替代 `AGENTS.md`、PRD 正本和数据口径正本。
> 替代文档：无

## 1. 已经自动生效的流程

统一入口：

```bash
npm run guard:governance-automation
```

该命令已接入：

```bash
npm run guard:release
```

CI 对 `main` 的 push 和 PR 执行 `guard:release`，所以治理自动化会随发布门禁一起执行。

## 2. 自动检查内容

1. 文档治理门禁：
   - 检查 `docs/README.md`、`docs/governance/*.md`、`docs/governance/change-records/*.md` 是否有状态头。
   - 检查治理入口文档中是否出现已登记的过期口径。
2. 需求变更记录门禁：
   - 自动识别本次变更文件。
   - L2 及以上变更必须有 `docs/governance/change-records/*.md`。
   - 变更记录必须写清影响页面、接口、表、指标、测试映射、异常豁免、事故反馈和发布后核验。
3. 风险分级门禁：
   - 根据变更文件自动判定 L1-L5。
   - 自动列出该等级对应的必跑检查。
4. 发布后核验门禁：
   - `guard:post-release` 是严格模式，缺少真实接口地址时会失败。
   - `guard:release` 仍使用 `guard:api-smoke` 的允许缺配置模式，避免没有 staging/线上密钥时阻塞普通代码 CI。

## 3. 自动生成变更记录

可执行：

```bash
npm run governance:record -- --title "本次变更标题"
```

它会根据当前 Git 变更自动生成变更记录草稿。草稿里的“待补”必须改成真实影响范围，否则后续人工审查不能视为完成。

## 4. 当前限制

1. 自动门禁能强制“必须有记录”，但不能自动理解用户口头决策的完整业务含义；业务判断仍要由 agent 填写。
2. 文档版本不会无脑自动滚动；只有相关文档被修改时，门禁要求它保持状态头和不含过期口径。
3. 发布后真实核验依赖 `FLOWTENNIS_API_SMOKE_BASE_URL`、管理员 token 或账号密码等环境变量；未配置时无法真实请求线上接口。
4. 历史文档仍不是一次性全量清完；当前自动门禁先覆盖治理入口和后续变更记录。
