# FlowTennis 数据问题快检与修复流程

> 文档类型：执行流程
> 状态：生效
> 版本：2026-08-27
> 生效日期：2026-08-27
> 最后审查日期：2026-08-27
> 维护人：FlowTennis 项目负责人
> 唯一依据：定义数据比对、异常排查、差异修复和复现验证的最低成本流程，不替代生产数据变更与回滚流程。
> 替代文档：无

## 1. 适用范围

以下四类任务都走本文：

1. 第三方数据比对。
2. 飞书同步数据比对。
3. 异常数据排查与修复。
4. 修复后复现排查。

## 2. 目标

1. 先用最少的时间和 token 找到差异。
2. 只查差异命中的少量记录，不默认全表扫。
3. 只修复已确认的差异，不顺手扩大范围。
4. 修复后只做一次复核，不无限追根究底。

## 3. 输入要求

每次发起前，优先只给这些最小信息：

1. 数据来源。
2. 对比目标。
3. 时间窗或批次号。
4. 具体单号、校区、页面、课程、学员、订单号或其他已知关键字。
5. 已发现的差异表现。

如果缺少以上信息，先补最小信息，再开始查。

## 4. 快检三步

### 4.1 先比对

1. 只看时间窗、批次号、单号和差异清单。
2. 先输出“哪里不一样”，不先猜“为什么不一样”。
3. 不允许为了找差异先扫全库、先翻整张表。

### 4.2 再定位

1. 只查差异命中的少量记录。
2. 只追和这批记录直接相关的页面、接口、表和字段。
3. 如果两轮还找不到，先停，返回当前差异和已查范围。

### 4.3 后修复

1. 只修已确认的错误记录。
2. 修复前先做 dry-run 或等价预览。
3. 修复后只核对原问题页、关联页和顶部统计。

## 5. 强制限制

1. 禁止默认全表扫描。
2. 禁止默认跨所有页面排查。
3. 禁止先读一堆无关治理文档再开始定位。
4. 禁止把“查不出来”变成无限扩大范围。
5. 禁止没有差异清单就直接写修复脚本。

## 6. 四类场景口径

### 6.1 第三方数据比对

1. 先按日期、批次、导出文件或外部单号比对。
2. 只输出差异行，不输出整表。
3. 差异行确认后再补差。

### 6.2 飞书同步数据比对

1. 先按同步批次、课程、学员、排课或订单号比对。
2. 先查同步前后差异，不先回扫全量历史。
3. 只补同步失败或缺失的记录。

### 6.3 异常数据排查与修复

1. 先锁定错误页面、错误字段、错误单号。
2. 只查这条链路上的直接依赖。
3. 只修当前错误，不顺手扩查相邻模块。

### 6.4 修复后复现排查

1. 先复查原问题是否还在。
2. 再查是否被某条写入或同步覆盖。
3. 第二轮仍找不到，就先停，不再无限扩大。

## 7. 结束条件

1. 差异已明确。
2. 修复范围已明确。
3. 复核页已通过。
4. 没有新的异常扩散。

如果任一项没满足，就不能宣布“已彻底解决”。
