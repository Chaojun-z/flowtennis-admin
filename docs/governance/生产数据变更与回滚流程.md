# FlowTennis 生产数据变更与回滚流程

> 文档类型：执行流程
> 状态：生效
> 版本：2026-08-24
> 生效日期：2026-08-24
> 最后审查日期：2026-08-24
> 维护人：FlowTennis 项目负责人
> 唯一依据：定义生产写入、修数、导入和回滚的最低流程，不替代具体修数方案。
> 替代文档：无

## 1. 适用范围

只要涉及生产写入、导入、修数、财务补账、会员/课包/权益/订场写入或回滚，都必须按本文执行。
纯查询、纯比对、纯排查先走 `docs/governance/数据问题快检与修复流程.md`，不默认进入本文。

## 2. 写入前

1. 功能开发和修数任务分开，不混在同一次交付。
2. 必须先 dry-run，产出目标记录、影响表、金额、权益、人数和风险清单。
3. 必须确认线上真实实例：
   - 请求线上 `/api/diag`
   - 本地 `TS_ENDPOINT` / `TS_INSTANCE` 必须与线上一致
4. 必须生成操作前快照或可恢复点。
5. 必须准备 `operationId` 或 `batchId`。
6. 必须写清回滚方案，整表或整库恢复必须先征得用户明确同意。

## 3. 写入时

1. 默认只允许最小范围写入。
2. 写入脚本必须显式 `--write`，默认 dry-run。
3. 写入报告必须记录：
   - `operationId`
   - `batchId`
   - 目标实例
   - 影响表
   - 写入数量
   - 金额和权益变化

## 4. 写入后

1. 核对数据库事实表。
2. 核对线上 API 或页面接口。
3. 核对前端页面展示。
4. 涉及财务时，核对财务总览、收入流水、已入账流水。
5. 任一页面不生效，不能说“已完成”，必须继续查接口和前端读取链路。

## 5. 回滚

1. 优先按 `operationId` 或 `batchId` 回滚单次操作。
2. 回滚前必须生成恢复前快照。
3. 回滚后必须生成恢复后快照。
4. 回滚后重新核对数据库、线上接口、前端展示。
5. 整库、整表、批量覆盖类恢复必须用户明确同意。
