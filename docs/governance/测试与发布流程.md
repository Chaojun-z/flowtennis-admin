## 1. 默认发布门禁

发布级变更执行：

```bash
npm run guard:release
```

当前组合包括：

1. `npm test`
2. `npm run guard:test-inventory`
3. `npm run guard:deps-security`
4. `npm run guard:finance`
5. `npm run guard:api-smoke`
6. 页面数据、权限、性能、生产安全等补充测试

## 2. 测试清单同步

`npm run guard:test-inventory` 检查：

1. `tests/*.test.js` 是否已进入任一 npm 脚本。
2. 未进入脚本的测试是否在 `config/test-inventory.json` 登记原因。
3. 已登记的测试如果后来进入脚本或文件不存在，门禁会要求清理登记。

新增测试不能只把文件放进 `tests/` 就结束；必须进入 `npm test`、专项脚本、发布门禁，或登记为暂不接入并写清原因。

## 3. 接口冒烟

`npm run guard:api-smoke` 默认执行只读接口冒烟。

需要真实冒烟时配置：

```bash
FLOWTENNIS_API_SMOKE_BASE_URL=https://staging.example.com
API_SMOKE_EXPECTED_INSTANCE=flow-staging
FLOWTENNIS_ADMIN_TOKEN=...
```

或配置：

```bash
FLOWTENNIS_ADMIN_USERNAME=...
FLOWTENNIS_ADMIN_PASSWORD=...
```

未配置真实 `baseUrl` 时，脚本会明确输出“未配置”，不能把这种结果说成“线上接口已验收”。

## 4. 发布后核验

发布后不能只看 Git push 成功。

必须确认：

1. 线上代码已部署。
2. 核心接口可返回 JSON。
3. 目标页面能看到新逻辑。
4. 生产写入类任务已完成数据库、线上接口、前端展示三段核对。
