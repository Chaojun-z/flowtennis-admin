## 1. 当前机制分层

### 1.1 开工前

1. 先读硬规则：根目录 `AGENTS.md`、仓库 `AGENTS.md`。
2. 再读业务正本：PRD 正本、数据口径总表、核心数据字典、核心表关系图。
3. 动代码前做影响面检查：确认会影响哪些页面、接口、表、指标和测试。
4. 需求、口径、表关系或验收变化时，先更新对应正本文档，再进入实现。
5. 仓库根目录新增一级目录或正式入口文件时，先走仓库根目录治理文档和自动门禁，再改目录结构。

### 1.2 开工时

1. 只改本次需求范围，不顺手重构。
2. 命中财务、课包、权益、订场、会员、生产写入时，自动按高风险处理。
3. 代码改动必须和承诺、验收、测试一一对应。
4. 如果改动触达测试清单、发布流程或 CI，必须同步更新 `package.json`、CI 配置和治理文档。

### 1.3 开工后

1. 普通变更跑对应局部测试。
2. 发布级变更跑 `npm run guard:release`。
3. 财务相关变更跑 `npm run guard:finance`，不能只测目标页面。
4. 生产写入、导入、修数必须完成数据库、线上接口、前端展示三段核对。
5. 最终汇报必须写清已覆盖范围、已跑测试、未覆盖风险。

## 2. 当前自动门禁

发布级门禁统一入口是：

```bash
npm run guard:release
```

当前已包含：

1. `npm test`
2. `npm run guard:test-inventory`
3. `npm run guard:governance-automation`
4. `npm run guard:deps-security`
5. `npm run guard:finance`
6. `npm run guard:api-smoke`
7. 页面数据、权限、性能、生产安全等补充测试
8. `governance:record` 自动同步 PRD 决策正本，并卡住异常豁免和事故闭环字段

CI 已配置在 `.github/workflows/ci-guard.yml`，对 `main` 分支 push 和 PR 执行 `npm run guard:release`。

## 3. 当前已知限制

1. `npm run guard:api-smoke` 未配置真实 `FLOWTENNIS_API_SMOKE_BASE_URL` 时，只说明“未配置”，不能当成线上接口已验收。
2. `config/test-inventory.json` 当前仍登记 80 个已被 Git 跟踪、但未接入默认脚本的历史测试；后续触达对应功能时，必须接入脚本或更新登记原因。
3. `npm run guard:governance-automation` 已能自动拦截缺状态头、缺变更记录、风险分级和发布后核验清单缺口。
4. `npm run governance:record -- --title "标题"` 已能按当前 Git 变更生成变更记录草稿，并同步 PRD 决策正本；但业务影响结论仍需要人工或 agent 填实。
5. 本地工作区仍存在其他任务或历史遗留的未提交文件；本次治理收口不清理这些文件。
6. 历史文档仍需以后按触达范围继续细分状态。

## 4. 后续补强优先级

1. 给 CI 配置真实接口冒烟环境变量和只读管理员凭据。
2. 分批把 80 个历史未接入测试纳入默认测试、专项脚本或发布门禁。
3. 触达历史文档时，继续补状态头和替代入口。
4. 清理历史 worktree、无关未跟踪文件和旧报告时，必须先由用户确认范围。
