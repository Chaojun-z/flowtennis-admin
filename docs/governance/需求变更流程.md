# FlowTennis 需求变更流程

> 文档类型：执行流程
> 状态：生效
> 版本：2026-08-24
> 生效日期：2026-08-24
> 最后审查日期：2026-08-24
> 维护人：FlowTennis 项目负责人
> 唯一依据：定义需求从开工前到开工后的检查流程，不替代具体业务 PRD。
> 替代文档：无

## 1. 开工前

1. 确认任务范围：
   - 要改哪些页面
   - 要改哪些接口
   - 要改哪些表
   - 要改哪些指标
   - 是否涉及财务、课包、权益、订场、会员、生产写入
2. 确认文档依据：
   - 需求看 PRD 正本
   - 字段和指标看数据口径总表
   - 表关系看核心数据字典和核心表关系图
   - 发布和测试看治理流程
3. 输出影响面：
   - 受影响页面
   - 受影响接口
   - 受影响数据表
   - 受影响指标
   - 应跑测试
   - 未覆盖风险

## 2. 开工时

1. 小范围修改，不做顺手重构。
2. 不把功能开发和生产修数混在一起。
3. 不在页面、接口或脚本里新增临时口径。
4. 触达高风险链路时，先补或确认测试，再改实现。
5. 连续报错超过 2 次，停止盲改，先汇报现状。

## 3. 开工后

1. 对照用户要求清单，确认是否全部覆盖。
2. 对照影响面清单，确认是否误伤非需求范围。
3. 跑对应测试：
   - 普通页面：对应页面和规则测试
   - 口径变更：跨页面一致性和数据标准测试
   - 财务相关：`npm run guard:finance`
   - 发布级变更：`npm run guard:release`
4. 如果需要线上确认，必须核对：
   - 代码已部署
   - 接口返回正确
   - 页面展示正确
   - 数据库、接口、前端三段链路一致

## 4. 最终汇报固定要求

最终汇报必须写清：

1. 已改什么。
2. 覆盖哪些页面、接口、表和指标。
3. 跑了哪些测试。
4. 哪些没有覆盖或仍有风险。
5. 是否已提交、推送、上线。没有做就明确说没有。
