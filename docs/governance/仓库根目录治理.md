> 生效日期：2026-08-25
> 最后审查日期：2026-08-25
> 维护人：FlowTennis 项目负责人
> 唯一依据：定义仓库根目录允许放什么、哪些只能算运行产物、哪些必须先登记，不替代业务口径、PRD 和各类流程正本。
> 替代文档：无

## 1. 这份规范管什么

仓库根目录不是“随便堆文件”的地方。这里要么放正式入口，要么放正式代码目录，要么放已登记的本地资料和运行产物。

## 2. 当前根目录分层

### 2.1 正式入口文件

- `AGENTS.md`
- `README.md`
- `package.json`
- `package-lock.json`
- `vercel.json`
- `.gitignore`

### 2.2 正式代码与载体目录

- `.github/`
- `api/`
- `config/`
- `docs/`
- `fixtures/`
- `migrations/`
- `offline-reports/`
- `public/`
- `scripts/`
- `server/`
- `standalone-services/`
- `tests/`
- `wechat-miniprogram/`

### 2.3 本地资料和历史参考

- `_local/`

### 2.4 本地运行产物和临时状态

- `.npm-cache/`
- `.vercel/`
- `.vercel-home/`
- `.worktrees/`
- `_exports/`
- `tmp/`
- `var/`
- `node_modules/`
- `.env`
- `.env.local`
- `.env.staging`

这些目录只能作为本地状态、临时产物、历史引用或运行缓存存在，不能当成新正式结构的默认落点。

## 3. 新增一级目录前的规则

1. 先判断是不是可以放进已有分类。
2. 不能放进已有分类时，先更新本文件，再更新自动门禁配置。
3. 不允许为了图省事在仓库根目录直接再开一个新大类目录。
4. 新正式文档不能放在仓库根目录，必须进对应分类目录。

## 4. 目录边界

1. 代码改动放代码目录。
2. 测试放 `tests/`。
3. 脚本放 `scripts/`。
4. 正式文档放 `docs/`。
5. 历史报告放 `offline-reports/` 或 `docs/reports/`，不要混写。
6. 需要长期追溯但不作为当前规则的资料，放 `_local/` 或归档目录。
7. 临时下载、导入缓存、手工抽样文件，只能放本地临时目录，不能变成新的仓库根目录入口。

## 5. 自动检查

仓库根目录治理由 `npm run guard:governance-automation` 自动检查。
