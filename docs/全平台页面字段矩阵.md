> 版本：2026-06-26  
> 范围：当前管理员侧栏 21 个菜单入口。  
> 目的：把“页面字段、筛选、顶部卡片、表格列、详情字段、导出字段”逐页绑定到标准口径 ID，后续按本表收口代码和 CI 门禁。  
> 第一事实源：[FlowTennis 全平台数据口径总表](/Users/shaobaolu/Desktop/FlowTennis/flowtennis-mgmt-main/docs/FlowTennis全平台数据口径总表.md)。

## 1. 使用规则

1. 本表是全平台字段统一的覆盖清单，不代表当前代码已经全部统一。
2. `标准口径 ID` 已存在的字段，页面必须按 ID 对应口径展示、筛选、导出。
3. `待补标准 ID` 表示当前业务字段还没有进入数据口径总表，后续上线前必须先补 ID。
4. `旧字段兼容` 只允许作为导入、历史数据读取或映射入口，不允许作为页面展示名继续扩散。
5. 页面出现本文档没有登记的字段、筛选项、卡片或导出列，必须先更新本表。
6. 页面顶部卡片、列表、详情、导出必须说明取数范围：全局统一指标、当前页面视图、还是当前筛选列表；禁止混用后不标明。
7. 同一页面如果同时展示“当前列表统计”和“全局指标”，字段名必须明显区分，不能共用一个容易误解的文案。

## 1.1 截图类问题专项约束

截图暴露的问题不能只靠“字段矩阵”自动杜绝，必须在代码和 CI 中落实以下硬规则：

| 问题类型 | 强约束 |
|---|---|
| 线索池本地重算预约 / 已体验 / 体验后成交 | 线索池顶部指标必须读取与转化与留存同一个指标模型；禁止 `leads.js` 自己重新定义 `TRIAL_BOOKED_CUSTOMERS`、`TRIAL_ATTENDED_CUSTOMERS`、`TRIAL_TO_COURSE_RATE` 的公式。 |
| 线索池和经营分析不是同一入口 | 线索池、转化与留存、经营分析只允许有一个权威指标入口；如因性能需要分接口，接口结果也必须由同一 read model 生成。 |
| 线索池顶部仍展示普通 / 正式学员 | 线索池顶部必须展示历史学员和在期学员，并分别读取 `HISTORICAL_STUDENTS`、`ACTIVE_STUDENTS`；禁止继续用 `COURSE_CHAIN_STUDENTS`、`COURSE_DEAL_CUSTOMERS` 冒充。 |
| 历史学员只从 `students` 表筛 | 历史学员必须读取 `teachingStudentViews.historicalStudents`；禁止只从 `students` 表筛选后宣称是历史总学员。 |
| 在期学员只认课包有余额 | 在期学员必须读取 `teachingStudentViews.activeStudents`，包含课包有余额和近 90 天有正式课两类人。 |
| 三页顶部同类指标各算各的 | 线索池、历史学员、在期学员的历史学员数、在期学员数、标签计数必须来自同一后端读模型；前端不得扫描排课、购买、课包余额表重算。 |
| 会员管理独立客户表 | 会员管理必须是统一客户生命周期中的订场用户子集 / 会员账户视图；禁止把会员账户当作一套独立自然人客户表。 |

验收要求：

1. 做代码收口前，必须先用全仓库审计列出是否存在上述问题。
2. 做 CI 前，必须把上述问题变成测试样本或静态扫描规则。
3. 任一条没覆盖，最终回复不得说“能杜绝截图这类问题”。

## 2. 字段口径 ID 说明

| 类型 | 含义 |
|---|---|
| `CUSTOMER_*` | 客户身份、姓名、手机号、首次触达等统一客户字段 |
| `LEAD_*` | 线索、阶段、意向、需求、来源等统一字段或字典 |
| `COURSE_*` | 教学成交、课包购买、课程转化等统一字段或指标 |
| `COURT_*` | 订场、场时、订场会员、订场消费等统一字段或指标 |
| `FIN_*` | 财务金额字段或指标 |
| `COACH_*` | 教练人效字段或指标 |
| `STANDARD_*` | 全平台统一字典 |
| `待补标准 ID` | 需要补进数据口径总表后才能作为强约束 |

## 4. 本轮确认的禁止项

| 禁止项 | 原因 | 后续门禁方向 |
|---|---|---|
| 页面展示“意向等级” | 标准字段名已定为“意向等级” `LEAD_INTENT_LEVEL_OPTIONS` | 搜索并禁止文案“意向等级” |
| 同一人主字段显示“账号 / 姓名 / 姓名 / 客户” | 主展示字段已统一为“姓名” `CUSTOMER_DISPLAY_NAME` | 页面展示字段白名单 |
| 导入字段继续扩散“需求产品” | 标准字段名是“需求产品” `LEAD_DEMAND_PRODUCT_OPTIONS` | 只允许作为导入兼容别名 |
| 页面自己手写下拉选项 | 统一字典在 `business-taxonomy.js` 和数据口径总表 | CI 扫描下拉来源 |
| 财务页或经营分析页直接重算财务金额 | 财务金额必须来自标准财务流水 / 财务快照 | 禁止页面扫描业务事实表算财务核心指标 |
| 普通学员顶部展示“课程成交” | 普通学员是体验链当前视图，不是课程成交视图 | 文案门禁 + 普通/正式学员指标关系测试 |
| 普通学员只读 `students` 表筛选 | 会漏掉已预约但未生成学员档案的人 | 普通学员必须读取客户生命周期视图 |
| 线索池和转化与留存各算一套体验链漏斗 | 会出现同一指标不同数字 | 线索池顶部和转化与留存同样本一致性测试 |
