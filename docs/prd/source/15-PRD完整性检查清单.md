
# PRD 完整性检查清单

> 版本：2026-07-02
> 状态：PRD 正本门禁。
> 定位：以后写需求、改需求、交接给 AI 或研发前，统一用本文检查 PRD 是否足够完整。

## 1. 使用场景

以下情况必须先跑本清单：

1. 新增页面、字段、按钮、状态、接口。
2. 修改财务、权益、会员、订场、排课、客户生命周期、经营分析口径。
3. 上线前交给研发、测试、AI 接手。
4. 线上问题复盘后要固化规则。
5. 需求从需求池进入 Roadmap。

## 2. 总体门禁

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| PRD-01 | 是否在 PRD 内闭环 | 不需要打开旧 `docs/` 才能理解需求。 |
| PRD-02 | 是否写明影响范围 | 明确影响端、页面、对象、字段、状态、接口、权限、测试。 |
| PRD-03 | 是否写明不做范围 | 明确本次不做什么，防止执行扩大。 |
| PRD-04 | 是否有验收方式 | 自动测试、人工验收、数据核对、页面核对至少一种。 |
| PRD-05 | 是否更新变更记录 | 重要决策进入 `14-变更记录与决策记录.md`。 |
| PRD-06 | 是否进入需求池或 Roadmap | 新需求先进入 `13`，确认执行后进入 `12`。 |

## 3. 页面级 PRD 检查

适用于 `08-具体需求/` 下所有页面。

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| PAGE-01 | 页面入口 | 写清端、模块、页面名、页面 ID、菜单路径。 |
| PAGE-02 | 使用角色 | 写清管理员、运营、财务、教练、用户等角色。 |
| PAGE-03 | 顶部摘要 | 每个卡片有字段名、口径、数据来源、筛选影响规则。 |
| PAGE-04 | 筛选搜索 | 每个筛选项有字段、枚举来源、是否影响统计/导出。 |
| PAGE-05 | 列表字段 | 每一列有字段名、来源、展示格式、空值规则。 |
| PAGE-06 | 详情/弹窗 | 详情字段和列表同源，编辑字段有校验规则。 |
| PAGE-07 | 按钮操作 | 每个按钮有入口、前置条件、写入对象、成功结果、失败提示。 |
| PAGE-08 | 状态流转 | 每个状态有进入条件、退出条件、禁止操作。 |
| PAGE-09 | 接口/读模型 | 写清列表、详情、保存、导入、导出使用的接口或读模型。 |
| PAGE-10 | 权限规则 | 写清可见范围、可操作范围、校区/本人数据限制。 |
| PAGE-11 | 异常场景 | 空数据、接口失败、权限不足、重复冲突、历史兼容都有处理。 |
| PAGE-12 | 验收标准 | 至少覆盖打开页面、字段完整、筛选一致、操作闭环、权限隔离。 |

## 4. 数据模型检查

适用于 `09-数据模型与表关系/`。

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| DATA-01 | 对象清楚 | 写清真实业务对象，不只写概念。 |
| DATA-02 | 表关系清楚 | 写清主表、关联表、主键、关联键。 |
| DATA-03 | 字段清楚 | 核心字段有含义、来源、写入规则。 |
| DATA-04 | 状态清楚 | 状态枚举、进入条件、退出条件、禁止操作明确。 |
| DATA-05 | 写入链路清楚 | 新增、编辑、作废、导入、同步、修复分别写哪些对象。 |
| DATA-06 | 删除/作废清楚 | 高风险事实默认作废/冲销，不物理删除。 |
| DATA-07 | 页面影响清楚 | 写清哪些页面读取该模型。 |
| DATA-08 | 验收样例清楚 | 有 AI 可执行检查项。 |

## 5. 口径和字段检查

适用于 `05` 和 `06`。

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| METRIC-01 | 指标定义唯一 | 同一业务含义只有一个标准定义。 |
| METRIC-02 | 字段定义唯一 | 同一字段只有一个标准名、来源和展示规则。 |
| METRIC-03 | 状态枚举唯一 | 页面不自造状态文案。 |
| METRIC-04 | 跨页一致 | 线索池、学员、经营分析、财务等同名数字同源。 |
| METRIC-05 | 历史兼容 | 旧字段只映射，不扩散为新页面字段。 |

## 6. 高风险检查

触达以下对象时必须按高风险处理：

- `ft_purchases`
- `ft_entitlements`
- `ft_entitlement_ledger`
- `ft_courts`
- `ft_financial_ledger`
- `ft_membership_orders`
- `ft_membership_benefit_ledger`
- `ft_schedule` 的完成/消课动作
- 约球费用同步到订场/财务

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| RISK-01 | 是否影响财务 | 影响时必须更新财务模型和验收。 |
| RISK-02 | 是否影响权益余额 | 影响时必须写清权益流水和余额规则。 |
| RISK-03 | 是否影响生产数据 | 影响时必须写清实例校验、批次、快照、回滚。 |
| RISK-04 | 是否影响多端 | 影响教练端、小程序、服务号、飞书时必须更新对应页面/触点 PRD。 |
| RISK-05 | 是否有回归 | 高风险需求必须有自动测试或明确人工验收。 |

## 8. 判定结果

| 结果 | 含义 | 下一步 |
|---|---|---|
| 通过 | PRD 足够执行 | 可以进入开发/测试/交接。 |
| 条件通过 | 只有少量待确认，不影响主流程 | 标记待确认项，进入需求池或 Roadmap。 |
| 不通过 | 缺字段、缺状态、缺接口、缺验收、依赖旧 docs | 先补 PRD，不能直接开发。 |
