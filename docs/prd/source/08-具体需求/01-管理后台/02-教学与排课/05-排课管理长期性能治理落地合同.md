# 排课管理长期性能治理落地合同

> 日期：2026-08-05
> 范围：管理后台 / 教学与排课 / 排课管理
> 状态：代码改造前合同。本文批准后，才允许进入排课管理第一阶段代码改造。
> 文档归属：排课管理 PRD 补充合同，承接既有性能治理路线。
> 索引关键词：核心列表、线索池、历史学员、在期学员、快路径、防复发

## 1. 本文件解决什么

本文件把排课管理的长期性能治理从“方向建议”落到可执行边界，目标是：

1. 排课列表、翻页、筛选、详情、保存不再依赖前端全量扫描。
2. 读模型只做页面展示，不能成为新的事实源。
3. 新旧链路先并行对账，再切默认路径。
4. 不重复历史会话 `019f8eb9-1d68-76b1-8248-1c82168b2f74` 的事故。

本文件暂不改业务代码，不写生产数据，不做修数。

## 2. 当前问题基线

### 2.1 当前代码事实

当前排课管理仍在首屏拉取多类数据：

- `PAGE_DATA_REQUIREMENTS.schedule = ['campuses','students','courts','schedule','coaches','coachProposals','lifecycleMetricsPage']`
- 进入排课页仍显示 `排课数据加载中...`
- 生产环境 `getScheduleListRows()` 仍扫描 `ft_schedule` 的列表投影字段

关键代码位置：

- `public/assets/scripts/core/state.js`
- `api/index.js`
- `server/page-data/core-pages.js`
- `public/assets/scripts/pages/schedule.js`

### 2.2 当前性能事实

最近只读计时显示：

| 对象 | 当前数据量或耗时 |
| --- | --- |
| `ft_schedule` | 约 1484 条 |
| `ft_schedule` 投影扫描 | 约 13.1s / 13.4s |
| `ft_courts` 扫描 | 约 11s |
| `ft_entitlement_ledger` 扫描 | 约 5.4s - 5.7s |

结论：

`排课页慢不是单个按钮问题，而是首屏读链、详情读链和保存后刷新链都可能被全量扫描拖慢。`

## 3. 历史事故复盘后固定的禁令

历史会话 `019f8eb9-1d68-76b1-8248-1c82168b2f74` 的问题不是“读模型方向错”，而是落地方式错。

本次排课治理固定以下禁令：

1. 禁止一次同时改多个高敏感页面。
2. 禁止让列表分页接口重新定义统计口径。
3. 禁止把当前页 20 条或 50 条数据当成全局统计来源。
4. 禁止接口、页面、读模型各算一套学员、课包、权益、排课状态。
5. 禁止未完成真实样本对账就切默认路径。
6. 禁止通过修数或迁移污染事实表来掩盖读模型错误。
7. 禁止旧接口未保留、回退路径未验证时上线。

## 4. 目标架构

排课管理采用四层：

| 层级 | 职责 | 说明 |
| --- | --- | --- |
| 事实表 | 记录真实发生的业务 | `ft_schedule`、`ft_students`、`ft_entitlements`、`ft_entitlement_ledger`、`ft_feedbacks` 等 |
| 统一规则层 | 只在后端计算业务口径 | 状态、课程类型、消课、权益、教练、学员展示名 |
| 排课读模型 | 给页面直接展示 | 列表、详情摘要、筛选项、分页信息 |
| 前端页面 | 展示和轻交互 | 不再现场拼全量学员、课包、权益、财务 |

核心原则：

`事实表负责真实账本，读模型负责页面速度。读模型错了只能重建，不能反向改事实表。`

## 6. 排课列表读模型：`ScheduleListView`

### 6.1 接口目标

建议新增只服务排课列表首屏的接口：

`/page-data/schedule-list-view`

请求参数：

| 参数 | 含义 |
| --- | --- |
| `page` | 当前页 |
| `pageSize` | 每页条数，默认 20 或 50 |
| `campus` | 校区筛选 |
| `dateFrom/dateTo` | 上课日期范围 |
| `coachId` | 教练筛选 |
| `studentId` | 学员筛选 |
| `status` | 排课状态 |
| `courseType` | 课程类型 |
| `q` | 搜索关键词 |

返回结构：

| 字段 | 含义 |
| --- | --- |
| `items` | 当前页排课行 |
| `summary` | 当前筛选条件下的统计摘要 |
| `filters` | 筛选器可选项 |
| `pageInfo` | `page/pageSize/total/hasMore` |
| `modelVersion` | 读模型生成版本 |
| `sourceVersion` | 来源事实表版本或生成时间 |

### 6.2 `items` 首屏字段

| 字段 | 中文含义 | 权威来源 |
| --- | --- | --- |
| `id` | 排课 ID | `ft_schedule.id` |
| `startTime/endTime` | 上课时间 | `ft_schedule` |
| `campusName` | 校区 | 统一校区字典 |
| `venueText` | 场地 | 排课事实 + 场地展示规则 |
| `coachId/coachName` | 教练 | 排课事实 + 教练资料 |
| `studentSummary` | 学员摘要 | 排课事实 + 学员统一展示名 |
| `studentIds` | 学员 ID 列表 | `ft_schedule` |
| `courseTypeLabel` | 课程类型 | 统一课程类型字典 |
| `lessonCount` | 课时数 | 排课事实 |
| `statusLabel` | 排课状态 | 后端统一状态规则 |
| `cancelReason` | 取消原因 | 排课事实 |
| `proposalStatus` | 课前教案状态 | 排课 + 教案事实 |
| `feedbackStatus` | 课后反馈状态 | 排课 + 反馈事实 |
| `entitlementSummary` | 课包/权益摘要 | 权益统一读模型摘要 |
| `updatedAt` | 更新时间 | 排课事实 |

### 6.3 首屏禁止字段

`ScheduleListView` 首屏禁止返回：

1. 全量学员表。
2. 全量订场用户表。
3. 全量课包表。
4. 全量权益流水。
5. 全量反馈详情。
6. 全量生命周期指标。
7. 详情抽屉完整表单数据。

## 7. 排课详情读模型：`ScheduleDetailView`

点击“查看”时，不允许为了打开一条详情重新加载全页大包。

建议新增：

`/page-data/schedule-detail-view?id=...`

详情第一屏只返回：

1. 当前排课完整业务字段。
2. 当前排课关联学员摘要。
3. 当前排课关联权益摘要。
4. 当前排课课前教案摘要。
5. 当前排课课后反馈摘要。
6. 当前排课操作审计摘要。

更深的流水、历史、财务追溯按 Tab 二次加载。

## 8. 翻页、详情、购买课包、保存为什么会快

### 8.1 翻页

翻页只读取下一页 `ScheduleListView.items`，不重新扫描全部排课，也不重新拼全部学员和课包。

目标：

- 翻页接口：`p95 < 500ms`
- 翻页后表格可见：`p95 < 800ms`

### 8.2 学员详情

从排课页点学员详情时，先打开学员摘要，不一次加载全部历史：

1. 学员基础摘要。
2. 当前课包摘要。
3. 最近排课摘要。
4. 其它 Tab 按需加载。

目标：

- 详情摘要：`p95 < 800ms`

### 8.3 购买课包

购买课包弹窗只需要：

1. 当前学员基础信息。
2. 可购买课包产品。
3. 当前有效权益摘要。
4. 支付和课包创建所需字段。

不允许因为打开购买弹窗扫描全部排课、全部权益流水、全部财务流水。

### 8.4 保存、取消、删除、关联

保存类操作不允许触发整页全量重载。

正确链路：

1. 写入或更新事实表。
2. 记录 `operationId`。
3. 只更新受影响的排课、学员、权益、教练索引。
4. 当前页面只刷新受影响行和必要摘要。
5. 大范围重建放后台任务，并有任务状态与对账结果。

目标：

- 新增/编辑/取消/删除关键保存：`p95 < 2s`
- 保存后当前行回显：`p95 < 1s`

## 9. 写链安全合同

排课写链触达课包、权益、教练端和可能的财务展示，属于高风险链路。

进入代码改造前，必须列出并核对：

| 写入动作 | 必须更新 | 必须对账 |
| --- | --- | --- |
| 新增排课 | `ft_schedule`、教练排课索引、学员排课摘要、权益占用摘要 | 后台排课、学员详情、教练端日程 |
| 编辑排课 | 当前排课行、相关索引 | 原排课和新排课关系不丢 |
| 取消排课 | 排课状态、取消原因、权益回滚或保留规则 | 课包余额、消课流水、教练统计 |
| 删除误建排课 | 只允许在业务规则允许时处理 | 不破坏历史业务链 |
| 完成课程 | 排课状态、权益流水、已入账口径 | 课包余额、核销流水、财务展示 |
| 关联学员/课包 | 关系键和摘要索引 | 学员详情、课包详情、排课详情 |

规则：

1. 已发生下游影响的排课，默认不做物理删除。
2. 涉及权益或财务时，必须保留操作前快照或可恢复点。
3. 后台重建任务只能重建读模型，不能擅自修改事实表。
4. 任何生产写入前必须按项目生产实例红线确认真实实例。

## 10. 新旧并行与回退

第一阶段必须这样上线：

1. 旧排课加载路径保留。
2. 新 `ScheduleListView` 接口新增，不覆盖旧接口。
3. 先隐藏模式读取新接口，只做对账。
4. 对账通过后，只切排课管理首屏。
5. 详情、保存、导出、飞书同步不在第一刀一起切。
6. 出问题时通过开关切回旧路径，回退不依赖数据迁移。

回退触发条件：

1. 页面无法加载。
2. 列表缺字段。
3. 排课数量、状态、学员、课包摘要错误。
4. 保存后数据不同步。
5. 影响学员页、课包页、教练端、财务页。
6. 性能没有明显改善。

## 16. 2026-08-23 已落地后的强制合同

> 本节覆盖 2026-08-23 已上线的排课管理快照读模型改造。后续任何排课管理需求都必须继续遵守本节，不能因为新增功能、修准确性或临时排查问题把首屏改回慢链路。

### 16.1 首屏唯一读链

排课管理首屏、搜索、筛选、翻页的唯一读取入口是：

`/page-data/schedule-list-view -> ScheduleListSnapshot -> ft_schedule_list_snapshot`

首屏禁止直接或间接读取：

1. `ft_schedule` 全表或投影扫描。
2. `ft_students` 全表扫描。
3. `ft_feedbacks` 全表扫描。
4. `ft_coach_proposals` 全表扫描。
5. `ft_entitlement_ledger` 全表扫描。
6. `ft_purchases` 全表扫描。
7. 任何为了“临时保证准确”而把事实表扫回首屏的兜底逻辑。

允许读取事实表的场景只有：

1. 后台快照重建。
2. 快照首轮受控 bootstrap。
3. 单条排课详情。
4. 对账 compare 接口。
5. 后台审计或修复脚本。

### 16.2 快照发布合同

`ft_schedule_list_snapshot` 必须按发布状态读取：

| 字段 | 要求 |
| --- | --- |
| `status` | 只有 `published` 可被首屏读取 |
| `batchId` | 必须存在，用于定位读取批次 |
| `completedAt` | 必须存在，用于判断构建完成时间 |
| `sourceSnapshotAt` | 必须存在，用于判断事实源快照时间 |
| `checksum` | 必须存在且读取时校验一致 |

禁止读取半成品快照：

1. `building` 不能上线读取。
2. `failed` 不能上线读取。
3. `checksum` 不一致不能展示。
4. `total` 与 bundle 行数不一致不能展示。

快照未初始化时，允许后端执行一次受控首轮 bootstrap，bootstrap 完成后仍必须重新从快照读取；禁止把页面回退到旧慢读模型。

### 16.3 变更后刷新合同

新建、编辑、取消、删除排课后必须遵守：

1. 事实表仍写 `ft_schedule`，事实源不变。
2. 写入成功后同步 `ft_schedule_list_snapshot` 的 delta。
3. delta 同步失败只能记录后台任务，不得影响事实写入成功。
4. 前端只轻量刷新当前请求对应的排课页。
5. 禁止 `loadPageDataAndRender('schedule',{force:true})`。
6. 禁止 `ensureDatasetsByName(['schedule'],{force:true})`。
7. 禁止因为一次保存/取消/删除重新拉取排课页全量大包。

### 16.4 数据正确性合同

排课列表快照不是新的事实源，只是首屏展示读模型：

1. 页面不能自己拼数据、补字段、重算核心口径。
2. 快照只能由后端统一构建器生成。
3. 单条 delta 不能只拿一条排课硬拼索引；必须通过完整增量数据源生成。
4. 列表筛选、搜索、统计、分页必须基于同一批完整快照数据，不能只按当前页计算。
5. 发现快照错误时只能重建快照或修后端构建规则，不能反向修改事实表。

### 16.5 必保测试门禁

以下测试属于排课管理性能治理硬门禁，必须长期保留在 `npm test`：

1. `tests/schedule-list-performance-lock.test.js`
2. `tests/schedule-list-snapshot.test.js`
3. `tests/schedule-list-snapshot-performance.test.js`

这些测试必须持续覆盖：

1. 首屏路由不能调用旧慢读模型。
2. 首屏路由不能持有慢表依赖。
3. 快照未初始化时必须受控 bootstrap 并重试快照。
4. 未 `published` 的快照不能展示。
5. `checksum` 错误必须拒绝展示。
6. 缺少完整增量数据源时不能写 active delta。
7. 5000 条样本下首屏、筛选、搜索、翻页均必须小于 1 秒。
8. 保存、取消、删除后禁止整页强制刷新。

删除、绕开、放宽这些测试，视为破坏排课管理性能治理合同。

### 16.6 后续需求变更检查

任何后续排课管理需求，只要触达列表、筛选、搜索、翻页、保存后刷新、详情打开，都必须先检查：

1. 是否仍走 `ScheduleListSnapshot`。
2. 是否新增了首屏慢表依赖。
3. 是否新增了整页强制重拉。
4. 是否绕开了快照 `published/checksum` 校验。
5. 是否让页面自己拼核心字段。
6. 是否补充或更新了对应反向测试。
7. 是否试图删除、绕开或降级已落地的 `ScheduleListSnapshot` 快路径；这类改动必须同时更新 `AGENTS.md`、`docs/business-rules/FlowTennis全平台数据口径总表.md` 和对应反向测试，否则禁止合并。

没有通过以上检查，不允许合并。
