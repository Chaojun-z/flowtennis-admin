2. 任何新增收入、退款、会员余额、课包核销、订场导入，必须说明影响总收入、已入账、待履约和余额。
3. 第三方导入必须接入本文档定义的统一财务流水和期间快照规则。

## 1. 背景

FlowTennis 当前已有会员、订场、课包、排课、财务页面和每日快照能力，但底层财务仍处于“业务表 + 财务读模型 + 快照保护”的阶段。

当前系统已经存在 `ft_financial_ledger` 和财务影子账对账能力。本文档不是要求再新增第三套账本，而是要求把现有影子账本延续升级为“统一财务总账候选账”。

账本关系必须明确：

| 账本/口径 | 当前定位 | 后续方向 |
|---|---|---|
| 现有财务页口径 | 当前线上展示口径，仍保留 | 短期不切换，继续作为线上稳定口径 |
| `ft_financial_ledger` 影子账 | 已存在的旁路对账账本 | 升级为统一财务总账候选账 |
| 统一财务总账 | 最终目标口径 | 不另起第三账本，优先复用并完善 `ft_financial_ledger` |

禁止事项：

1. 禁止为了第三方导入再创建一套新的“第三账本”。
2. 禁止让现有财务页、影子账、第三方导入账三套口径并行长期存在。
3. 第三方导入产生的财务流水应进入 `ft_financial_ledger` 候选账，并和现有财务页做对账。

当前风险：

1. 财务页数字可能正确，但来源分散。
2. 业务表可以拼出财务结果，但还不是完整会计式总账。
3. 日、周、月、季度、半年、年度报表的一致性需要更强约束。
4. 第三方导入会增加会员储值、会员订场、散客订场、退款、锁场等数据，必须先明确底层财务模型。

## 2. 目标

建立统一财务总账模型，使 FlowTennis 可以稳定回答：

1. 某一天收入、已入账、退款、会员消耗是多少。
2. 某一周、月、季度、半年、年度汇总是多少。
3. 日汇总、周汇总、月汇总、季度汇总按同一底层流水计算，结果一致。
4. 会员余额、课包余额、待履约收入能按期初、发生额、期末余额核对。
5. 每次导入、修数、退款、回滚都有批次、流水和审计记录。

## 3. 最健康的三层模型

平台财务应采用三层模型：

```text
第一层：业务原始事实
订场、锁场、排课、充值、退款、课包购买、消课

第二层：统一财务流水
每一笔钱的变化生成一条不可随便改的财务流水

第三层：期间快照
日、周、月、季度、半年、年度都从统一财务流水汇总
```

这是当前最健康、最能规避风险的模型，原因：

1. 业务事实回答“发生了什么”。
2. 财务流水回答“钱如何变化”。
3. 期间快照回答“某个时间范围的账是多少”。
4. 页面只展示统一结果，不自己重新算钱。
5. 任意时间范围都能从同一批流水汇总，避免口径漂移。

## 4. 当前系统差距

当前系统已有：

| 已有能力 | 状态 |
|---|---|
| 财务快照 | 已有 |
| 财务门禁测试 | 已有 |
| `operationId` / `batchId` | 部分已有 |
| 买课包、消课、会员储值、订场的校验脚本 | 部分已有 |
| 财务页面统一读模型 | 部分已有 |
| `ft_financial_ledger` 影子账 | 已有，但覆盖不完整 |
| 财务影子账差异报告 | 已有，用于新旧口径对账 |

当前不足：

| 差距 | 说明 |
|---|---|
| 统一财务总账未完全成为第一事实源 | 财务页仍从多张业务表拼结果 |
| 财务流水覆盖不完整 | 不是所有业务动作都有统一财务流水 |
| 期间快照体系不完整 | 有每日快照能力，但日/周/月/季/半年/年一致性未完全产品化 |
| 回滚未完全闭环 | 批次回滚尚未完整落地 |
| 页面仍可能局部计算 | 需要继续收口到统一财务层 |

结论：

当前系统有财务保护能力和影子账基础，但还不是完整的会计式总账系统。第三方导入前，必须把新增数据写入现有 `ft_financial_ledger` 候选账，并按统一财务流水和期间快照规则处理。

## 5. 财务字段定义

统一财务流水优先落到现有 `ft_financial_ledger`。如现有字段不足，应在 `ft_financial_ledger` 上补齐或通过兼容字段扩展，不另建第三账本。

统一财务流水必须至少包含：

| 字段 | 说明 |
|---|---|
| `id` | 财务流水 ID |
| `ledgerVersion` | 财务流水版本 |
| `batchId` | 批次 ID |
| `operationId` | 操作 ID |
| `businessDate` | 业务发生时间，决定归属哪一天 |
| `createdAt` | 系统写入时间 |
| `businessType` | 课程、会员储值、会员订场、散客订场、退款等 |
| `transactionType` | 收款、消耗、退款、冲正 |
| `cashDelta` | 现金收入变化 |
| `recognizedRevenueDelta` | 已入账收入变化 |
| `deferredRevenueDelta` | 待履约收入变化 |
| `refundDelta` | 退款变化 |
| `paymentMethod` | 微信、转账、会员余额、大众点评券码等 |
| `sourceType` | 来源类型 |
| `sourceId` | 来源业务单据 |
| `idempotencyKey` | 幂等去重键 |
| `operator` | 操作人 |
| `sourceSnapshot` | 最小业务快照 |

金额规则：

1. 底层金额建议统一使用“分”的整数。
2. 页面展示时再转换为“元”。
3. 不得用浮点数作为底层财务判断依据。

## 6. 业务入账规则

| 业务 | 总收入 `cashDelta` | 已入账 `recognizedRevenueDelta` | 待履约 `deferredRevenueDelta` |
|---|---:|---:|---:|
| 课包购买 3000 | +3000 | 0 | +3000 |
| 消课 300 | 0 | +300 | -300 |
| 会员充值 1000 | +1000 | 0 | +1000 |
| 会员余额订场 100 | 0 | +100 | -100 |
| 散客微信订场 100 | +100 | +100 | 0 |
| 大众点评券码订场 80 | +80 | +80 | 0 |
| 私教课排课占场 | 0 | 0 | 0 |
| 内部锁场 | 0 | 0 | 0 |
| 退款 | 负向冲减 | 按来源冲减 | 按来源冲减 |

硬规则：

1. 会员余额订场不增加总收入，只增加已入账、减少待履约。
2. 课包消课不增加总收入，只增加已入账、减少待履约。
3. 私教课排课占场默认不单独计算场地费，除非排课明确标注单独支付场地费。
4. 大众点评券码按平台结算或人工确认金额计收入。
5. 退款必须生成独立负向流水，不得直接改原流水。

## 7. 可相加指标与不可相加指标

### 7.1 可以直接相加的期间指标

以下指标可以按日、周、月、季度、半年、年直接相加：

| 指标 | 说明 |
|---|---|
| 总收入 | 正向现金收入 |
| 课程收入 | 课程相关现金收入 |
| 会员储值收入 | 会员储值本金收入 |
| 场地收入 | 散客订场、券码订场等收入 |
| 已入账收入 | 已完成履约确认的收入 |
| 退款金额 | 退款负向发生额 |
| 会员余额消耗 | 会员订场消耗 |
| 课包消课金额 | 课包核销确认 |

### 7.2 不能直接相加的余额指标

以下指标不能把每天数值直接相加，只能看期初、发生额、期末：

| 指标 | 正确看法 |
|---|---|
| 会员余额 | 月初余额 + 充值 + 赠送 - 消耗 - 退款/清零 = 月末余额 |
| 待履约收入 | 期初待履约 + 本期收款 - 本期已入账 - 本期退款 = 期末待履约 |
| 课包剩余金额 | 期初剩余 + 购买 - 消课 - 退款/作废 = 期末剩余 |
| 课包剩余课时 | 期初课时 + 新购课时 - 消课课时 - 退回/作废 = 期末课时 |

## 8. 期间快照

系统应支持以下期间快照：

| 快照 | 用途 |
|---|---|
| 日快照 | 每天收盘核对 |
| 周快照 | 周报和周度核对 |
| 月快照 | 月度封账 |
| 季度快照 | 季度经营核对 |
| 半年快照 | 半年账单 |
| 年度快照 | 年度总账 |

快照生成规则：

1. 快照只能由统一财务流水汇总生成。
2. 快照不能手工改数字。
3. 快照必须记录生成时间、范围、版本、来源流水数量。
4. 同一期间重复生成快照时，必须保留历史版本。
5. 已封账月份如需调整，必须通过调整流水，不得直接改快照。

## 9. 汇总一致性校验

系统必须支持以下校验：

```text
本月总收入 = 本月每日总收入相加
本月已入账 = 本月每日已入账相加
本月退款 = 本月每日退款相加
季度总收入 = 季度内月份总收入相加
半年总收入 = 半年内月份总收入相加
年度总收入 = 全年月份总收入相加
```

余额类校验：

```text
期末待履约 = 期初待履约 + 本期收款 - 本期已入账 - 本期退款
会员期末余额 = 期初余额 + 本期充值 + 本期赠送 - 本期消耗 - 本期退款/清零
课包期末剩余 = 期初剩余 + 本期购买 - 本期消课 - 本期退款/作废
```

只要任一校验不平，系统不得标记财务健康。

## 10. 第三方导入的财务要求

第三方导入必须先生成统一财务流水，再汇总到期间快照。

第三方导入的财务流水要求：

1. 优先写入或生成到现有 `ft_financial_ledger` 影子账。
2. 作为统一财务总账候选账参与对账。
3. 不直接替换现有财务页展示口径。
4. 不创建第三套导入账本。
5. 导入批次必须输出“现有财务页口径 vs `ft_financial_ledger` 候选账”的差异报告。

禁止：

1. 直接改财务页面数字。
2. 直接改月报数字。
3. 把会员余额扣款当现金收入。
4. 把锁场直接当订场收入。
5. 把私教课排课占场重复算场地收入。

第三方 7 月上半月试点必须验证：

1. 每日汇总相加等于 7 月上半月汇总。
2. 会员余额期初、发生额、期末能对上。
3. 待履约期初、发生额、期末能对上。
4. 已入账增加能追溯到会员订场、散客订场、消课等来源。
5. 异常数据不进入财务流水。

## 11. 回滚与调整

回滚规则：

1. 按 `batchId` 或 `operationId` 回滚。
2. 原始业务事实不物理删除，优先作废或撤销绑定。
3. 财务流水不物理删除，使用负向冲正流水。
4. 快照不直接修改，重新生成新版本快照。
5. 回滚后必须重新跑汇总一致性校验。

## 12. 上线顺序

推荐顺序：

1. 明确统一财务流水字段。
2. 基于现有 `ft_financial_ledger` 补齐统一财务流水字段和覆盖范围。
3. 对比现有财务页和旁路流水结果。
4. 先不切换财务页来源。
5. 第三方 7 月上半月导入接入 `ft_financial_ledger` 候选账和快照校验。
6. 校验稳定后，逐步把财务页切换到统一总账读模型。
7. 最后上线日、周、月、季度、半年、年度快照页面。

## 13. 非目标

本阶段不做：

1. 直接重写财务页。
2. 直接把所有历史财务回填为新总账。
3. 同时改业务写入和财务展示来源。
4. 未经校验直接切换财务口径。
5. 让页面各自重新计算财务指标。
