## 1. 背景

原“普通学员 / 正式学员”更偏转化漏斗，不能完整回答门店经营中的两个问题：

1. 一个校区历史上一共有多少人真实来上过课。
2. 当前还有多少人仍然有运营价值。

因此新增两个学员视图，并统一学员活跃标签。

## 2. 学员列表范围

| 列表名称 | 展示范围 | 不展示 |
|---|---|---|
| 历史学员 | 所有有过有效排课或上课事实的客户，包括体验课、正式课、课包课、单次付费课、0 元单次课；未取消且时间已过去的已排课记录视为上课事实 | 只有线索、只有预约、没有任何有效排课或上课事实的客户 |
| 在期学员 | 历史学员的子集：课包有余额，或近 90 天有正式课上课记录；未取消且时间已过去的已排课正式课计入最近正式课 | 只上过体验课且 90 天内没有正式课；正式课最近一次超过 90 天且无课包余额 |

说明：

1. `历史学员` 回答累计服务人数。
2. `在期学员` 回答当前可继续运营的人群。
3. 单次付费金额可以为 0；0 元单次课不单独拆成资源置换或赠课标签。
4. 暂不启用“即将过期 / 已过期有余额”标签；当前课包有效期数据不完整，不能作为可靠全局口径。

## 3. 标签字段

| 标签名称 | 字段 | 字段定义 |
|---|---|---|
| 课包状态 | 未买过课包 | 从未购买过正式课包 |
| 课包状态 | 课包有余额 | 当前正式课包剩余课时 > 0 |
| 课包状态 | 课包即将耗尽 | 当前正式课包剩余课时 > 0 且 <= 2 节 |
| 课包状态 | 课包已用完 | 买过正式课包，但当前正式课包剩余课时 = 0 |
| 付费方式 | 课包学员 | 有正式课通过课包扣减 |
| 付费方式 | 单次付费学员 | 有正式课通过直接收款、线下收款、免费赠送等非课包方式结算，金额可以为 0 |
| 付费方式 | 课包+单次付费 | 同一个学员既有课包扣减正式课，也有单次付费正式课 |
| 活跃状态 | 近30天活跃 | 最近 30 天有正式课上课记录 |
| 活跃状态 | 31-90天活跃 | 最近 31-90 天有正式课上课记录，且近 30 天没有正式课 |
| 活跃状态 | 91-180天沉默 | 最近 91-180 天有正式课上课记录，且近 90 天没有正式课 |
| 活跃状态 | 180天以上沉睡 | 距离最近一次正式课已超过 180 天 |
| 活跃状态 | 从未正式上课 | 没有正式课上课记录；可能只有体验课、预约或购买记录 |
| 累计上课筛选 | 历史课时30+ | 累计上课次数 >= 30 |
| 累计上课筛选 | 历史课时50+ | 累计上课次数 >= 50 |
| 累计上课筛选 | 历史课时100+ | 累计上课次数 >= 100 |
| 学员状态 | 已转单次付费 | 课包已用完后，又发生了单次付费正式课 |
| 学员状态 | 有余额未活跃 | 课包有余额，但最近 30 天没有正式课 |

## 4. 口径规则

| 规则 | 说明 |
|---|---|
| 正式课 | 不包含体验课；包含私教正式课、小班正式课、训练营、随到随学等正式教学服务 |
| 单次付费 | 非课包扣减的正式课结算方式；金额可以大于 0，也可以等于 0 |
| 0 元单次课 | 归入单次付费学员，不再拆资源置换、赠课、补偿课 |
| 课包即将耗尽 | 只看剩余课时，不看有效期 |
| 活跃状态 | 同一学员只能命中一个活跃状态 |
| 其他标签 | 同一学员可以同时命中多个标签，例如 `课包已用完` + `已转单次付费` + `近30天活跃` |
| 标签筛选 | 历史学员、在期学员页面使用一个标签级联筛选入口；一级为标签组，二级为标签值；支持多选、选项人数、清空和单项移除 |
| 标签筛选组合 | 同一标签组内多选为或，多个标签组之间为且 |
| 统一读模型 | 历史学员、在期学员的列表范围、顶部卡片、列表字段和标签字段都必须来自后端 `teachingStudentViews`；前端只展示和筛选后端标签，不得扫描排课、购买或课包余额表重新计算 |

## 5. 页面使用

| 页面 | 使用方式 |
|---|---|
| 线索池 | 仍以线索跟进和转化为主，不把所有历史学员混入线索列表 |
| 历史学员 | 展示累计来上过课的人，支持常用筛选和标签级联多选 |
| 在期学员 | 默认展示仍有运营价值的人，支持常用筛选和标签级联多选 |
| 普通学员 / 正式学员 | 保留漏斗口径；展示字段和标签必须读取统一学员标签读模型 |
| 教练端我的学员 | 可复用活跃状态、付费方式、课包状态，不得单独定义另一套标签 |
| 经营分析 | 可复用历史学员、在期学员和活跃状态做人数统计 |

## 6. 验收标准

- 历史学员不遗漏单次付费和 0 元单次课学员。
- 在期学员不只按课包余额判断。
- 在期学员必须是历史学员的子集；课包有余额、近30天活跃等包含关系内的统一数字在两个页面必须一致。
- 没买过课包的单次付费学员不得被标记为 `课包已用完`。
- 中文 `课包`、`课包划扣`、`课包核销` 等结算方式不得被误判为单次付费。
- 前端如果重新计算活跃状态、付费方式、课包状态、累计上课筛选、最近上课、累计课程付费或学员状态，测试必须失败，不能上线。
- 课包有效期字段不完整时，不展示“即将过期 / 已过期有余额”。
- 同一个学员的标签在客户与线索、教学、经营分析、教练端保持一致。
