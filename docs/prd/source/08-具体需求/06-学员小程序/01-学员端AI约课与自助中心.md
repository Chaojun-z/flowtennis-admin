## 1. 产品定位

学员端不是课程商城，而是“AI 约课助手 + 学员自助中心”。

目标是把原来依赖微信找运营的约课、订场、买课包、查余额、查上课记录、看反馈，逐步迁移到学员自己能完成的小程序里。

初版原则：

1. 学员可以直接说“帮我约明天晚上王教练的正手课”。
2. 系统把自然语言转成约课需求。
3. 系统根据学员权益判断是课包扣课、单次付费、体验课，还是推荐购买课包。
4. AI 负责听懂人话和追问信息，系统规则负责查余额、查价格、查教练、查冲突和落单。
5. 初版不做完全自动复杂调度；高风险和异常场景仍进入运营待确认。

## 2. 使用角色

| 角色 | 说明 |
|---|---|
| 在期学员 | 有有效课包或近期上课记录的学员 |
| 单次付费学员 | 没有课包，但可以按单次价格约课 |
| 体验课学员 | 首次体验或运营允许购买体验课的学员 |
| 运营人员 | 在管理后台处理待确认、异常、退款、改课、场地确认 |
| 教练 | 在教练端查看已确认课程和提交课后反馈 |

## 3. 产品载体

推荐方案：

1. 不新建独立小程序。
2. 在现有 `wechat-miniprogram/` 小程序体系中增加“学员身份”和“学员端界面”。
3. 服务号只做入口和提醒，点击后进入小程序学员端。

原因：

1. 降低开发、审核、推广和维护成本。
2. 复用现有微信登录、小程序配置和后端能力。
3. 未来可在同一小程序里按身份进入学员端、教练端或运营端。

## 3.1 代码目录边界

学员端小程序开发必须限制在小程序目录内，不得把学员端页面做进管理端网页。

推荐目录结构：

```text
wechat-miniprogram/
  miniprogram/
    pages/
      coach/
        index/
        schedule/
        detail/
      student/
        login/
        home/
        booking/
        packages/
        records/
        feedback/
        profile/
      common/
        agreement/
        privacy/
```

目录职责：

| 目录 | 职责 |
|---|---|
| `pages/coach/` | 教练端小程序页面，包含首页、排课日程、课程详情、课后反馈入口 |
| `pages/student/` | 学员端小程序页面，包含登录绑定、首页、AI 约课、课包、上课记录、课程反馈、我的 |
| `pages/common/` | 小程序公共页面，包含用户协议、隐私政策等 |
| `utils/` | 小程序内公共请求、日期、排课展示等工具 |

开发边界：

1. 学员端页面只放在 `wechat-miniprogram/miniprogram/pages/student/`。
2. 教练端小程序页面统一放在 `wechat-miniprogram/miniprogram/pages/coach/`。
3. 用户协议、隐私政策等共享页面放在 `wechat-miniprogram/miniprogram/pages/common/`。
4. 管理端网页目录 `public/` 不承载学员端 UI。
5. 管理端后端和服务端目录只提供共用接口，不等于学员端页面开发范围。
6. 迁移教练端旧目录时，只做路径调整和 `app.json` 页面路径更新，不改变教练端业务功能。
7. 如果后续需要改共用接口，必须单独说明影响范围，避免影响正在开发的教练管理端网页。

## 4.1 登录绑定与课包数据串联

学员端必须先解决“微信里这个人是谁”，再读取后台课包、预约、上课记录和反馈。

核心原则：

1. 微信身份只负责识别登录用户。
2. 后台学员档案才是课包、排课、反馈、财务数据的主身份。
3. 小程序不能只靠微信昵称、头像、备注名匹配学员。
4. 课包余额必须通过绑定后的后台学员 ID 查询，不能只按手机号临时查。

### 4.1.1 首次登录流程

```text
学员打开小程序
↓
微信授权登录
↓
系统获取微信 openid / unionid
↓
检查是否已有绑定关系
↓
没有绑定 → 引导手机号授权或输入手机号
↓
用手机号匹配后台学员档案
↓
匹配成功 → 展示姓名和尾号，让学员确认绑定
↓
绑定成功 → 进入学员首页
↓
首页读取课包、预约、上课记录、课程反馈
```

### 4.1.2 已绑定用户登录流程

```text
学员打开小程序
↓
微信静默登录
↓
系统通过 openid / unionid 找到绑定的 studentId
↓
读取该 studentId 的课包、预约、上课记录、课程反馈
↓
进入首页
```

### 4.1.3 后台数据如何和小程序用户串联

| 数据 | 后台来源 | 小程序读取方式 |
|---|---|---|
| 学员身份 | 学员档案 / 客户生命周期 | 微信 openid / unionid 绑定到 studentId |
| 课包余额 | 权益账户 | 按 studentId 查询有效权益 |
| 购买记录 | 购买记录 | 按 studentId 查询本人购买记录 |
| 上课记录 | 排课管理 / 权益流水 | 按 studentId 查询本人已完成课程 |
| 课程反馈 | 教练反馈 | 按 studentId 查询本人课程反馈 |
| 我的预约 | 预约申请 / 排课记录 | 按 studentId 查询本人待确认和已确认预约 |
| 单次支付 | 支付订单 / 财务流水 | 支付成功后挂到 studentId |

### 4.1.4 绑定匹配规则

| 场景 | 处理方式 |
|---|---|
| openid 已绑定 studentId | 直接进入首页 |
| 手机号只匹配到 1 个学员 | 展示姓名和手机号尾号，确认后绑定 |
| 手机号匹配到多个学员 | 不让用户自行选择，进入运营确认 |
| 手机号没有匹配到学员 | 创建未绑定访客状态，可买体验课或联系运营 |
| 同一微信同时是教练和学员 | 登录后展示身份切换：学员端 / 教练端 |
| 学员换手机号 | 进入运营确认，不自动改后台档案 |

### 4.1.5 课包展示规则

绑定成功后，小程序首页只展示该学员自己的有效权益：

1. 课包名称。
2. 剩余次数。
3. 有效期。
4. 可用校区。
5. 可用课程类型。
6. 可用教练范围。

如果课包已过期、已用完或不适用于当前预约，必须明确提示原因，不允许静默隐藏后直接引导单次付费。

## 5. 初版必须支持

| 功能 | 初版要求 |
|---|---|
| 微信登录 | 通过微信身份进入小程序 |
| 绑定学员 | 用手机号绑定后台已有学员档案 |
| 首页 | 展示 AI 输入框、快捷入口、课包余额、最近预约 |

| 课包约课 | 有可用课包时展示扣课包预约 |
| 单次付费约课 | 无课包时展示单次价格并支付预约 |
| 体验课预约 | 符合体验规则时展示体验价或联系运营 |
| 购买课包 | 展示可购买课包，支持购买后生成权益 |
| 我的课包 | 查看剩余次数、有效期、适用范围 |
| 我的预约 | 查看待确认、已确认、已完成、已取消课程 |
| 上课记录 | 查看历史上课和核销记录 |
| 课程反馈 | 查看教练课后反馈 |
| 通知 | 预约结果、上课提醒、改课结果通知 |
| 运营待确认 | 场地待确认、价格异常、排课冲突等进入后台 |

## 6. 初版暂不支持

| 暂不支持 | 原因 |
|---|---|
| 直接读取个人微信聊天 | 不稳定且有隐私、合规和封号风险 |
| 全自动复杂排课 | 初版风险高，先由系统推荐、运营兜底 |
| 第三方场地全自动预订 | 取决于第三方是否开放接口 |
| 多人拼班自动成团 | 规则复杂，后续单独设计 |
| 复杂候补机制 | 初版只做可约、待确认、已满提示 |
| AI 自动定价 | 价格必须由系统定价规则决定 |
| AI 自动退款或赔付 | 财务高风险，必须人工确认 |

页面要求：

3. 首页不展示复杂运营字段、内部 ID、流水号。

## 8. AI 约课流程

### 8.1 有课包学员

```text
学员输入：
帮我约明天晚上王教练

AI 回复：
明天晚上王教练有 2 个时间可以约：

1. 19:00-20:00
   可用权益：私教课包
   本次扣 1 次

2. 20:00-21:00
   可用权益：私教课包
   本次扣 1 次

[约 19:00] [约 20:00] [换个教练] [换一天]
```

确认后：

1. 如果教练、场地、权益均无冲突，生成“已确认预约”或“待运营确认预约”。
2. 初版建议默认生成“待运营确认”，运营确认后再通知学员。
3. 后续稳定后，可将低风险场景升级为自动确认。

### 8.2 无课包单次付费学员

```text
学员输入：
帮我约明天晚上王教练

AI 回复：
你当前没有可用课包，可以单次预约。

王教练明天晚上可约：

1. 19:00-20:00
   单次价格：¥280

2. 20:00-21:00
   单次价格：¥280

[支付并预约 19:00] [支付并预约 20:00] [购买课包更划算]
```

规则：

1. 单次付费学员和课包学员共用“我要约课”入口。
2. 是否扣课包、单次付费或推荐买课包，由系统根据权益和定价规则判断。
3. 支付成功后生成预约单。
4. 初版单次付费预约可先进入运营待确认，避免已付款但场地无法安排。

### 8.3 体验课学员

```text
AI 回复：
你可以预约首次体验课。

体验课价格：¥129
可选时间：
1. 周六 10:00 李教练
2. 周日 15:00 陈教练

[支付并预约体验课] [联系运营]
```

规则：

1. 是否可买体验课由后台学员状态和体验课规则决定。
2. 同一手机号或同一微信身份是否可重复购买体验课，必须由系统规则控制。
3. 体验课完成后，首页和课程反馈页引导购买正式课包。

## 12. 课后反馈查看路径

学员端不新建一套反馈系统，必须复用现有教练端课后反馈 `feedbacks`。

### 12.1 数据流转路径

```text
后台排课生成课程 schedule
↓
课程同步到教练端 Web / 教练小程序
↓
教练上完课后提交课后反馈 feedbacks
↓
feedbacks 绑定 scheduleId
↓
feedbacks 同时关联 studentId / studentIds
↓
后台排课详情和学员详情可见
↓
学员小程序按 studentId 查询本人反馈
↓
学员在“课程反馈”里查看
```

### 12.2 学员端反馈入口

| 入口 | 展示内容 |
|---|---|
| 首页最近课程 | 如果最近一节课已有反馈，显示“查看反馈” |
| 我的 / 课程反馈 | 按时间倒序展示全部可见反馈 |
| 上课记录详情 | 单节课下展示对应反馈 |
| 课程完成通知 | 点击进入该节课反馈详情 |

### 12.3 课程反馈列表文字原型

```text
课程反馈

2026-08-10 19:00
王教练 · 私教课 · 正手训练

本节重点：
正手击球稳定性、引拍准备、随挥完整性

教练建议：
下节课建议继续练移动中的正手击球。

[查看详情]
```

### 12.4 课程反馈详情文字原型

```text
课程反馈详情

课程：
2026-08-10 19:00-20:00
王教练私教课
马坡校区 / 2号场

训练内容：
正手击球稳定性、步伐移动、击球点控制

本节表现：
击球稳定性比上节课更好，但移动中击球容易晚点。

下次建议：
继续练移动击球和提前引拍。

[继续约课]
```

### 12.5 学员可见与不可见字段

| 类型 | 字段 | 学员端是否展示 |
|---|---|---|
| 教学反馈 | 知识点/问题 knowledgePoint | 展示 |
| 教学建议 | 下次训练建议 nextTraining | 展示 |
| 学员水平 | playerLevel | 可展示为通俗文案 |
| 学习目标 | goalType | 可展示 |
| 主要问题 | mainIssues | 展示 |
| 转化意向 | conversionIntent | 不展示 |
| 推荐产品 | recommendedProductType | 不直接展示，可转成课包推荐 |
| 运营跟进 | needOpsFollowUp、priority、suggestion | 不展示 |

### 12.6 权限和状态规则

1. 学员只能查看自己 `studentId` 关联课程的反馈。
2. 教练未提交反馈时，学员端显示“教练还未填写课后反馈”。
3. 已取消、未完成、未上课课程不展示反馈入口。
4. 多学员课程只展示当前学员所属课程反馈，不展示其他学员隐私信息。
5. 运营内部跟进建议、转化意向、推荐产品等字段默认不直接展示给学员。
6. 如果教练编辑反馈，学员端展示最新版本。

## 13. 核心业务对象

| 对象 | 说明 |
|---|---|
| 学员档案 | 后台已有学员，绑定微信身份后进入学员端 |
| 微信身份 | openid / unionid / 手机号绑定信息 |
| 课包产品 | 可购买的课包、价格、次数、有效期、适用规则 |
| 权益账户 | 学员购买课包后形成的剩余课时和可用规则 |
| 预约申请 | 学员发起的约课或订场需求 |
| 排课记录 | 运营确认后形成正式课程 |
| 支付订单 | 单次付费、体验课、课包购买产生的订单 |
| 课程反馈 | 教练课后提交，学员端可查看 |
| 通知记录 | 预约结果、上课提醒、改课取消通知 |

## 14. 字段清单

| 区域 | 字段 / 指标 | 来源 / 口径 | 展示或编辑规则 |
|---|---|---|---|
| 登录绑定 | 微信 openid、手机号、学员 ID | 微信登录 / 学员档案 | openid 不展示给学员 |
| 首页权益 | 课包名称、剩余次数、有效期 | 权益账户 | 只展示可理解字段 |
| AI 输入 | 原始输入、识别意图、缺失信息 | AI 解析结果 | 原始输入可留审计，不直接决定业务结果 |
| 约课方案 | 日期、时间段、教练、校区、场地、价格、权益 | 排课、教练、价格、权益读模型 | 价格和权益由系统规则返回 |
| 预约单 | 状态、学员、课程类型、时间、支付方式 | 预约申请 / 排课 | 状态必须可追溯 |
| 支付 | 应付金额、实付金额、支付状态 | 支付订单 / 财务流水 | 不展示内部流水 ID |
| 上课记录 | 上课时间、教练、课程主题、核销次数 | 排课 / 权益流水 | 和后台排课、消课同源 |
| 课程反馈 | 训练内容、表现总结、下次建议 | 教练反馈 | 不展示运营内部备注 |

## 15. 状态与流转

### 15.1 预约状态

| 状态 | 进入条件 | 学员可见文案 | 退出条件 |
|---|---|---|---|
| 草稿 | AI 已识别但未确认 | 待选择时间 | 学员选择方案 |
| 待支付 | 无可用课包且需先付款 | 待支付 | 支付成功或取消 |
| 待确认 | 已提交但需运营确认 | 等待确认 | 运营确认或拒绝 |
| 已确认 | 时间、教练、场地、权益/支付确认 | 预约成功 | 完课、取消、改课 |
| 已完成 | 课程完成并核销 | 已上课 | 只读 |
| 已取消 | 学员或运营取消 | 已取消 | 只读 |
| 已拒绝 | 运营无法安排 | 未能安排 | 可重新发起 |

### 15.2 支付方式判断

| 场景 | 系统动作 |
|---|---|
| 有可用课包 | 优先展示课包扣课 |
| 无可用课包但允许单次付费 | 展示单次价格和支付按钮 |
| 符合体验课条件 | 展示体验课价格 |
| 无课包且不允许单次付费 | 引导购买课包或联系运营 |

## 16. AI 能力边界

AI 可以做：

1. 理解自然语言约课需求。
2. 识别课程类型、时间、教练、校区、训练主题。
3. 追问缺失信息。
4. 把需求转成结构化预约草稿。
5. 用自然语言解释可选方案。
6. 根据历史上课频率推荐课包。

AI 不可以做：

1. 自己判断课包余额。
2. 自己编造价格。
3. 自己承诺教练和场地一定可用。
4. 自己扣课包。
5. 自己完成退款、赔付、冲正。
6. 自己修改财务流水。

核心原则：

> AI 负责理解和引导，系统负责查数据、校验和落单。

## 17. 接口与数据来源

| 用途 | 接口 / 读模型 | 方法 | 说明 |
|---|---|---|---|
| 微信登录 | 小程序登录接口 | POST | 获取微信身份并换取业务登录态 |
| 学员绑定 | 学员绑定接口 | POST | 手机号绑定后台学员档案 |
| 首页数据 | 学员首页读模型 | GET | 汇总权益、预约、推荐 |
| AI 解析 | AI 约课解析接口 | POST | 输入自然语言，输出结构化草稿 |
| 约课推荐 | 约课方案推荐接口 | POST | 查教练、时间、权益、价格和冲突 |
| 创建预约 | 预约申请接口 | POST | 生成预约单或待支付单 |
| 支付 | 微信支付接口 | POST | 单次课、体验课、课包购买 |
| 我的课包 | 权益账户读模型 | GET | 查看余额和有效期 |
| 上课记录 | 排课 / 权益流水读模型 | GET | 查看已完成课程和核销 |
| 课程反馈 | 反馈读模型 | GET | 查看教练反馈 |
| 运营确认 | 管理后台预约处理接口 | POST | 运营确认、拒绝、改时间 |

说明：

1. 上表是产品级接口描述，不限定具体路径。
2. 正式开发时必须复用现有统一读模型和字段口径。
3. 涉及权益、支付、财务、排课完成时，必须按高风险规则设计审计和验收。

## 18. 权限规则

| 角色 | 可见范围 | 可操作范围 |
|---|---|---|
| 学员 | 仅本人课包、预约、记录、反馈 | 约课、买课包、取消本人未完成预约 |
| 未绑定微信用户 | 仅登录绑定页和公开产品入口 | 不可查看学员数据 |
| 运营 | 授权校区内预约申请和学员信息 | 确认、拒绝、改期、回填场地 |
| 教练 | 本人已确认课程和相关学员信息 | 查看课程、提交反馈 |

## 19. 异常场景

| 场景 | 页面表现 | 处理规则 |
|---|---|---|
| 未绑定学员 | 提示绑定手机号 | 不展示任何学员数据 |
| 找不到学员档案 | 提示联系运营 | 不自动创建正式学员 |
| 手机号匹配多个学员 | 进入运营确认 | 不让用户自行选择他人档案 |
| 课包不足 | 展示单次付费或买课包 | 不允许负数扣课 |
| 课包过期 | 提示不可用和有效期 | 不自动延期 |
| 教练时间冲突 | 展示其他时间或待确认 | 不静默覆盖已有排课 |
| 场地待确认 | 展示等待确认 | 运营回填后通知 |
| 支付失败 | 提示重新支付 | 不生成已确认预约 |
| 支付成功但预约失败 | 进入运营异常处理 | 必须保留支付和预约失败记录 |
| AI 没听懂 | 给出快捷按钮 | 不编造结果 |
| 接口失败 | 提示稍后重试 | 不产生半条业务记录 |

## 20. 管理后台联动

学员端初版必须在管理后台形成可处理任务。

| 后台任务 | 来源 | 运营动作 |
|---|---|---|
| 待确认约课 | 学员提交预约 | 确认、改时间、拒绝 |
| 待确认场地 | 需要第三方订场 | 回填场地结果 |
| 支付异常 | 已支付但预约未确认 | 处理退款或人工安排 |
| 绑定异常 | 手机号匹配多个档案 | 人工确认绑定 |
| 体验课线索 | 体验课预约或购买 | 后续转化跟进 |

## 23. 版本规划

### V1：学员自助 MVP

1. 微信登录与学员绑定。
2. 首页 AI 输入框 + 快捷入口。
3. 一句话约课。
4. 有课包扣课预约。
5. 无课包单次支付预约。
6. 我的课包、我的预约、上课记录、课程反馈。
7. 运营后台待确认任务。

### V2：半自动排课

1. 系统自动推荐更准确的教练和时间。
2. 低风险场景可自动确认。
3. 改课、取消、候补规则完善。
4. 服务号提醒和小程序订阅消息完善。

### V3：AI 调度中枢

1. 根据教练负载、学员偏好、课包类型、场地可用性综合推荐。
2. 自动处理标准约课。
3. 运营只处理异常。
4. 形成学员、教练、运营三端联动。

## 24. 安全与财务红线

1. 不允许 AI 直接写财务流水。
2. 不允许 AI 直接扣权益，必须由系统接口按规则扣减。
3. 支付、退款、课包购买、权益核销必须可追溯。
4. 支付成功、预约成功、权益变化、财务流水必须能互相对账。
5. 生产上线前必须验证业务表、页面接口、前端展示三段链路。
6. 不展示 openid、内部流水 ID、数据库 ID、调试字段给学员。
