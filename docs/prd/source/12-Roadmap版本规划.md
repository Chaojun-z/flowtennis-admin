## 1. Roadmap 和需求池的边界

| 文档 | 作用 | 进入条件 | 输出结果 |
|---|---|---|---|
| 13-需求池 | 收纳所有想法、问题、待确认事项 | 只要出现新需求或问题即可进入 | 待澄清、待评估、待排期、暂不做、已进入 Roadmap |
| 12-Roadmap | 管理已经确认要推进的阶段计划 | 需求已明确影响范围、优先级、验收路径 | 阶段目标、范围、交付清单、验收标准 |

规则：没有进入需求池的需求，不得直接写 Roadmap；没有进入 Roadmap 的需求，不得默认进入开发。

## 2. 版本规划字段标准

| 字段 | 要求 |
|---|---|
| 阶段编号 | 例如 R-PRD-01、R-P0-01。 |
| 阶段目标 | 用业务结果描述，不写空泛“优化”。 |
| 包含范围 | 明确影响哪些端、页面、对象、口径。 |
| 不包含范围 | 明确本阶段不做什么，防止执行扩大。 |
| 前置依赖 | PRD、数据、权限、平台、测试、上线依赖。 |
| 验收标准 | 必须能被测试或人工检查。 |
| 风险等级 | 普通 / 高风险 / 财务高风险。 |
| 对应需求池 | 关联 13 中的需求编号。 |

## 3. 当前 Roadmap

### R-PRD-01：PRD 独立正本建设

| 项 | 内容 |
|---|---|
| 阶段目标 | PRD 文件组成为唯一需求、口径、字段、状态、流程、验收来源。 |
| 包含范围 | 清理旧 docs 依赖；重写数据模型；补齐页面级 PRD；完善技术上线、Roadmap、需求池、变更记录；新增完整性检查清单。 |
| 不包含范围 | 不改业务代码；不调整线上数据；不发布新功能。 |
| 前置依赖 | 现有 PRD 目录、现有代码表关系、现有字段矩阵和页面功能总览。 |
| 验收标准 | 全 PRD 不再依赖旧 docs 作为复刻必读资料；08/09 可用于页面和数据链路复刻；15 可用于后续检查。 |
| 风险等级 | 普通文档治理，但影响后续所有开发流程。 |
| 对应需求池 | REQ-001 |

## 4. 暂不做清单

| 项 | 暂不做原因 | 重新评估条件 |
|---|---|---|
| 净利润/成本拆解 | 当前成本数据不完整。 | 成本、工资、租金、渠道投放进入标准数据模型。 |
| 自定义 BI 平台 | 现阶段先保证经营分析页口径可信。 | 固定分析无法满足运营需求且数据治理稳定。 |
| 自动修数/自动决策 | 财务和权益高风险，不能让系统自动改事实数据。 | 有批次、快照、审计、回滚和人工确认机制。 |
| 约球用户自动合并主客户 | openid/手机号/客户身份边界还需确认。 | 需求池单独评审并补客户生命周期规则。 |

## 5. Roadmap 更新流程

1. 新问题先进入 `13-需求池.md`。
2. 需求池条目补齐影响端、页面、对象、口径、验收方式。
3. 确认优先级后，移动到本文件对应阶段。
4. 同步更新受影响的 `08-具体需求/`、`05`、`06`、`09`、`10`、`11`。
5. 进入开发前，用 `15-PRD完整性检查清单.md` 检查是否可执行。
