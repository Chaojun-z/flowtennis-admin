# 项目总览

> 版本：2026-07-02
> 状态：PRD 正本总入口。
> 定位：FlowTennis PRD 总入口。

## 0. PRD 正本规则

1. `docs/prd/source/` 是 FlowTennis 产品需求、口径、字段、状态、流程、页面和验收规则的唯一 PRD 正本。
2. 旧 `docs/` 下的零散文档只作为历史迁移来源，不再作为复刻系统的必读依赖。
3. 后续新增或修改任何业务规则，必须更新 PRD 目录内对应文件。
4. 如果旧文档、代码注释、运营手册和 PRD 冲突，以 PRD 为准；如果代码仍未实现 PRD，必须在对应页面或 Roadmap 标注差距。
5. 对外交接时，目标是只交付 PRD 目录，也能 1:1 复刻系统。

## 1. 系统定位

FlowTennis 是网球门店经营管理系统，覆盖线索、学员、课包、排课、订场、会员、财务、经营分析、教练端和小程序触点。系统当前以管理后台为主，辅以教练端 Web、教练小程序、服务号提醒和约球相关能力。

## 2. 当前可信基线

- 正式开发目录：`/Users/shaobaolu/Desktop/FlowTennis/flowtennis-mgmt-main`
- 可信代码基线：`origin/main`
- 生产业务数据库：TableStore `flowtennis-ue`
- 后端入口：`api/index.js`，由 `server/` 内部模块承接业务。
- 管理后台入口：`public/index.html` + `public/assets/scripts/`。

## 3. 系统边界

- 管理后台：运营、管理员、财务使用。
- 教练端 Web：教练查看工作台、提交课后评价、查看自己的学员和班次。
- 教练小程序：教练移动端查看排课和课程详情。
- 约球小程序：独立载体，本仓库只承接管理和同步边界，不得和教练小程序混淆。
- 外部触点：服务号提醒、飞书日报、消息通知。

## 4. 核心原则

1. 一个事实源 + 一个生命周期口径 + 多个页面只做展示。
2. 页面不得自己重新定义核心字段、金额、权益、转化率。
3. 财务、课包、会员、订场、权益相关变更默认高风险。
4. PRD 修改后，后续代码变更必须能映射到具体页面、字段、口径和验收标准。

## 5. 文档使用方式

- 查整体功能：看 `04-功能清单.md`。
- 查流程：看 `03-核心业务流程.md`。
- 查字段与状态：看 `06-字段与状态规则.md`。
- 查技术架构、登录和上线流程：看 `07-技术架构与上线方案.md`。
- 查页面需求：看 `08-具体需求/`，当前覆盖 44 个页面 / 触点，每个页面包含字段、操作、状态、数据关系、接口和验收。
- 查表关系：看 `09-数据模型与表关系/`。
- 查上线优先级：看 `12-Roadmap版本规划.md`。
- 收纳新想法：放 `13-需求池.md`。
- 追溯为什么这么定：看 `14-变更记录与决策记录.md`。
- 检查 PRD 是否完整：看 `15-PRD完整性检查清单.md`。


## 6. 后续需求执行顺序

1. 新问题先进入 `13-需求池.md`。
2. 确认要做后进入 `12-Roadmap版本规划.md`。
3. 按影响范围更新 `08-具体需求/`、`05`、`06`、`09`、`10`、`11`。
4. 用 `15-PRD完整性检查清单.md` 检查通过后，再进入开发或交接。
5. 重要决策同步写入 `14-变更记录与决策记录.md`。
