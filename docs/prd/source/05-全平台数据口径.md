> 版本：2026-07-02
> 状态：PRD 内置第一事实源

> 适用范围：客户中心、线索池、留存与转化、经营分析、教学中心、订场用户、会员管理、财务中心、教练端、小程序和后续新增报表。

## 0. PRD 归档规则

1. 本文是 PRD 文件组内的数据口径第一事实源。
2. 旧版数据口径文件仅作为历史迁移来源；后续应以本文为准。
3. 交付给外部团队时，只需要交付 `docs/prd/source/` 目录，不应依赖 PRD 外部散文档才能复刻系统。
4. 如果代码、旧文档、运营手册与本文冲突，以本文为准。
5. 任何新增页面字段、筛选项、顶部卡片、导出列、经营指标、财务指标，都必须先补本文，再补页面需求和测试门禁。

## 1. 文档原则

1. 本文档是全平台数据口径的第一事实源。
2. 页面、接口、读模型、经营分析和导出报表不得各自定义同名指标。
3. 同一个业务含义只能有一个指标名、一个计算公式、一个去重规则、一个排除规则。
4. 原始业务表可以分开存，但客户必须通过统一客户 ID 串联。
5. 页面只展示统一读模型算好的结果，不在页面临时拼口径。
6. 新增指标前，必须先补本文档，再补读模型、接口、页面和测试。
7. 如果旧文档、旧草案、旧代码注释与本文档冲突，以本文档为准。
8. 口径变更时，必须同步记录变更生效日期、影响范围和历史数据处理方式。
9. 历史数据是否按新口径回算，必须在口径变更评审时明确写入变更记录，不允许默认猜测。
10. 如果历史数据不回算，页面在跨越口径变更日期展示趋势或同比数据时，必须标注“口径差异”，不得把新旧口径数据当作同一连续序列直接比较。

### 1.1 口径执行硬规则

1. 本文档是全平台字段和指标的唯一口径来源。
2. 修改任何字段、指标、筛选、统计、列表展示、顶部卡片、详情字段、导出字段前，必须先检索本文档。
3. 本文档已定义的字段，代码只能调用统一读模型、统一字段定义或统一计算函数，禁止页面、接口、脚本各自重新计算。
4. 如果现有代码和本文档冲突，以本文档为准；不得为了兼容当前代码而放宽口径。
5. 如果本文档没有定义该字段，必须先补充口径定义，再实现代码。
6. 同一个字段必须通过跨页面一致性测试：同一批样本数据下，线索池、学员页、转化留存、经营分析等相关页面结果必须一致。
7. 最终交付时必须说明：本次涉及的字段在本文档中的口径位置、调用的统一计算入口、覆盖的页面和测试文件。
8. 禁止只修改单个页面或单个统计模块后宣称“全局统一”；没有接入统一读模型和跨页面测试，就不能说口径已统一。

### 1.2 口径测试与发布门禁

1. 任何新增或修改核心口径的需求，必须同时补齐文档、统一读模型、页面接入和回归测试，缺一不可。
2. 口径测试不能只测单个指标，必须覆盖以下四类门禁：
   - 跨页面一致性：同一指标在不同页面必须返回同一结果。
   - 跨模块一致性：同一字段字典、标签、排序、枚举在不同模块必须一致。
   - 边界场景一致性：退款、作废、同日多动作、混合支付、跨链成交、余额补差、第三方券码、未绑定场地、零权益异常等场景必须有回归样本。
   - 统一层唯一性：页面不得绕开统一读模型临时重算核心指标。
3. 跨页面一致性测试至少覆盖以下指标，不允许只测其中一个：
   - 总成交人数
   - 总成交转化率
   - 课程转化率
   - 订场转化率
   - 线索到订场会员转化率
   - 课包复购率
   - 订场复订率
   - 总收入
   - 已入账收入
   - 待履约收入
4. 每个核心指标的测试样本，至少覆盖以下业务组合：
   - 同一客户只买课包
   - 同一客户只订场
   - 同一客户先订场后储值
   - 同一客户既买课包又订场又储值
   - 会员余额不足补差
   - 第三方券码成交
   - 退款 / 作废 / 冲正
   - 陪打
   - 未绑定具体场地的课程
   - 零权益或异常数据
5. 任何页面如果展示本文档已定义的核心指标，必须直接读取统一层结果；测试也必须校验“页面展示值 = 统一层结果”。
6. 任何核心指标只要在一个页面改了计算逻辑，CI 必须同时回归所有引用该指标的页面；任一页面不一致即视为失败。
7. 没有通过口径一致性测试的改动，不允许合入主分支。

## 3. 统一基础口径

### 3.1 口径总表字段说明

后续所有指标都按这张表的字段补充。

| 字段 | 含义 |
|---|---|
| 口径 ID | 指标唯一编号，后续读模型和测试可引用 |
| 指标名 | 页面和文档统一展示名称 |
| 归属模块 | 客户、线索、教学、订场、会员、财务等 |
| 指标用途 | 这个指标回答什么业务问题 |
| 分子 | 指标上面的数 |
| 分母 | 指标下面的数；人数指标可为空 |
| 去重规则 | 按客户、订单、课包、场次还是流水去重 |
| 时间口径 | 按创建时间、成交时间、上课时间、订场时间还是储值时间 |
| 排除规则 | 哪些数据不能算进去 |
| 权威数据来源 | 后续实现时必须读取的事实源或统一读模型 |
| 页面使用 | 哪些页面展示或调用 |
| 当前状态 | 已固化 / 待补充 / 禁用 |

### 3.2 全局统计规则

| 规则 | 统一定义 |
|---|---|
| 人数指标 | 默认按客户 ID 去重，不按线索条数、订单条数或手机号条数直接相加 |
| 金额指标 | 默认按有效业务流水或财务流水计算，后续财务章节补全 |
| 时间筛选 | 默认按指标自己的业务发生时间，不统一混用创建时间 |
| 统计范围 | 用户在页面选择的开始时间到结束时间 |
| 统计截止时间 | 用于判断统计范围内 cohort 后续是否转化、留存或复购；默认取当前数据刷新时间；如果页面单独传入观察截止时间，则取页面传入时间和当前数据刷新时间中更早的时间 |
| 体验课 | 是教学链漏斗环节，不算正式成交 |
| 订场 | 只要是真实有效付费或有效权益消耗，就算成交 |
| 订场会员 | 属于订场链最终转化，不单独拆成第三条会员链 |
| 总成交 | 只做去重汇总，不是一条漏斗 |
| 复购 | 只在同一业务链内计算，不跨教学链和订场链混算 |
| 留存 | 看成交后是否继续使用或继续消费，不等于复购 |

## 4. 客户与身份识别口径

### 4.1 客户 ID

| 字段 | 定义 |
|---|---|
| 口径 ID | CUSTOMER_ID |
| 指标名 | 客户 ID |
| 归属模块 | 客户 |
| 指标用途 | 识别同一个真实自然人客户 |
| 统一定义 | 客户 ID = 系统识别出的唯一自然人客户 |
| 识别优先级 | 已人工合并的客户档案 ID > 已有客户档案 ID > 手机号 > 微信 unionid/openid > 会员账户 |
| 禁止规则 | 姓名不能作为唯一判断依据；线索 ID、订单 ID、课包 ID、订场记录 ID 不能当客户 ID |
| 影响范围 | 线索、体验课、正式课包、订场、订场会员、储值、消费记录、留存与转化 |
| 当前状态 | 已固化 |

### 4.2 同一个会员账户

| 字段 | 定义 |
|---|---|
| 口径 ID | MEMBERSHIP_ACCOUNT_IDENTITY |
| 指标名 | 同一个会员账户 |
| 归属模块 | 订场会员 |
| 统一定义 | 同一个会员账户 = 同一个客户 ID 下的订场会员储值账户 |
| 判断优先级 | 客户 ID > 手机号 > 微信 unionid/openid > 人工合并关系 |
| 特殊情况 | 如果手机号或微信变化，但人工确认是同一人，应合并到同一个客户 ID |
| 禁止规则 | 只是姓名一样，不能合并 |

### 4.3 有效线索数

| 字段 | 定义 |
|---|---|
| 口径 ID | LEAD_EFFECTIVE_CUSTOMERS |
| 指标名 | 有效线索数 |
| 归属模块 | 线索 |
| 指标用途 | 作为转化漏斗和总成交转化率的统一分母 |
| 分子 | 进入线索池，且未被标记为无效、重复、测试、误录的客户人数 |
| 分母 | 无 |
| 去重规则 | 同一个客户 ID 只算 1 人；没有客户 ID 时，用手机号 / 微信 / 其他唯一联系方式合并 |
| 时间口径 | 线索时间，按 4.6 `LEAD_ENTERED_AT` 执行 |
| 排除规则 | 无效、重复、测试、误录线索 |

补充规则：

1. 使用手机号去重前，必须先按 4.5 `CUSTOMER_PRIMARY_PHONE` 的标准化规则处理。
2. 如果某个标准化手机号已命中多个未合并客户 ID，或已进入重复客户异常处理队列，则该手机号对应线索不得自动合并去重。
3. 命中上述异常的线索记录，进入数据异常处理，不自动计入有效线索数。

### 4.4 姓名

| 字段 | 定义 |
|---|---|
| 口径 ID | CUSTOMER_DISPLAY_NAME |
| 指标名 | 姓名 |
| 归属模块 | 客户 |
| 指标用途 | 作为全平台统一的人名展示字段 |
| 统一定义 | 姓名 = 统一客户读模型输出的客户展示姓名 |
| 取值优先级 | 人工确认后的客户档案姓名 > 学员档案姓名 > 订场用户姓名 > 会员账户姓名 > 线索微信名 > 线索 displayName |
| 空值规则 | 所有来源都为空时显示 `-` |
| 禁止规则 | 页面不得再分别展示“微信名 / 账号 / 客户 / 姓名”作为同一含义的主字段名；统一展示名必须叫“姓名” |
| 兼容规则 | 历史原始字段允许保留，但只作为事实源，不作为页面最终字段名 |
| 当前状态 | 已固化 |

### 4.5 手机号

| 字段 | 定义 |
|---|---|
| 口径 ID | CUSTOMER_PRIMARY_PHONE |
| 指标名 | 手机号 |
| 归属模块 | 客户 |
| 指标用途 | 作为全平台统一手机号字段，用于识别、查找、去重和展示 |
| 统一定义 | 手机号 = 同一客户当前唯一主手机号 |
| 标准化规则 | 去掉空格、短横线、括号；中国大陆手机号去掉前缀 `+86` 或 `86` 后按 11 位手机号保存和比较 |
| 主手机号确定优先级 | 人工确认主手机号 > 客户档案手机号 > 学员档案手机号 > 订场用户手机号 > 会员账户手机号 > 线索手机号 |
| 唯一性规则 | 同一个标准化后的主手机号，在未删除、未作废、非测试的有效客户档案中只能归属于 1 个客户 ID |
| 异常规则 | 同一个标准化手机号命中多个未合并客户 ID 时，不自动按姓名合并；必须进入数据异常处理 |
| 空值规则 | 没有合法手机号时为空值，不得用微信号、昵称、备注代替 |
| 展示规则 | 页面展示字段统一叫“手机号”；需要脱敏时统一按 `138****8000` 形式展示 |
| 当前状态 | 已固化 |

### 4.6 线索时间

| 字段 | 定义 |
|---|---|
| 口径 ID | LEAD_ENTERED_AT |
| 指标名 | 线索时间 |
| 归属模块 | 线索 |
| 指标用途 | 表示客户首次进入线索池的时间，用于线索 cohort 统计 |
| 统一定义 | 线索时间 = 该客户首次进入线索池或首次创建线索档案的时间 |
| 取值规则 | 同一客户存在多条有效线索时，取最早一条有效线索的创建时间或明确录入的线索发生时间 |
| 导入规则 | 导入时间只是系统入库时间，不代表线索发生时间；如果导入数据带有明确线索发生时间，可覆盖创建时间；不得被更早的历史付款、排课、订场时间反向覆盖 |
| 兜底规则 | 没有线索档案时，字段为空；不允许用历史付费、历史订场、历史排课时间回填为线索时间 |
| 排除规则 | 无效、重复、测试、误录线索不参与计算 |
| 页面使用 | 线索池、客户中心、留存与转化、经营分析 |
| 当前状态 | 已固化 |

补充规则：

1. `LEAD_ENTERED_AT` 只服务线索 cohort 和线索相关报表。
2. 线索时间早于首次线索建档时间的历史业务记录，不得覆盖线索时间。
3. 如果需要表达客户更早的历史接触时间，必须单独使用 `CUSTOMER_FIRST_TOUCH_AT`，不得复用 `LEAD_ENTERED_AT`。

## 5. 转化漏斗口径

### 5.1 转化结构

FlowTennis 只保留三类转化观察口径：课程总漏斗、体验路径漏斗、订场链漏斗。

```text
课程总漏斗：线索 → 普通学员 → 正式学员 → 课包复购
体验路径漏斗：体验路径学员 → 体验路径成交 / 体验路径未成交
订场链漏斗：订场用户 → 订场会员 → 会员复购
总成交：线索 → 任一正式付费成交
```

总成交不是漏斗，只是去重汇总。

关键规则：

1. `普通学员` 表示进入课程服务体系的客户，不表示“未成交学员”。
2. `普通学员` 包含已经购买正式课包的客户；`普通学员` 和 `正式学员` 不是互斥列表。
3. `正式学员` 是 `普通学员` 的下级漏斗。
4. 未经过体验课、直接购买正式课包的客户，必须计入 `普通学员` 和 `正式学员`，并归为 `直接正式成交`。
5. `体验路径学员` 只表示有体验课预约、体验课排课或体验课课包购买证据的客户，不包含没有体验路径的直接正式成交客户。
6. `体验路径成交` 只表示体验路径学员中购买正式课包的客户；如果没有已完成体验课记录，不得命名为“体验后成交”。
7. 当前订场用户与线索池客户身份尚未打通时，订场链不得展示“线索 → 订场用户”转化率，只能展示“订场用户 → 订场会员 → 会员复购”。

### 5.2.1 预约体验课事实证据优先级

预约体验课人数只能按下列优先级取一次结果，不得把多个数据源相加。

| 优先级 | 判断证据 | 命中条件 | 预约时间 |
|---|---|---|---|
| 1 | 体验课排课记录 | 有体验课类型排课记录，且状态不是已取消、测试 | 排课开始时间 |
| 2 | 体验课预约记录 | 有独立体验课预约记录，且状态不是已取消、测试 | 预约时间 |
| 3 | 体验课课包购买记录 | 有有效体验课课包购买记录，订单未退款、未作废、非测试 | 购买时间 |

执行规则：

1. 同一客户同时命中多个证据时，只取最高优先级证据。
2. 同一客户在同一优先级有多条证据时，取最早一条有效证据。
3. 只在备注、沟通记录、聊天内容、线索阶段或手工邀约时间里写“想体验 / 已约体验”，但没有上表任何事实证据，不算预约体验课。
4. 取消后没有重新预约成功，不算预约体验课。
5. `trialAtRaw`、`trialLessonAt`、线索阶段 `已约体验` 只作为线索跟进展示字段；不得作为 `TRIAL_BOOKED_CUSTOMERS`、`TRIAL_PATH_STUDENTS`、`TRIAL_PATH_DEAL_CUSTOMERS` 的判断证据。

### 5.3.1 转化率时间归属规则

转化率统一采用线索 cohort 口径，不采用当期事件口径。

| 规则 | 定义 |
|---|---|
| cohort 人群 | 线索进入时间落在统计范围内的有效线索客户 |
| 分母 | 只从 cohort 人群里取 |
| 分子 | 只从 cohort 人群里取，且对应转化动作发生时间必须晚于或等于线索进入时间，并且不晚于统计截止时间 |
| 阶段顺序 | 课程总漏斗必须按线索 → 普通学员 → 正式学员 → 课包复购；体验路径漏斗必须按体验路径学员 → 体验路径成交 / 体验路径未成交；订场链在客户身份未打通前必须按订场用户 → 订场会员 → 会员复购 |
| 跨期转化 | 线索在本期进入，转化动作在本期之后但不晚于统计截止时间，计入该线索 cohort 的转化 |
| 当期事件 | 只看统计范围内发生的预约、到课、成交事件，不等于转化率口径 |

执行示例：

```text
统计范围：6月1日-6月30日
统计截止时间：7月15日
客户 A：6月10日进入线索池，7月5日买正式课包
客户 A 计入 6月线索 cohort 的课程转化率分子。
```

补充说明：

1. `COURSE_CHAIN_ENTRY_RATE`、`COURSE_STUDENT_TO_FORMAL_RATE` 和 `COURSE_CONVERSION_RATE` 是课程总漏斗口径，包含直接正式成交客户。
2. 教练视角的体验转化效率，统一使用 `COACH_TRIAL_CONVERSION_RATE`，不得直接复用 `TRIAL_TO_COURSE_RATE`。
3. `TRIAL_BOOKED_CUSTOMERS`、`TRIAL_ATTENDED_CUSTOMERS`、`COURSE_DEAL_CUSTOMERS` 在漏斗和转化率计算中，必须使用同一批线索 cohort 人群。
4. `TRIAL_ATTENDED_CUSTOMERS` 的体验课完成时间必须大于或等于该客户的 `LEAD_ENTERED_AT`，且不晚于统计截止时间。
5. `TRIAL_TO_COURSE_RATE` 的分子只统计“先已体验、后购买正式课包”的客户，不直接复用 `COURSE_DEAL_CUSTOMERS` 全量结果。
6. 未参加标准体验课、直接购买正式课包的私教直接转化客户，计入 `COURSE_DEAL_CUSTOMERS` 和 `COURSE_CONVERSION_RATE`，但不计入 `TRIAL_TO_COURSE_RATE` 分子。
7. 如果客户已体验但在统计截止时间前尚未购买正式课包，该客户进入 `TRIAL_TO_COURSE_RATE` 分母但不进入分子，这是正常现象；随着统计截止时间后移，分子可以继续增长。
8. `TRIAL_PATH_DEAL_RATE` 和 `TRIAL_TO_COURSE_RATE` 不是同一个指标。前者只要求客户有体验路径证据并购买正式课包；后者要求客户先完成有效体验课，再购买正式课包。
9. 当数据库没有已完成 / 已到课 / 已消课的体验课记录时，`TRIAL_ATTENDED_CUSTOMERS = 0`，页面不得把 `TRIAL_PATH_DEAL_CUSTOMERS` 命名为“体验后成交”。

```text
体验路径学员 / 普通学员 = 36 / 110 = 32.7%
体验路径成交率 = 14 / 36 = 38.9%
体验路径未成交率 = 22 / 36 = 61.1%
直接正式成交 / 正式学员 = 74 / 88 = 84.1%
课包复购率 = 18 / 88 = 20.5%
```

必须满足的恒等关系：

```text
普通学员包含体验路径学员、已转化课程学员、正式课包学员和有排课记录学员；同一客户多条证据只算 1 人。

正式学员 = 体验路径成交 + 直接正式成交
88 = 14 + 74

体验路径未成交 = 体验路径学员 - 体验路径成交
22 = 36 - 14
```

订场链当前生产验收样例：

```text
订场用户 = 339
订场会员 = 33
会员复购 = 3
订场复订人数 = 148

订场会员转化率 = 33 / 339 = 9.7%
会员复购率 = 3 / 33 = 9.1%
订场复订率 = 148 / 339 = 43.7%
```

当前生产库中，订场用户和订场会员可关联到线索池的数量为 0。因此在客户身份未打通前，经营分析不得展示 `线索数 → 订场用户` 转化率。

### 5.4 首次订场后入会率补充规则

| 规则 | 定义 |

## 6. 留存与复购口径

### 6.1 留存结构

```text
教学留存：正式课包后是否续买 / 持续上课
```

### 6.3 复购率时间归属规则

复购率统一采用首购 cohort 口径，不采用当期复购事件口径。

| 指标 | 分母 | 分子 |
|---|---|---|
| 课包复购率 | 统计范围内首次购买正式课包的客户人数 | 分母客户中，首次购买之后、统计截止时间前发生第二次及以上正式课包购买的人数 |
| 订场复订率 | 统计范围内首次发生有效订场的客户人数 | 分母客户中，首次订场之后、统计截止时间前发生第二次及以上有效订场的人数 |
| 订场会员再次储值率 | 统计范围内首次有效储值成为订场会员的客户人数 | 分母客户中，首次储值之后、统计截止时间前发生第二次及以上有效储值的人数 |
| 总复购率 | 统计范围内首次成为总成交的客户人数 | 分母客户中，首次成交之后、统计截止时间前发生课包复购或订场会员再次储值的人数；第二次及以上订场不计入总复购 |

执行规则：

1. 第三次、第四次购买不增加复购人数，只影响复购次数和复购金额。
2. 跨链购买不算复购。
3. 统计范围只决定分母 cohort；分子动作可以发生在统计范围之后，但不能晚于统计截止时间。
4. 第二次及以上订场属于订场复订或订场持续消费，不属于总复购率分子。
5. `COURSE_REPEAT_BUYERS` 是增量指标，定义为统计范围内首次发生第二次及以上正式课包购买的客户人数，按第二次正式课包购买时间归属统计范围。
6. `COURT_REBOOK_CUSTOMERS` 是增量指标，定义为统计范围内首次发生第二次及以上有效订场的客户人数，按第二次有效订场时间归属统计范围。
7. `COURSE_REPEAT_BUYERS` 和 `COURSE_REPEAT_RATE` 的 cohort 基础不同，不能直接用 `课包复购人数 / 任意首购人数` 反推课包复购率。

### 6.4 课包续购窗口

| 续购窗口条件 | 进入窗口时间 |
|---|---|
| 剩余课时 | 有效消课后，课包剩余课时首次 <= 2 的核销时间 |
| 已消耗完 | 有效消课后，课包剩余课时首次 = 0 的核销时间 |
| 到期窗口 | 课包到期日前 30 天的 00:00 |

执行规则：

1. 满足任一条件，即进入课包续购窗口。
2. 同一个课包只取最早一次进入窗口时间。
3. 分母统计时间口径：统计范围内首次进入续购窗口的客户人数，按进入窗口时间归属统计范围。
4. 如果同一客户有多个正式课包在统计范围内进入续购窗口，分母只算 1 人，取最早进入窗口的课包作为本次续购判断对象。
5. 有课包到期日时，无论该客户是因剩余课时、已消耗完还是到期窗口进入续购窗口，续购窗口结束时间统一 = 课包到期日后 30 天的 23:59:59。
6. 只有课包没有到期日时，续购窗口结束时间才 = 进入窗口时间后 30 天的 23:59:59。
7. 分子判断截止时间 = 续购窗口结束时间 和 统计截止时间 中更早的时间。
8. 分子只统计购买时间大于或等于进入窗口时间，且小于或等于分子判断截止时间的正式课包购买客户。
9. 如果续购购买时间早于进入窗口时间，或晚于分子判断截止时间，不计入本次续购。
10. 全局 `COURSE_RENEWAL_RATE` 的分母按客户全局最早进入续购窗口的课包取 1 次；教练维度 `COACH_PACKAGE_RENEWAL_RATE` 可因不同课包归属不同教练而在多个教练分母中分别出现。
11. 因此，全局课包续购率分母与各教练课包续购率分母之和不可直接相加校验；两者必须分别按统一读模型取数。

### 6.5 N 日留存观察期

| 指标 | N 的固定取值 | 默认展示 |
|---|---|---|
| N 日订场持续消费率 | 7 / 30 / 60 / 90 / 120 / 360 | 30 日 |
| N 日订场会员留存率 | 30 / 60 / 90 | 30 日 |

执行规则：

1. N 只能使用上表固定取值。
2. 如果页面只展示一个值，必须展示默认值。
3. 如果页面提供切换，只能在上表固定取值中切换。
4. 分母只包含已完整度过 N 天观察期的客户。
5. 观察期是否完整的判断：起点事件时间 + N 天 <= 统计截止时间。
6. 订场持续消费的起点事件是首次有效订场；分子事件必须是同一客户的第二次及以上有效订场，且订场开始时间大于首次有效订场开始时间。
7. 订场会员留存的起点事件是首次有效储值；分子事件必须是同一客户首次有效储值后的有效订场，包含余额扣款订场、单独支付订场、会员权益抵扣订场。
8. 如果只有日期没有时分秒，起点当天发生的第二条及以上有效订场记录计入 N 日观察期；同一条订场记录不能同时作为起点和分子。

### 6.6 不算复购的情况

| 行为 | 是否复购 | 原因 |
|---|---|---|
| 先买课包，后订场 | 否 | 两条链路分别转化，不是同链复购 |
| 先订场，后买课包 | 否 | 两条链路分别转化，不是同链复购 |
| 先订场，后储值订场会员 | 否 | 这是订场链升级，不是复购 |
| 储值后继续订场 | 否 | 对订场会员来说是留存，不是再次储值 |
| 买第三个正式课包 | 不增加复购人数 | 已在第二次购买时计为复购人，第三次只增加次数和金额 |

## 9. 财务金额口径

### 9.1 统一底层规则

1. 所有财务统计都以有效财务流水为最小单位。
2. 同一条流水只能表达一个动作：收款、消耗、退款或废弃，不能同时兼做多个动作。
3. 所有财务时间字段统一使用北京时间 `YYYY-MM-DD HH:mm:ss`。
4. 混合支付必须拆分成多条流水。例如：应收 200，储值扣 150，微信补 50，必须拆成 1 条储值消耗流水和 1 条微信收款流水。
5. 退款、作废、冲正不得直接改写原收款流水，必须生成独立负向流水。
6. 没有进入有效财务流水的业务，不计入任何财务汇总。
7. 即时履约 = 支付后无需等待后续课包核销或储值消耗、在当次服务完成时即可确认收入的业务。
8. 即时履约当前只包括：排课直接收款中的课程收款、排课直接收款中的场地收款。
9. 散客订场、约球局虽然也是单次履约业务，但在财务口径中单独归类，不并入“即时履约”定义，避免重复归类。

### 9.2 财务字段总表

| 口径 ID | 指标名 | 统一定义 | 公式 / 规则 | 当前状态 |
|---|---|---|---|---|
| FIN_TOTAL_INCOME | 总收入 | 统计范围内所有有效正向收款流水的实收金额之和 | `总收入 = Σ(有效收款流水.实收金额)` | 已固化 |
| FIN_COURSE_INCOME | 课程收入 | 总收入中归属课程业务的实收金额 | 正式课包购买实收 + 体验课实收 + 排课课程直接收款 + 课程类第三方券结算收入 + 课程补差收款 | 已固化 |
| FIN_COURT_INCOME | 场地收入 | 总收入中归属场地业务的实收金额 | 散客订场实收 + 约球局实收 + 排课场地收款 + 会员订场现金补差 + 场地类第三方券结算收入 | 已固化 |
| FIN_COURT_MEMBER_RECHARGE | 订场会员储值收入 | 用户购买订场会员储值时产生的有效正向实收金额 | `Σ(有效会员储值收款流水.实收金额)` | 已固化 |
| FIN_RECOGNIZED_REVENUE | 已入账收入 | 统计范围内已完成履约、可确认收入的金额 | 课包核销确认收入 + 会员订场余额消耗确认收入 + 散客订场完成确认收入 + 约球局完成确认收入 + 即时履约收款确认收入 | 已固化 |
| FIN_PENDING_REVENUE | 待履约收入 | 截止统计时点已经收款但尚未履约的金额 | 累计有效课包实收 + 累计有效会员储值实收 - 累计已入账收入 - 累计对应退款 / 作废冲减 | 已固化 |
| FIN_REFUND_AMOUNT | 退款金额 | 统计范围内所有有效退款流水金额绝对值之和 | `退款金额 = Σ(abs(有效退款流水.退款金额))` | 已固化 |
| FIN_NET_CASH_INCOME | 净实收 | 统计范围内真正留在账上的净现金流入 | `净实收 = 总收入 - 退款金额` | 已固化 |
| RECEIVABLE_AMOUNT | 应收金额 | 这次业务按最终成交条件应该支付的总金额 | 课包购买取订单应付金额；订场取本次订场应付金额；直接收款取本次课程费或场地费；会员储值取充值金额 | 已固化 |
| ACTUAL_RECEIVED_AMOUNT | 实收金额 | 本次交易实际新增收到的钱 | 只包括微信、支付宝、现金、转账、大众点评券码、抖音券码、其他第三方券结算金额 | 已固化 |
| DIFF_AMOUNT | 差价 | 同一条收款流水里，应收和实收之间的差额 | `差价 = 应收金额 - 实收金额` | 已固化 |
| DIFF_REASON | 差价说明 | 对差价来源的标准解释 | 只允许使用统一枚举 | 已固化 |
| TRANSACTION_TIME | 交易时间 | 交易真正生效的时间 | 收款取支付成功时间；消耗取履约 / 核销成功时间；退款取退款成功时间；废弃取作废或冲正生效时间 | 已固化 |
| TRANSACTION_TYPE | 交易类型 | 财务动作统一分类 | 固定值：收款、消耗、退款、废弃 | 已固化 |
| INCOME_TYPE | 收入类型 | 对收入按业务归属做一级分类 | 固定值：课程收入、场地收入、会员储值收入 | 已固化 |
| BUSINESS_TYPE | 业务类型 | 对业务事实做统一业务归类 | 取 12.7.8 业务类型统一字典 | 已固化 |
| PAYMENT_METHOD | 支付方式 | 用户本次实际支付或结算方式 | 固定值：储值卡、微信、支付宝、现金、转账、大众点评券码、抖音券码、其他 | 已固化 |

字段关系：

1. `FIN_TOTAL_INCOME = FIN_COURSE_INCOME + FIN_COURT_INCOME + FIN_COURT_MEMBER_RECHARGE`
2. `FIN_COURT_INCOME` 不包含订场会员储值实收。
3. 订场会员储值实收只进入 `FIN_COURT_MEMBER_RECHARGE`，不重复计入 `FIN_COURT_INCOME`。
4. `PAYMENT_METHOD = 储值卡` 的流水，`TRANSACTION_TYPE` 必须为 `消耗`，不得为 `收款`。
5. 实现时不得只看 `PAYMENT_METHOD` 判断是否计入总收入，必须同时校验 `TRANSACTION_TYPE`。

### 9.3 总收入纳入口径

总收入只纳入以下真实收款场景：

1. 正式课包购买实收。
2. 体验课购买实收。
3. 排课直接收款中的课程收款。
4. 排课直接收款中的场地收款。
5. 大众点评券码、抖音券码和其他第三方平台券码对应的结算收入。
6. 散客订场实收。
7. 约球局实收。
8. 订场会员储值实收。
9. 会员订场余额不足时的现金、微信、支付宝或转账补差实收。

以下场景不计入总收入：

1. 储值余额消耗。
2. 课包权益核销。
3. 赠送金额。
4. 权益抵扣。
5. 测试、作废、未生效记录。
6. 退款负向流水。

### 9.4 差价说明固定枚举

`DIFF_REASON` 只允许以下固定值：

```text
储值余额抵扣
课包权益抵扣
平台结算差额
优惠减免
手工改价
赠送
超收
补录差异
其他
```

执行规则：

1. `差价 != 0` 时，差价说明必填。
2. `差价 = 0` 时，差价说明为空。
3. 储值余额抵扣、课包权益抵扣不得写成“其他”。
4. 第三方券码到账与标价不一致时，必须写 `平台结算差额`。
5. 如果 `实收金额 > 应收金额`，允许 `差价 < 0`；此时差价说明只能使用 `超收` 或 `补录差异`。
6. 负差价记录必须进入异常提示队列，不得静默忽略。

### 9.5 已入账触发规则

1. 课包已入账收入触发时间 = 实际核销成功时间。
2. 会员订场已入账收入触发时间 = 订场实际完成时间。
3. 散客订场已入账收入触发时间 = 订场实际完成时间。
4. 约球局已入账收入触发时间 = 约球局结束时间。
5. 约球局没有明确结束时间时，优先取预约结束时间；仍没有结束时间时，该记录进入数据异常处理，不自动推断。
6. 即时履约收款当前只包括排课直接收款中的课程收款、排课直接收款中的场地收款；已入账触发时间 = 该次课程或场地服务实际完成时间。

### 9.6 快照与守恒规则

1. `FIN_TOTAL_INCOME`、`FIN_COURSE_INCOME`、`FIN_COURT_INCOME`、`FIN_COURT_MEMBER_RECHARGE`、`FIN_RECOGNIZED_REVENUE` 默认是统计范围内的区间增量指标。
2. `FIN_PENDING_REVENUE` 是截止统计范围结束时点的快照指标，不是统计范围内的区间增量指标。
3. `FIN_PENDING_REVENUE` 的所有组成项都取截止统计结束时点的历史累计值，不得与统计范围内增量值混用。
4. 递延类收入守恒关系只适用于课包和订场会员储值，不适用于散客订场、约球局或即时履约直接收款。
5. 课包守恒关系：
   - `历史累计课包实收 = 历史累计课包已入账 + 截止时点课包待履约 + 历史累计课包退款/作废冲减`
6. 订场会员储值守恒关系：
   - `历史累计会员储值实收 = 历史累计会员储值已入账 + 截止时点会员储值待履约 + 历史累计会员储值退款/作废冲减`
7. 统一读模型每次刷新后，必须对课包和订场会员储值执行守恒校验；任一账户不满足守恒关系时，进入异常告警队列。
8. `FIN_REFUND_AMOUNT` 按退款成功时间归属统计范围，不要求原收款发生在同一统计范围内。
9. 因此，某个统计范围内出现“退款金额大于当期总收入”或“净实收为负数”是正常财务现象，不视为数据异常。

## 10. 课包核销与权益口径

### 10.1 课包权益字段总表

| 口径 ID | 指标名 | 统一定义 | 公式 / 规则 | 当前状态 |
|---|---|---|---|---|
| PACKAGE_INITIAL_RIGHTS | 课包初始总权益 | 课包生效时一次性发放的总课时 / 总次数 | `初始总权益 = 付费权益 + 同单赠送权益` | 已固化 |
| PACKAGE_ACTIVE_ENTITLEMENT | 当前有效权益 | 截止统计时点仍可继续使用的课包权益 | `当前有效权益 = 初始总权益 + 后续补赠 - 已核销 - 已过期 - 已作废 - 已退款回收` | 已固化 |
| PACKAGE_LESSON_CONSUMED | 已核销权益 | 累计成功消课的课时 / 次数 | 只统计已完成、已到课、已消课；不统计取消、爽约、未到、待上课和核销回退后的记录 | 已固化 |
| PACKAGE_REMAINING_LESSONS | 剩余权益 | 截止统计时点客户还能继续使用的课时 / 次数 | 展示别名，直接复用 `PACKAGE_ACTIVE_ENTITLEMENT`，不单独计算、不单独建列、不单独维护 | 已固化 |
| PACKAGE_UNIT_RECOGNIZED_AMOUNT | 单位确认收入 | 每核销 1 课时 / 1 次可确认的收入金额 | `单位确认收入 = 课包有效实收金额 / 课包初始总权益` | 已固化 |
| PACKAGE_RECOGNIZED_AMOUNT | 课包已入账金额 | 课包累计已确认的收入金额 | `课包已入账金额 = 已核销权益 × 单位确认收入` | 已固化 |
| PACKAGE_PENDING_AMOUNT | 课包待入账金额 | 已收款但尚未通过核销确认的课包收入金额 | `课包待入账金额 = 课包有效实收金额 - 课包已入账金额 - 已退款冲减金额` | 已固化 |
| PACKAGE_EXPIRED_RIGHTS | 过期未用权益 | 到期时仍未核销、未退款回收、未作废回收的权益数量 | 截止失效日直接冻结，不再可用 | 已固化 |
| PACKAGE_VOIDED_PURCHASE | 作废权益 | 因手工作废、订单撤销、系统冲正被回收的权益数量 | 只记录被回收的未使用权益 | 已固化 |
| PACKAGE_REFUNDED_RIGHTS | 退款回收权益 | 因课包退款而回收的未使用权益数量 | 退款必须同时影响金额和权益，不能只退钱不回收权益 | 已固化 |

### 10.2 执行规则

1. 赠送权益参与单位确认收入分摊，不单独按 0 元核销。
2. 课包核销的最小事实单位是单次排课对应的实际消课记录，不允许页面按课包余额反推。
3. 同一条排课记录如果发生核销回退，必须生成独立回退记录，不允许直接覆盖原核销记录。
4. 课包作废后，未使用权益全部退出当前有效权益；已核销历史不回滚到未使用权益。
5. 课包退款后，已退款冲减金额进入财务退款口径，未使用权益进入退款回收权益。
6. 体验课包、赠课包、测试课包不进入正式课包权益口径。
7. 如果课包初始总权益 = 0，则 `PACKAGE_UNIT_RECOGNIZED_AMOUNT` 为空值，不参与任何财务汇总，并进入数据异常处理队列。
8. `已过期权益` 和 `已作废权益` 必须互斥；同一份未使用权益不能同时进入过期和作废。
9. 作废优先于到期；课包在到期前已作废时，未使用权益只进入 `PACKAGE_VOIDED_PURCHASE`，不再进入 `PACKAGE_EXPIRED_RIGHTS`。
10. 部分退款规则：`退款金额 = 退款权益数量 × PACKAGE_UNIT_RECOGNIZED_AMOUNT`。
11. 已核销权益对应的已入账收入不参与退款计算；只有未使用权益可以进入退款回收权益。
12. 部分退款后，必须同时更新 `已退款冲减金额` 和 `PACKAGE_REFUNDED_RIGHTS`，并继续满足 9.6 的守恒规则。
13. 如果核销回退涉及的权益已进入 `PACKAGE_REFUNDED_RIGHTS`，该核销回退记录必须标记为无效，不得恢复对应权益数量。
14. 命中“已退款权益又尝试核销回退”的记录，必须进入异常告警队列，不得静默处理。

## 11. 场地使用与场时口径

### 11.1 场时基础定义

| 口径 ID | 指标名 | 统一定义 | 计算方法 | 不计入 | 页面使用 | 当前状态 |
|---|---|---|---|---|---|---|
| COURT_AVAILABLE_HOURS | 可用场时 | 统计范围内可对外经营的场地时间总和 | 单日可用场时 = 启用场地数量 × 当日可经营小时数；多日可用场时 = 每一天单日可用场时相加 | 场地维修、临时关闭、不对外开放时段、内部占用、系统明确标记不可用的场地或时段 | 经营分析、场地运转、热力图 | 已固化 |
| COURT_USED_HOURS | 已使用场时 | 统计范围内真实占用了具体场地的时间 | 按有效占场记录的开始和结束时间折算小时数 | 内部占用、维修、临时关闭、未确认预约、已取消、已退款、测试订单、未绑定具体场地的课程或活动 | 经营分析、场地运转、热力图 | 已固化 |
| COURT_BUSINESS_HOURS | 经营场时 | 实际产生收入、权益消耗、课包核销或会员余额消耗的场地使用时间 | 在已使用场时中，筛选有收入、权益消耗、课包核销或会员余额消耗的记录 | 内部占用、免费活动、纯赠送且无财务确认的占场、维修、临时关闭、测试、取消、退款 | 经营分析、财务辅助分析 | 已固化 |
| COURT_INTERNAL_OCCUPANCY | 内部占用 | 因内部活动、教练训练、运营活动、领导使用等锁定场地，但不对外经营的时间 | 按内部占用记录的开始和结束时间折算小时数 | 不进入可用场时、已使用场时、经营场时和利用率分子 | 热力图、场地排班 | 已固化 |

补充规则：

1. 启用场地 = 在系统中被明确标记为当日可对外经营状态的物理场地。
2. 未开放、维修中、临时关闭、已停用、系统标记不可用的场地，不计入当日启用场地数量。
3. 排课记录里填写了具体校区和具体场地，且课程未取消，算课程占场。
4. 约球活动绑定了具体校区和具体场地，且活动未取消，算约球占场。
5. 没有绑定具体场地的课程、约球或活动，不计入场地使用和利用率。
6. 内部占用必须在热力图上单独显示，使用灰色或斜纹，不使用蓝色热度，避免被误认为高热度经营使用。
7. 课程类核销只有在排课绑定了具体场地时，才计入经营场时；如果只绑定校区不绑定场地，课包核销仍计入财务已入账，但不计入经营场时，两者允许不相等，不视为异常。

### 11.2 场地利用率

| 口径 ID | 指标名 | 公式 | 业务解释 | 当前状态 |
|---|---|---|---|---|
| COURT_UTILIZATION_RATE | 场地利用率 | 已使用场时 / 可用场时 | 看可经营场地时间里有多少被真实使用 | 已固化 |
| COURT_DAILY_UTILIZATION_RATE | 当日场地利用率 | 当日已使用场时 / 当日可用场时 | 看某一天场地使用情况 | 已固化 |
| COURT_RANGE_UTILIZATION_RATE | 选定范围场地利用率 | 选定范围内已使用场时 / 选定范围内可用场时 | 看本周、本月或自定义时间范围内的场地使用情况 | 已固化 |
| COURT_BUSINESS_UTILIZATION_RATE | 经营利用率 | 经营场时 / 可用场时 | 看可经营场地时间里有多少产生经营价值 | 已固化 |

计算规则：

1. 当日可用场时 = 当日启用场地数量 × 当日可经营小时数。
2. 本周可用场时 = 本周每天可用场时相加，不直接假设每天都一样。
3. 本月可用场时 = 本月每天可用场时相加。
4. 自定义范围可用场时 = 用户选择的每一天可用场时相加。
5. 若某天有维修、临时关闭、内部占用或不可用时段，必须先从当天可用场时中扣除。
6. 计算最小单位必须用分钟，页面展示再换算成小时，避免跨小时记录误差。

例子：

```text
1 片场，当日可经营 10 小时，已使用 2 小时
当日场地利用率 = 2 / 10 = 20%

4 片场，当日每片可经营 10 小时，已使用 8 小时
当日可用场时 = 4 × 10 = 40
当日场地利用率 = 8 / 40 = 20%

4 片场，连续 7 天，每天每片可经营 10 小时，已使用 80 小时
本周可用场时 = 4 × 10 × 7 = 280
本周场地利用率 = 80 / 280 = 28.57%
```

教练课时量补充规则：

1. 私教课、体验课、小班课、大师课等课程类型计入课时量。
2. 陪打不计入课时量。
3. 课时量按课程实际时长折算，不按课程条数简单计数。
4. 一节课 60 分钟计 1 课时；90 分钟计 1.5 课时；120 分钟计 2 课时。
5. 小班课、团课、多人课不按学员人数倍增课时；一节 60 分钟小班课仍计 1 课时。
6. 一节课记录多个上课教练时，每名上课教练各计完整课时，不做平分。
7. 课时量不是比例指标，没有分子和分母；实现时直接汇总有效课程时长。

教练工作量补充规则：

1. 私教课、体验课、小班课、大师课、陪打都计入工作量。
2. 工作量按单次排课或服务实际完成时长折算，不按记录条数简单计数。
3. 一节 60 分钟服务计 1 小时工作量；90 分钟计 1.5 小时；120 分钟计 2 小时。
4. 小班课、团课、多人课不按学员人数倍增工作量。
5. 一节课记录多个上课教练时，每名上课教练各计完整工作量，不做平分。
6. 工作量用于衡量教练实际投入，不替代课时量。

教练体验课转化率补充规则：

1. 分母按体验课上课教练计算。
2. 分子按正式课包成交教练计算。
3. 只有同一个客户的体验课上课教练和正式课包成交教练都是同一教练时，才计入该教练体验课转化率分子。
4. 不设置 30 天、60 天等成交时间窗口。
5. 体验课完成后任意时间购买正式课包，只要购买时间满足第 9、10 条，且成交教练一致，就计入分子。
6. 同一客户在同一教练名下完成多次体验课，分母只算 1 人，取该教练名下最早一次已完成体验课作为判断时间。
7. 同一客户在多个教练名下分别完成体验课，分别进入对应上课教练的分母。
8. 同一客户购买多个正式课包，分子只算 1 人，取购买时间最早且成交教练一致的正式课包作为判断依据。
9. 如果体验课完成时间和正式课包购买时间只有日期没有时分秒，同一自然日完成体验并购买正式课包，计入分子。
10. 如果有具体时分秒，正式课包购买时间必须大于体验课完成时间；购买时间早于或等于体验课完成时间，不计入分子。

课后反馈完成率补充规则：

1. 有效课次数按排课记录计数，不按学员人数计数。
2. 小班课、团课、多人课的一条排课记录只算 1 个需反馈课次。
3. 一节课记录多个上课教练时，该课对每名上课教练各形成 1 个需反馈课次。
4. 当前排课记录已有有效课后反馈，即视为该课对所有上课教练反馈完成。
5. 有效课后反馈 = 反馈记录已提交，未删除，未作废，且关联到该排课记录。
6. 是否需要课后反馈以课程类型配置为准；课程类型未配置“需要课后反馈”时，该课程不进入分母。

教案提交率补充规则：

1. 需教案课次数按排课记录计数，不按学员人数计数。
2. 小班课、团课、多人课的一条排课记录只算 1 个需教案课次。
3. 一节课记录多个上课教练时，该课对每名上课教练各形成 1 个需教案课次。
4. 当前排课记录已有有效教案或教练提案，即视为该课对所有上课教练教案已提交。
5. 有效教案或教练提案 = 教案记录或教练提案记录已提交，未删除，未作废，且关联到该排课记录。
6. 是否需要教案或教练提案以课程类型配置为准；课程类型未配置“需要教案”或“需要教练提案”时，该课程不进入分母。
7. 教案按时提交率的按时判断：有效教案或教练提案的提交时间必须小于或等于课程开始时间。
8. 教案或教练提案的提交时间一经记录，不允许直接覆盖修改。
9. 如确有录入错误，必须作废原记录并重新提交新记录，不得直接改历史提交时间。

课包续购补充规则：

1. 教练课包续购率只按课包归属教练归因。
2. 不按上课教练归因。
3. 不按成交教练归因。
4. 一个客户在续购窗口内多次购买正式课包，续购人数只算 1 人。
5. 归因对象是进入续购窗口的原课包归属教练；续购新课包的课包归属教练不改变本次续购率归因。
6. 同一客户在同一统计范围内有多个课包分别归属不同教练并进入续购窗口时，该客户可分别进入不同教练的分母；同一教练名下只算 1 人。
7. 同一客户在同一教练名下有多个课包进入续购窗口时，取该教练名下最早进入续购窗口的课包作为判断对象。
8. 教练课包续购率的续购窗口和分子判断截止时间，完全复用 6.4 `课包续购窗口` 规则，不得单独定义另一套时间上限。

## 13. 数据质量与异常排除口径

### 13.1 有效记录标准

有效记录必须同时满足：

1. 非测试。
2. 非重复脏数据。
3. 金额、时间、客户归属、校区归属满足当前指标要求。
4. 状态已生效。
5. 不属于被删除、作废、冲正后失效的记录。

### 13.3 执行规则

1. 人数指标默认按客户 ID 去重；未完成客户合并前，不得按姓名去重。
2. 测试记录默认不进入任何经营、转化、留存、财务和教练统计。
3. 作废记录默认不进入任何正向统计；如需展示，只能在审计明细里展示。
4. 退款记录不计入成交人数、总收入、有效权益和正向消耗。
5. 取消、爽约、未到、待上课的排课记录，不进入已体验、课时量、工作量、课后反馈和核销统计。
6. 孤儿记录不得自动按姓名硬拼到客户档案，必须进入数据修复队列。
7. 同一标准化手机号命中多个未合并客户 ID 时，按重复客户处理，不自动统计为多人。
