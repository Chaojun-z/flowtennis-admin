## 1. 模型目标

会员储值与权益模型保证开卡、续充、赠送权益、订场扣费、权益消耗、财务收入都能追溯到同一个会员账户。

| 原则 | 说明 |
|---|---|
| 会员账户不是独立自然人 | 必须挂到订场用户和客户生命周期。 |
| 会员订单是储值事实 | 开卡、续充、充值均写会员订单。 |
| 会员权益流水是余额和权益凭证 | 余额、赠送权益、扣费、补发、作废都要可追溯。 |
| 会员储值收入和赠送权益分开 | 实收进入储值收入，赠送只作为权益。 |
| 财务展示必须同源 | 会员页、订场页、财务页读取同一事实链。 |

## 2. 核心表和对象

| 对象 | 表/来源 | 定位 |
|---|---|---|
| 订场用户 | `ft_courts` | 会员账户归属的客户主档之一。 |
| 会员方案 | `ft_membership_plans` | 可售储值/赠送/折扣方案。 |
| 会员账户 | `ft_membership_accounts` | 用户当前会员身份、余额、状态。 |
| 会员订单 | `ft_membership_orders` | 开卡、续充、充值事实。 |
| 会员权益流水 | `ft_membership_benefit_ledger` | 余额、赠送权益、扣费、补发、作废的凭证。 |
| 会员账户事件 | `ft_membership_account_events` | 账户状态变化审计。 |
| 财务流水 | `ft_financial_ledger`/`courts.history`/财务统一层 | 会员储值收入、消耗、退款等财务展示来源。 |

## 3. 主关系

| 关系 | 规则 |
|---|---|
| 订场用户 -> 会员账户 | 一个订场用户可有会员账户；账户必须能回到客户生命周期。 |
| 会员方案 -> 会员订单 | 订单保存方案快照，后续改方案不影响历史订单。 |
| 会员账户 -> 会员订单 | 一个会员账户可多次开卡/续充。 |
| 会员订单 -> 权益流水 | 订单产生充值、赠送、折扣权益流水。 |
| 订场消费 -> 权益流水 | 使用会员余额或权益订场时产生消耗流水。 |
| 会员订单/消耗 -> 财务统一层 | 财务页展示储值收入、已消耗、余额。 |

## 4. 会员方案字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 方案 ID | 全局唯一。 |
| `name` | 方案名称 | 页面展示和订单快照使用。 |
| `rechargeAmount` | 充值金额 | 实收储值基准。 |
| `giftAmount` | 赠送金额 | 不计入实收收入。 |
| `benefits` | 赠送权益 | 可包含场地、活动、折扣等权益。 |
| `discountRate` | 折扣 | 订场扣费时使用。 |
| `validDays` | 有效期 | 新账户或续费后计算有效期。 |
| `campusScope` | 适用校区 | 多校区扩展必须明确。 |
| `status` | 状态 | 草稿、上架、停售。 |

## 5. 会员账户字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 账户 ID | 全局唯一。 |
| `courtId` | 订场用户 ID | 必须可追溯到订场用户。 |
| `customerId` | 生命周期客户 ID | 读模型生成或显式保存。 |
| `phone` | 手机号 | 与客户生命周期一致。 |
| `status` | 会员状态 | active、expired、paused、voided 等。 |
| `balance` | 储值余额 | 由订单和消耗流水汇总，不靠页面手填。 |
| `giftBalance` | 赠送余额/权益 | 与实收余额分开。 |
| `validFrom`/`validTo` | 有效期 | 过期后不可享受会员权益。 |
| `lastOrderId` | 最近订单 | 便于追溯最近一次开卡/续充。 |

## 6. 会员订单字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 订单 ID | 全局唯一。 |
| `accountId` | 会员账户 ID | 必填。 |
| `planId` | 会员方案 ID | 可为空但必须保存方案快照。 |
| `planSnapshot` | 购买时方案快照 | 保存充值金额、赠送、折扣、有效期。 |
| `paidAmount` | 实收金额 | 进入会员储值收入。 |
| `giftAmount` | 赠送金额 | 不作为实收。 |
| `paymentMethod` | 支付方式 | 使用统一字典。 |
| `purchaseDate` | 购买时间 | 财务和会员统计使用。 |
| `status` | 订单状态 | 有效、作废、退款等。 |
| `operator` | 操作人 | 必须可审计。 |

## 7. 会员权益流水字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 流水 ID | 全局唯一。 |
| `accountId` | 会员账户 | 必填。 |
| `orderId` | 来源订单 | 充值/赠送/作废时必填。 |
| `courtHistoryId` | 来源订场消费 | 消耗时应能追溯。 |
| `action` | 动作 | recharge、grant、consume、adjust、void、refund、expire。 |
| `benefitType` | 权益类型 | cash、gift、discount、courtBenefit 等。 |
| `deltaAmount` | 金额变化 | 正负必须清楚。 |
| `balanceAfter` | 变更后余额 | 用于审计。 |
| `reason` | 原因 | 人工调整、作废、补发必须填写。 |
| `operator` | 操作人 | 系统/后台账号。 |

## 8. 状态规则

| 对象 | 状态 | 进入条件 | 禁止操作 |
|---|---|---|---|
| 方案 | 草稿 | 新建未上架 | 不能被购买。 |
| 方案 | 上架 | 可售 | 购买时保存快照。 |
| 方案 | 停售 | 下架 | 历史订单不受影响。 |
| 账户 | active | 有效期内且未作废 | 可享受权益。 |
| 账户 | expired | 超过有效期 | 不可继续使用会员权益。 |
| 账户 | voided | 人工作废 | 不得继续扣费。 |
| 订单 | 有效 | 支付确认 | 影响余额和财务。 |
| 订单 | 作废/退款 | 人工处理 | 必须有反向流水和财务影响。 |

## 9. 写入链路

| 动作 | 必须写入 | 必须校验 |
|---|---|---|
| 开卡 | 会员账户、会员订单、权益流水、账户事件、财务收款 | 订场用户存在、方案可售、金额合法。 |
| 续充 | 会员订单、权益流水、账户事件、财务收款 | 账户状态合法，方案快照保存。 |
| 会员订场扣费 | 订场历史、权益流水、账户余额、财务消耗 | 余额足够、折扣规则正确。 |
| 作废订单 | 订单状态、权益冲销、账户事件、财务冲销 | 已消费部分必须人工确认。 |
| 补发/调整权益 | 权益流水、账户事件 | 必须填写原因。 |

## 10. 页面影响范围

| 页面 | 使用内容 |
|---|---|
| 订场用户 | 会员入口、累计消费、余额、消费历史。 |
| 会员管理 | 会员账户、状态、余额、开卡续充。 |
| 会员购买记录 | 订单审计、方案快照、作废记录。 |
| 会员权益流水 | 充值、赠送、消耗、调整、过期审计。 |
| 财务中心 | 会员储值收入、消耗、退款、余额。 |
| 经营分析 | 会员收入、复充、留存。 |

## 11. 验收清单

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| MB-01 | 开卡 | 会员账户创建，订单存在，权益流水存在，财务收款出现。 |
| MB-02 | 续充 | 余额增加，订单保留方案快照，历史订单不变。 |
| MB-03 | 会员订场消费 | 余额减少，订场历史和权益流水可互相追溯。 |
| MB-04 | 作废订单 | 余额、流水、财务都有反向记录。 |
| MB-05 | 订场用户与会员管理 | 同一客户的姓名/手机号/账户一致。 |
| MB-06 | 财务中心 | 会员储值收入不把赠送金额算作实收。 |
