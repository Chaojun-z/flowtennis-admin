## 1. 模型目标

订场与场时模型保证“谁订了场、在哪个校区/场地/时间、付了多少钱、是否会员消费、是否来自约球”都能被统一追溯。

| 原则 | 说明 |
|---|---|
| 订场用户进入客户生命周期 | 订场用户不能被当作另一套自然人客户。 |
| 场时是经营事实 | 有效订场、取消、退款、会员扣费都要影响场地经营指标。 |
| 价格方案只负责报价 | 历史订场必须保存当时价格，不被后续价格方案修改覆盖。 |
| 会员消费必须扣会员权益 | 会员订场消费要能追溯会员账户和权益流水。 |
| 约球同步必须可隔离 | 约球费用同步到订场财务时必须标明来源。 |

## 2. 核心表和对象

| 对象 | 表/来源 | 定位 |
|---|---|---|
| 订场用户/历史 | `ft_courts` | 当前承载订场客户主档、订场历史、部分场地财务历史。 |
| 价格方案 | `ft_price_plans` | 场地/校区/时段报价规则。 |
| 会员账户 | `ft_membership_accounts` | 会员订场扣费账户。 |
| 会员权益流水 | `ft_membership_benefit_ledger` | 会员余额扣费和调整凭证。 |
| 财务流水 | `ft_financial_ledger`/财务统一层 | 场地收入、退款、会员消耗展示来源。 |
| 约球活动 | `match_posts` | 约球场地占用和活动来源。 |
| 约球费用 | `match_fee_records`、`match_fee_splits` | 约球费用分摊和支付状态。 |

## 3. 订场用户字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 订场用户 ID | 全局唯一。 |
| `name`/`displayName` | 姓名 | 展示为“姓名”，进入客户生命周期。 |
| `phone` | 手机号 | 与客户生命周期合并使用。 |
| `campus` | 归属校区 | 不等同于每次订场发生校区。 |
| `accountType` | 账户类型 | 普通订场用户、会员账户、约球财务同步账户等。 |
| `memberAccountId` | 会员账户 | 有会员时关联。 |
| `history` | 订场/消费历史 | 必须结构化保存每次场地业务。 |
| `status` | 用户状态 | active、hidden、voided 等。 |

## 4. 单次订场/消费历史字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `historyId` | 历史记录 ID | 必须唯一或能被稳定追溯。 |
| `courtId` | 订场用户 ID | 必填。 |
| `campus` | 业务发生校区 | 场地经营指标按此统计。 |
| `venue`/`courtName` | 场地 | 用于场地利用率和详情展示。 |
| `startTime`/`endTime` | 场时 | 用于经营场时、黄金时段、冲突校验。 |
| `durationHours` | 时长 | 必须可由时间计算或明确保存。 |
| `priceSnapshot` | 当时报价 | 保存价格方案结果，不被后续改价覆盖。 |
| `receivableAmount` | 应收金额 | 财务展示基础。 |
| `actualReceivedAmount` | 实收金额 | 收款流水基础。 |
| `paymentMethod` | 支付方式 | 统一字典。 |
| `memberDeductAmount` | 会员扣费金额 | 会员消费时必填。 |
| `sourceType` | 来源 | manual、member、match、import 等。 |
| `status` | 状态 | booked、completed、cancelled、refunded 等。 |

## 5. 价格方案字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 价格方案 ID | 全局唯一。 |
| `campus` | 适用校区 | 多校区必填。 |
| `courtName` | 适用场地 | 可为空表示校区通用。 |
| `timeBand` | 时段 | 工作日/周末/黄金/非黄金等。 |
| `startTime`/`endTime` | 适用时间段 | 用于试算。 |
| `price` | 单价 | 必须明确单位：每小时或每场。 |
| `status` | 状态 | 启用、停用。 |
| `effectiveFrom`/`effectiveTo` | 生效时间 | 历史价格不回写旧订单。 |

## 6. 约球同步边界

| 来源 | 同步到订场/财务的内容 | 禁止项 |
|---|---|---|
| `match_posts` | 活动时间、地点、状态、场地费 | 不直接覆盖普通订场用户资料。 |
| `match_fee_records` | 总场地费、AA 金额、结算状态 | 不把未结算费用当作已收款。 |
| `match_fee_splits` | 用户分摊、支付状态 | 不把取消/退款用户算入实收。 |
| 同步账户 | `match-court-finance` 或等价来源标识 | 必须能和普通订场消费区分。 |

## 7. 状态规则

| 对象 | 状态 | 进入条件 | 影响 |
|---|---|---|---|
| 订场 | booked | 已确认预约 | 占用场地，但未必入账。 |
| 订场 | completed | 已完成或确认消费 | 计入有效订场和收入。 |
| 订场 | cancelled | 已取消 | 不计有效订场，按规则处理费用。 |
| 订场 | refunded | 已退款 | 财务需有退款或冲销。 |
| 订场用户 | active | 正常 | 可继续新增消费。 |
| 订场用户 | hidden/voided | 隐藏或作废 | 历史保留，不能物理删除财务事实。 |

## 8. 写入链路

| 动作 | 必须写入 | 必须校验 |
|---|---|---|
| 新增订场用户 | `ft_courts` | 手机号去重、客户生命周期关联。 |
| 新增订场消费 | `ft_courts.history`、财务统一层所需事实 | 场地时间、价格、会员扣费、支付方式。 |
| 会员订场扣费 | 订场历史、会员权益流水、会员账户余额 | 余额足够，折扣正确。 |
| 取消/退款 | 订场状态、财务退款/冲销 | 不静默删除历史。 |
| 约球费用同步 | 约球费用事实、订场财务同步记录 | 来源标识、支付状态、结算状态。 |

## 10. 验收清单

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| CB-01 | 新增订场消费 | 订场用户累计次数和累计消费变化。 |
| CB-02 | 会员扣费订场 | 会员余额减少，权益流水和订场历史可追溯。 |
| CB-03 | 取消/退款 | 不计有效订场，财务有对应退款/冲销。 |
| CB-04 | 场地运转 | 有效订场、场时、收入与订场事实一致。 |
| CB-05 | 约球同步 | 约球费用不混入普通订场账户，来源可识别。 |
| CB-06 | 价格方案改价 | 历史订场价格快照不变。 |
