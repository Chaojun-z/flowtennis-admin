## 1. 模型目标

财务流水模型保证“收了多少钱、来自什么业务、什么时候入账、还有多少待履约、是否退款或冲销”可以被财务中心、经营分析和回溯工具一致读取。

| 原则 | 说明 |
|---|---|
| 收款和入账分开 | 收到钱不等于已经完成履约。 |
| 业务事实不被页面改写 | 页面只能读财务统一层，不临时扫描业务表重算核心金额。 |
| 每笔财务必须能追溯源单 | 课程购买、排课消课、订场消费、会员订单、约球费用都要有来源。 |
| 退款/作废必须有反向记录 | 不允许删除原流水来“修正”。 |
| 快照用于回溯 | 每日经营财务快照用于安全对账，不替代真实业务事实。 |

## 2. 财务事实来源

| 业务 | 来源对象 | 财务含义 |
|---|---|---|
| 课程课包 | `ft_purchases` | 课包收款、待履约收入。 |
| 课程消课 | `ft_schedule` + `ft_entitlement_ledger` | 课包已入账收入、待履约减少。 |
| 订场消费 | `ft_courts.history` | 场地收款/退款/会员扣费。 |
| 会员储值 | `ft_membership_orders` | 会员储值收入，赠送不算实收。 |
| 会员消耗 | `ft_membership_benefit_ledger` | 储值余额消耗、场地收入确认。 |
| 约球费用 | `match_fee_records` + `match_fee_splits` | 活动场地费分摊、支付、结算。 |
| 标准财务流水 | `ft_financial_ledger`/财务统一层 | 财务中心展示的标准化结果。 |

## 3. 标准财务流水字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 财务流水 ID | 全局唯一。 |
| `sourceType` | 来源类型 | purchase、schedule、court、membership_order、membership_ledger、match_fee、manual_adjustment 等。 |
| `sourceId` | 来源单 ID | 必须可跳回业务源。 |
| `customerId` | 客户生命周期 ID | 能关联则必须关联。 |
| `campus` | 财务校区 | 按业务发生校区或财务归属校区定义。 |
| `transactionTime` | 交易时间 | 收款/退款发生时间。 |
| `recognizedTime` | 入账时间 | 履约完成或确认收入时间。 |
| `transactionType` | 交易类型 | 收款、退款、冲销、调整。 |
| `incomeType` | 收入类型 | 课程、场地、会员储值、约球等。 |
| `businessType` | 业务类型 | 私教、小班、订场、会员等。 |
| `paymentMethod` | 支付方式 | 微信、支付宝、现金、储值扣款等统一字典。 |
| `receivableAmount` | 应收金额 | 源单应收。 |
| `actualReceivedAmount` | 实收金额 | 真实收款，退款为负或单独类型。 |
| `recognizedAmount` | 已入账金额 | 完成履约确认收入。 |
| `pendingAmount` | 待履约金额 | 收款但未履约部分。 |
| `diffAmount` | 差价 | 应收和实收差异。 |
| `diffReason` | 差价说明 | 有差价时必填。 |
| `status` | 状态 | normal、voided、refunded、reversed 等。 |
| `batchId`/`operationId` | 批次 | 导入、修数、回溯必填。 |

## 4. 收款流水规则

| 场景 | 记入收款 | 备注 |
|---|---|---|
| 购买课包 | 实收金额 | 进入课包收入，同时形成待履约。 |
| 订场现金收款 | 实收金额 | 完成订场可同时入账。 |
| 会员开卡/续充 | 实收储值金额 | 赠送金额不进入实收。 |
| 会员余额扣费 | 不作为新现金收款 | 作为储值消耗/入账处理。 |
| 约球用户支付 | 已支付分摊金额 | 未支付、取消、退款不计实收。 |
| 退款 | 负向收款或退款类型 | 必须保留原单和退款单关系。 |

## 5. 入账流水规则

| 场景 | 入账时点 | 金额规则 |
|---|---|---|
| 课包消课 | 课程完成/确认消课 | 按权益/课包单价确认。 |
| 订场完成 | 场地使用完成或收款确认 | 按场地收入确认。 |
| 会员储值消耗 | 会员余额用于订场/权益消费 | 从储值待履约转入已入账。 |
| 约球结算 | 活动费用结清 | 按已支付且有效分摊确认。 |
| 退款/作废 | 退款或作废确认 | 反向冲销已入账或待履约。 |

## 6. 快照和回溯

| 对象 | 规则 |
|---|---|
| 每日财务快照 | 记录当天财务总览、收入流水、入账流水关键数字。 |
| 批次号 | 任何导入、修数、补账必须有 `batchId` 或 `operationId`。 |
| 恢复点 | 恢复前必须保存恢复前状态。 |
| 页面核对 | 写入后必须核对写入表、页面接口、前端展示三段链路。 |

## 7. 禁止项

- 禁止财务页直接扫描业务表临时拼金额。
- 禁止删除原始流水来处理退款、作废或修数。
- 禁止把会员赠送金额计入实收收入。
- 禁止只看数据库写入就宣布页面财务生效。
- 禁止本地写入实例和线上读取实例不一致时继续生产修数。

## 8. 页面影响范围

| 页面 | 使用内容 |
|---|---|
| 财务总览 | 总收入、课程收入、场地收入、会员储值、已入账、待履约。 |
| 收款流水 | 交易时间、收入类型、支付方式、应收、实收、差价。 |
| 入账流水 | 已入账变化、待履约变化、源单追溯。 |
| 财务快照与回溯 | 快照、批次、恢复点、三段核对。 |
| 经营分析 | 引用财务统一层的收入和入账指标。 |
| 订场/会员/购买 | 显示与源业务相关的财务摘要，不改财务口径。 |

## 9. 验收清单

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| FL-01 | 新增课包购买 | 收款流水增加，待履约增加，源单可追溯。 |
| FL-02 | 完成消课 | 入账流水增加，待履约减少。 |
| FL-03 | 会员开卡 | 会员储值收入增加，赠送不计实收。 |
| FL-04 | 会员扣费订场 | 现金收款不重复增加，入账/消耗正确。 |
| FL-05 | 退款/作废 | 原流水保留，反向记录存在。 |
| FL-06 | 生产导入 | 写入表、线上 API、前端页面三段一致。 |
