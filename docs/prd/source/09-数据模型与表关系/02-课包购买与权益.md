## 1. 模型目标

课包购买与权益模型用于保证“卖课、生成课时、排课扣课、财务确认收入”四件事按同一条链路发生。

复刻系统时必须遵守：

| 规则 | 说明 |
|---|---|
| 购买记录是销售事实 | `ft_purchases` 记录学员购买了什么、多少钱、什么时候买、状态是什么。 |
| 权益账户是履约余额 | `ft_entitlements` 记录这笔购买产生多少课时、剩余多少、有效期和可用规则。 |
| 权益流水是余额凭证 | `ft_entitlement_ledger` 记录发放、消耗、调整、作废。 |
| 排课消课必须关联权益 | 排课完成或确认消课后，必须能追溯扣了哪个权益。 |
| 财务不由页面临时算 | 课包收入、已入账、待履约必须走财务统一层。 |

## 2. 核心表和对象

| 对象 | 表/来源 | 定位 |
|---|---|---|
| 课程产品 | `ft_products` | 历史兼容课程模板，当前作为课程基础资料保留。 |
| 售卖课包 | `ft_packages` | 当前新增课程售卖的主商品对象。 |
| 购买记录 | `ft_purchases` | 销售订单和购课事实。 |
| 权益账户 | `ft_entitlements` | 购买后生成的课时/权益余额。 |
| 权益流水 | `ft_entitlement_ledger` | 权益变化凭证。 |
| 排课 | `ft_schedule` | 消耗权益的业务履约对象。 |
| 学员 | `ft_students` | 购买人和上课人。 |
| 财务流水 | `ft_financial_ledger`/财务统一层 | 收款、入账、待履约结果。 |

## 3. 主关系

| 关系 | 规则 |
|---|---|
| 学员 -> 购买记录 | 一个学员可以有多笔购买。 |
| 课包 -> 购买记录 | 购买时保存课包快照，历史订单不被后续改价影响。 |
| 购买记录 -> 权益账户 | 一笔有效购买默认生成一个或多个权益账户。 |
| 权益账户 -> 权益流水 | 每次发放、消耗、调整、作废都要产生流水。 |
| 权益账户 -> 排课 | 排课扣课时必须能追溯到权益账户。 |
| 排课 -> 财务入账 | 课程完成/消课后触发已入账变化，具体金额走财务统一口径。 |

## 4. 购买记录字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 购买记录 ID | 全局唯一。 |
| `studentId` | 学员 ID | 必填，必须能回到客户生命周期。 |
| `packageId` | 售卖课包 ID | 推荐必填；历史数据可通过产品/名称兼容。 |
| `packageSnapshot` | 购买时课包快照 | 必须保存价格、课时、有效期、课程类型等关键售卖信息。 |
| `purchaseDate` | 购买日期 | 财务和转化统计按此进入销售事实。 |
| `receivableAmount` | 应收金额 | 不等于实收时必须有差价说明。 |
| `actualReceivedAmount` | 实收金额 | 财务收款口径来源之一。 |
| `paymentMethod` | 支付方式 | 使用统一支付方式字典。 |
| `status` | 状态 | 有效、作废、退款等状态必须受控。 |
| `sourceLeadId` | 来源线索 | 线索转化成交必须保留。 |

## 5. 权益账户字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 权益账户 ID | 全局唯一。 |
| `purchaseId` | 来源购买 | 必须可追溯。 |
| `studentId` | 所属学员 | 必须和购买记录一致。 |
| `totalLessons` | 总课时 | 来自购买快照或人工调整。 |
| `usedLessons` | 已用课时 | 由消耗流水汇总，不靠页面手填。 |
| `remainingLessons` | 剩余课时 | 总课时减已用/作废/过期；页面只展示结果。 |
| `validFrom`/`validTo` | 有效期 | 排课推荐和权益可用性必须使用。 |
| `courseType` | 课程类型 | 与课包快照一致。 |
| `campusScope` | 适用校区 | 空表示按当前兼容规则处理；新增必须明确。 |
| `coachScope` | 适用教练 | 用于排课推荐，不得越权扣。 |
| `status` | 权益状态 | active、used_up、expired、voided 等。 |

## 6. 权益流水字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `id` | 流水 ID | 全局唯一。 |
| `entitlementId` | 权益账户 | 必填。 |
| `purchaseId` | 来源购买 | 发放/作废时必须有。 |
| `scheduleId` | 来源排课 | 消耗时必须有。 |
| `action` | 动作 | grant、consume、adjust、void、expire、refund 等。 |
| `deltaLessons` | 变化课时 | 发放为正，消耗/作废为负。 |
| `deltaAmount` | 对应金额 | 财务口径使用时必须可解释。 |
| `operator` | 操作人 | 后台/系统/导入必须可追溯。 |
| `reason` | 原因 | 人工调整、作废、导入修复必须填写。 |
| `createdAt` | 发生时间 | 审计和回溯使用。 |

## 7. 状态规则

| 对象 | 状态 | 进入条件 | 禁止操作 |
|---|---|---|---|
| 购买记录 | 有效 | 购买创建且未作废/退款 | 不得直接删除。 |
| 购买记录 | 作废 | 管理员作废或导入纠错 | 必须同步权益和财务影响。 |
| 购买记录 | 退款 | 发生退款 | 必须生成财务退款/冲销记录。 |
| 权益账户 | active | 有剩余且未过期 | 可排课推荐。 |
| 权益账户 | used_up | 剩余为 0 | 不可继续扣课。 |
| 权益账户 | expired | 超过有效期 | 不可继续扣课，除非走人工延期。 |
| 权益账户 | voided | 来源购买作废或人工作废 | 不可继续排课，不参与余额。 |

## 8. 写入链路

| 动作 | 必须写入 | 必须校验 |
|---|---|---|
| 新增购买 | `ft_purchases`、`ft_entitlements`、`ft_entitlement_ledger(grant)` | 学员存在、课包可售、金额合法。 |
| 编辑购买 | 购买记录和必要的权益差异流水 | 已消耗权益不能被静默改小。 |
| 作废购买 | 购买状态、权益状态、权益流水、财务影响 | 已上课/已入账必须走冲销或人工确认。 |
| 排课消课 | `ft_schedule`、`ft_entitlement_ledger(consume)`、权益余额 | 权益可用、余额足够、时间/教练/校区符合规则。 |
| 手动调整权益 | 权益账户、权益流水 | 必须填原因和操作人。 |

## 9. 页面影响范围

| 页面 | 使用内容 |
|---|---|
| 正式学员 | 购买时间、课包、剩余课时、上课记录。 |
| 购买记录 | 新增/编辑/作废/导入/导出购买。 |
| 权益账户 | 余额、有效期、流水、人工调整。 |
| 排课管理 | 权益推荐、扣课、课程完成。 |
| 财务总览/流水 | 课包收入、已入账、待履约、退款。 |
| 经营分析 | 课程成交、复购、续费、教练人效。 |

## 10. 验收清单

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| PE-01 | 新增购买 | 购买记录出现，权益账户生成，权益流水有 grant。 |
| PE-02 | 排课消课 | 权益余额减少，流水有 consume，排课可追溯权益。 |
| PE-03 | 作废购买 | 购买、权益、流水、财务影响均可追溯。 |
| PE-04 | 历史订单改价 | 历史购买快照不被课包新价格覆盖。 |
| PE-05 | 正式学员列表 | 与购买记录/权益账户余额一致。 |
| PE-06 | 财务页 | 课包收款、入账、待履约与财务统一层一致。 |
