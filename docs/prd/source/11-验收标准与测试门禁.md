# 验收标准与测试门禁

> 版本：2026-07-02
> 状态：PRD 内置验收正本
> 定位：给接手 AI、开发、测试使用的可执行验收清单。本文回答“一个需求怎样才算完成、必须跑什么、必须提供什么证据、什么情况不能通过”。

## 0. 使用规则

1. 本文是 PRD 正本的一部分，不再依赖 PRD 外部散文档。
2. 每个需求必须先判断需求类型，再按本文选择测试和人工验收。
3. 自动化测试只代表测试覆盖的范围；没有覆盖的页面、字段、接口、导出、线上展示，必须人工验收。
4. 没有运行的测试不得写“已通过”。
5. 未验证的范围必须明确写“未验证”。
6. 任何命中 [10-异常场景与安全红线.md](10-异常场景与安全红线.md) 的需求，必须先满足 10 的证据要求。

## 1. 验收结论标准

| 结论 | 允许使用条件 |
|---|---|
| 通过 | PRD 要求已覆盖；相关自动化通过；人工验收完成；无 P0 / P1 未关闭风险 |
| 部分通过 | 核心流程可用，但有明确未覆盖范围；必须写清剩余风险 |
| 不通过 | 任一必测项失败、关键页面不一致、财务 / 权益 / 权限无法解释、线上未生效 |
| 阻塞 | 缺生产权限、缺环境变量、线上实例不一致、用户未批准高风险动作 |

禁止结论：

1. 禁止只写“已修复”“已测试”“没问题”。
2. 禁止把本地测试通过等同于线上生效。
3. 禁止把单页面正确说成全平台统一。
4. 禁止把未覆盖的高风险项省略不说。

## 2. PRD 文档验收

每个页面级 PRD 必须包含：

| 模块 | 必须内容 |
|---|---|
| 页面目标 | 这个页面解决什么业务问题 |
| 使用角色 | 哪些角色可见、可操作 |
| 业务对象 | 涉及哪些对象和表 |
| 入口 | 从哪里进入，属于哪个端 |
| 顶部卡片 | 字段、口径、取数范围 |
| 筛选项 | 字段、枚举、默认值、联动规则 |
| 列表字段 | 字段名、来源、格式、排序 |
| 详情 / 抽屉 | 字段、操作、状态、关联对象 |
| 操作规则 | 新增、编辑、作废、删除、导入、导出 |
| 权限规则 | 角色、校区、教练本人、功能权限 |
| 状态规则 | 状态枚举、流转、禁止状态 |
| 数据口径 | 关联 `05-全平台数据口径.md` |
| 字段规则 | 关联 `06-字段与状态规则.md` |
| 异常场景 | 命中 `10-异常场景与安全红线.md` 的处理 |
| 接口 / 数据来源 | 页面读写接口、统一读模型、导出来源 |
| 验收标准 | 自动化测试、人工检查、失败判定 |

文档不通过条件：

1. 只写页面介绍，没有字段和状态。
2. 只引用旧 `docs/xxx`，PRD 内没有正文。
3. 没写权限、异常、验收。
4. 数据口径和 05 冲突。
5. 字段和状态规则和 06 冲突。

## 3. 需求类型与必选验收

| 需求类型 | 必跑 / 必验 |
|---|---|
| 只改 PRD 文档 | 核对 PRD 正本规则；确认无旧散文档硬依赖；确认 05 / 06 / 10 / 11 对齐 |
| 改页面字段 / 列表 / 抽屉 / 导出 | 字段来源、格式、空值、导出列、跨页面同名字段一致 |
| 改客户生命周期 / 线索 / 学员 | 生命周期读模型、线索池、普通学员、正式学员、经营分析一致 |
| 改购买 / 权益 / 排课 / 消课 | 购买、权益、权益流水、排课、反馈、财务入账链路一致 |
| 改订场 / 会员 | 订场用户、会员账户、会员订单、权益流水、财务、经营分析一致 |
| 改财务 | 财务总览、收款流水、入账流水、财务快照 / 基线、财务门禁 |
| 改权限 / 账号 / 校区 | 登录、账号状态、数据范围、写接口、页面接口、越权反例 |
| 改教练端 Web / 小程序 | 教练本人数据、日程、课程详情、反馈、账号绑定 |
| 改约球 | 活动、报名、取消、到场、费用、权限、日志 |
| 改生产导入 / 修数 | 按 10 的生产数据红线，必须有 diag、dry-run、回滚、线上三段核对 |
| 改技术架构 / 发布配置 | `npm run guard:release`；Vercel / API / 环境变量 / 生产安全门禁 |

## 4. 当前已存在测试命令

以下命令来自当前 `package.json`，接手方可以直接使用。

| 命令 | 用途 | 何时必须跑 |
|---|---|---|
| `npm test` | 当前主回归测试集合，覆盖业务字典、标准组件、排课、线索、客户生命周期、财务、经营分析、页面数据、架构拆分、生产安全、约球等 | 常规代码改动、跨模块改动 |
| `npm run guard:release` | 发布级门禁，包含 `npm test`、依赖安全、财务、页面数据、权限、性能、生产读写保护等额外检查 | 准备发布、合入主分支前、影响核心链路时 |
| `npm run guard:finance` | 财务回归门禁 | 任何影响财务金额、财务页、课包、会员、订场、权益的变更 |
| `npm run guard:deps-security` | 依赖安全门禁 | 改依赖、发布前 |
| `npm run snapshot:finance` | 创建财务每日快照 | 需要快照或回溯依据时 |
| `npm run finance:latest-snapshot` | 查看最新财务快照 | 财务核对、回溯前 |
| `npm run validate:finance-operation` | 财务操作校验 | 财务修数、补账、回滚前后 |
| `npm run verify:finance-page` | 财务页面授权验证脚本 | 需要验证财务页面读链路时 |
| `npm run test:match-real` | 约球真实链路测试 | 需要验证真实约球链路时 |

说明：

1. `npm test` 很长，不能用“跑了几个相关测试”冒充全量。
2. `guard:release` 比 `npm test` 更严格，发布前优先使用。
3. 文档修改不需要跑业务测试，但必须人工核对文档自包含和 PRD 正本规则。

## 7. 上线前最低门禁

### 7.1 普通功能改动

必须满足：

1. 相关页面 PRD 已更新或确认无需更新。
2. 相关字段在 05 / 06 有定义。
3. 相关测试已运行。
4. 人工验收覆盖列表、详情、操作、空状态、错误状态。

### 7.2 高风险功能改动

高风险包括财务、权益、会员、订场、生产导入、权限、校区、教练、约球财务。

必须满足：

1. 满足普通功能改动所有门禁。
2. 满足 10 的对应红线证据。
3. 运行 `npm run guard:finance` 或说明不涉及财务。
4. 如准备发布，运行 `npm run guard:release`。
5. 提供回滚或恢复方案。

### 7.3 生产数据写入

必须满足：

1. 线上 `/api/diag` 实例核对。
2. 本地写入实例核对。
3. dry-run。
4. 写入批次号或操作日志。
5. 写入表核对。
6. 线上 API 核对。
7. 前端展示核对。
8. 财务三表核对，若影响财务。

## 8. 失败判定

出现以下任一情况，验收必须判定不通过：

1. 同一指标跨页面不一致。
2. 页面展示值和统一读模型不一致。
3. 财务总览、收款流水、入账流水无法对上。
4. 购买、权益、排课、权益流水无法互相追溯。
5. 会员账户、会员订单、权益流水、订场历史无法互相追溯。
6. 校区管理员可读写非授权校区数据。
7. 教练可见或可操作其他教练课程。
8. 生产写入后线上页面未生效。
9. 测试失败但未修复。
10. 未验证却声称完成。

## 9. 接手 AI 执行顺序

接手 AI 做任何需求，按以下顺序执行：

1. 读 `00-项目总览.md`，确认 PRD 正本规则。
2. 读对应页面 PRD。
3. 读 `05-全平台数据口径.md`，确认指标。
4. 读 `06-字段与状态规则.md`，确认字段和状态。
5. 读 `10-异常场景与安全红线.md`，判断风险等级。
6. 按本文选择测试和人工验收。
7. 执行修改。
8. 运行测试。
9. 做人工验收。
10. 输出验收结论和未覆盖范围。

## 10. 不允许省略的最终说明

最终交付说明必须包含：

1. 改了什么。
2. 覆盖哪些页面 / 字段 / 口径 / 业务对象。
3. 跑了哪些测试，结果是什么。
4. 做了哪些人工验收。
5. 哪些没有覆盖。
6. 是否影响财务。
7. 是否影响生产数据。
8. 是否影响权限。
9. 是否需要提交、推送、发布。

如果没有任何测试或人工验收，必须明确写“未验证”，不得使用“已完成”作为唯一结论。

## 11. 核心列表性能防复发测试门禁

本节适用于排课管理、订场用户、会员管理、线索池、历史学员、在期学员等核心列表。凡用户要求或历史承诺为秒级加载的列表，都按本节执行。

### 11.1 必须有的反向测试

核心列表性能改造必须有反向测试。以下任一测试缺失，不能说“彻底解决”：

1. 慢表陷阱测试：首屏路由只要调用事实大表、权益流水大表、购买大表、反馈大表或旧慢读模型，测试必须失败。
2. 导入隔离测试：首屏模块只要直接导入慢表扫描函数、全量事实读取函数或完整事实校准函数，测试必须失败。
3. 未初始化测试：读模型为空、未初始化、`building`、`failed` 时，首屏不能静默回扫慢表。
4. 发布状态测试：只有 `published` 可被首屏读取。
5. `checksum` 错误拒绝测试：`checksum` 缺失或不一致时，页面不能展示该批数据。
6. 禁止整页强刷测试：保存、新建、编辑、取消、删除后，不能调用整页大包强制刷新。
7. 性能预算测试：固定大样本下，首屏、筛选、搜索、翻页必须小于承诺阈值；承诺 1 秒内的页面按 1 秒执行。

### 11.2 必须进入脚本门禁

1. 反向测试必须进入 `npm test` 或 `npm run guard:release`；只写测试文件但不接入脚本，不算完成。
2. 发布前如果跳过这些测试，验收结论只能写“不通过”或“未验证”，不能写“通过”。
3. 删除、跳过、降低阈值、改成只测正常路径，视为破坏性能治理。

### 11.3 数据正确性门禁

核心列表读模型测试必须同时证明：

1. 页面只读统一后端读模型最终输出。
2. 页面不自己拼核心字段、不补核心口径、不只读局部数据。
