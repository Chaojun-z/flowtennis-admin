## 1. 文档目标

这份文档回答 4 个问题：

1. FlowTennis 到底用了哪些平台。
2. 每个平台负责什么。
3. 管理后台、教练端、小程序、外部通知分别怎么登录。
4. 从开发到上线的流程怎么走。

## 2. 当前平台清单

| 平台 / 服务 | 当前用途 | 关键位置 | 备注 |
|---|---|---|---|
| GitHub | 代码托管、主分支管理 | `origin/main` | 推送后触发 Vercel 部署 |
| Vercel | 管理后台 Web、Node API、Cron | `vercel.json`、`api/index.js` | `/api/*` rewrite 到 `api/index` |

## 3. 当前技术架构

### 3.1 管理后台 Web

- 技术形态：原生 HTML / CSS / JavaScript 单页应用。
- 入口：`public/index.html`。
- 前端脚本：`public/assets/scripts/`。
- 前端请求：通过 `public/assets/scripts/core/api.js` 请求 `/api/...`。
- 登录态：浏览器 `localStorage` 保存 `ft_token` 和 `ft_user`。

### 3.2 后端 API

- 技术形态：Node.js + Express 风格路由。
- 线上载体：Vercel Serverless Function。
- 入口：`api/index.js`。
- 内部模块：`server/`。
- Vercel Hobby 限制：`api/` 目录必须保持只有 `index.js`，不能新增多个 Serverless Function。

### 3.3 数据层

- 主业务数据：阿里云 TableStore。
- 生产实例：`flowtennis-ue`。
- staging 实例：`flow-staging`。
- 历史旧实例：`flowtennis`，禁止作为线上导入、线上核对或生产修数目标。
- 约球子系统：PostgreSQL。

### 3.4 小程序与外部触点

- 教练小程序：`wechat-miniprogram/`。
- 约球小程序：不在本仓库主目录内，本仓库只定义管理后台和后端边界。
- 服务号提醒：通过服务号模板消息和代理服务发送。
- 飞书：用于日报、升级日志、通知。

## 4. 路由与部署方式

`vercel.json` 当前规则：

```json
{
  "rewrites": [
    { "source": "/api/(.*)", "destination": "/api" },
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

含义：

1. 所有 `/api/*` 请求进入同一个 `api/index.js`。
2. 其他路径都返回 `index.html`，由前端单页应用处理。
3. 后续后端拆分只能拆到 `server/`，不能新增 `api/*.js`。

## 5. 登录方案

### 5.1 管理后台登录

| 项 | 当前方案 |
|---|---|
| 登录入口 | 管理后台登录页 |
| 登录接口 | `POST /auth/login` |
| 账号来源 | `ft_users` / `adminUsers` |
| 凭证 | 账号 + 密码 |
| 密码存储 | 后端校验密码哈希 |
| Token | JWT |
| 有效期 | 7 天 |
| 前端保存 | `localStorage.ft_token`、`localStorage.ft_user` |
| 请求鉴权 | `Authorization: Bearer <token>` |

规则：

1. 账号密码不能为空。
2. 登录失败有频控。
3. 停用账号不能登录。
4. 登录后按角色进入管理员视角或教练视角。

### 5.2 教练端 Web 登录

教练端 Web 复用管理后台账号体系：

1. 教练使用账号密码登录。
2. 后端返回 JWT。
3. 前端根据 `role`、`coachName` 等用户信息进入教练视角。
4. 教练只能看本人课程、学员、班次和反馈。

注意：

- 登录账号不等于教练业务身份。
- 账号必须和教练资料绑定，才能稳定判断“本人课程”。

### 5.3 教练小程序登录

教练小程序当前有两种登录方式：

| 方式 | 说明 |
|---|---|
| 账号密码登录 | 调用 `/auth/login`，成功后保存 `ft_mini_token` 和 `ft_mini_user` |
| 微信快捷登录 | 调用 `wx.login` 获取 code，再请求 `/auth/wechat-login` |

绑定流程：

1. 教练第一次可使用账号密码登录。
2. 登录后调用 `/auth/wechat-bind`，把当前微信 openid 绑定到平台账号。
3. 后续可用微信快捷登录。
4. 如果微信未绑定教练账号，接口返回“微信未绑定教练账号，请先使用账号密码登录完成绑定”。

小程序请求：

- API 地址：`wechat-miniprogram/miniprogram/config.js` 的 `API_BASE_URL`。
- 当前指向：`https://www.flowtennis.cn/api`。
- 请求头带 `Authorization: Bearer <ft_mini_token>`。
- 请求头带客户端标识：`X-FlowTennis-Client: coach-mini`。

### 5.4 约球小程序登录

约球小程序使用独立用户登录：

| 项 | 当前方案 |
|---|---|
| 登录接口 | `POST /auth/wechat-mini-login` |
| 登录凭证 | 微信 `wx.login` code |
| 用户标识 | openid / unionid |
| 用户表 | `match_users` |
| Token | `buildMatchUserToken(matchUser)` |
| 数据库 | PostgreSQL |

规则：

1. 如果 openid 已存在，读取原用户。
2. 如果 openid 不存在，创建新的 `match_users`。
3. 约球用户和后台账号不是同一套身份。
4. 报名、取消报名、我的约球等操作按约球用户 token 鉴权。

### 5.5 学员服务号提醒绑定

服务号提醒绑定不是后台账号登录，而是学员绑定提醒身份：

1. 后台或教练生成提醒绑定链接。
2. 学员打开 `/student-reminder-bind?t=...`。
3. 页面通过服务号 OAuth 获取微信 code。
4. 后端完成绑定。
5. 绑定后通过服务号发送上课提醒。

注意：

- 这条链路只用于上课提醒绑定。
- 不等于管理后台账号。
- 不等于教练小程序登录。
- 不等于约球小程序登录。

## 6. 登录需求是否清楚

当前“已有实现”比较清楚：

1. 管理后台：账号密码 + JWT。
2. 教练端 Web：复用账号密码 + JWT，根据教练身份展示本人数据。
3. 教练小程序：账号密码登录 + 微信绑定 + 微信快捷登录。
4. 约球小程序：微信 code 登录，独立约球用户。
5. 学员服务号提醒：OAuth 绑定提醒身份。

当前“仍需产品确认”的点：

1. 管理后台是否需要短信验证码、微信扫码登录或 SSO，目前没有明确需求。
2. 教练端 Web 和教练小程序是否必须强制绑定微信，目前是支持绑定，不等于所有账号都已完成绑定。
3. 约球小程序用户是否要和主系统客户生命周期自动合并，目前边界未完全定义。
4. 学员服务号提醒绑定后，是否要反向写入统一客户身份模型，需要单独确认。
5. 多平台账号注销、解绑微信、换手机号、员工离职后的账号处理流程，需要补充更细规则。

结论：

- 当前登录实现链路是清楚的。
- 跨平台身份统一需求还没有完全清楚，尤其是“约球用户 / 学员 / 订场用户 / 会员 / 微信身份”的合并关系，后续应单独进入需求池和数据模型评审。

## 7. 上线流程

### 7.1 管理后台和后端 API 上线

1. 在正式开发目录 `/Users/shaobaolu/Desktop/FlowTennis/flowtennis-mgmt-main` 修改代码。
2. 确认基于 `origin/main`。
3. 按影响范围运行测试。
4. 涉及财务、课包、权益、订场、会员时，必须运行财务门禁。
5. 提交并推送到 GitHub。
6. Vercel 自动部署。
7. 部署后核对线上页面和线上 API。

高风险上线必须额外核对：

- `/api/diag` 真实 `TS_INSTANCE` 是否为 `flowtennis-ue`。
- 财务总览、收款流水、入账流水是否正确。
- 页面接口和前端展示是否生效。

### 7.2 教练小程序上线

1. 用微信开发者工具打开 `wechat-miniprogram/`。
2. 配置真实 AppID。
3. 确认 `API_BASE_URL` 指向正确环境。
4. 微信后台补齐合法 request 域名、消息模板和隐私保护指引。
5. 在微信开发者工具中预览、上传。
6. 走微信小程序审核和发布流程。
7. 发布后用真实教练账号验证账号密码登录、微信绑定、微信快捷登录、排课日程和课程详情。

### 7.3 约球小程序上线

当前约球小程序不在本仓库主目录内，本 PRD 只定义后端和管理后台边界。

上线必须确认：

1. 约球小程序实际代码仓库和发布平台。
2. 约球 API 地址。
3. PostgreSQL 生产连接。
4. 微信登录 AppID / Secret。
5. 约球财务同步到订场财务的边界。

### 7.4 服务号提醒上线

1. 服务号模板消息配置完成。
2. 阿里云固定 IP 代理可用。
3. Vercel 或本地配置 `WECHAT_OFFICIAL_ACCOUNT_PROXY_URL`。
4. 敏感密钥只放环境变量，不写代码或文档明文。
5. 发送测试通知前先确认代理健康检查成功。

### 7.5 飞书日报 / 飞书通知上线

1. 配置飞书机器人或应用凭证。
2. 确认日报数据来源。
3. 确认发送时间和接收群。
4. 先用测试群验证格式和数字。
5. 上线后持续核对日报数字和管理后台一致。

## 8. 环境变量清单

敏感信息只允许配置在 `.env`、Vercel 环境变量、微信 / 飞书 / 阿里云对应平台后台，禁止写入代码和文档明文。

| 变量 | 用途 |
|---|---|
| `TS_ENDPOINT` | TableStore 地址 |
| `TS_INSTANCE` | TableStore 实例，生产为 `flowtennis-ue` |
| `ALIBABA_CLOUD_ACCESS_KEY_ID` | 阿里云访问 Key |
| `ALIBABA_CLOUD_ACCESS_KEY_SECRET` | 阿里云访问 Secret |
| `JWT_SECRET` | 管理后台 / 教练端 JWT 签名 |
| `DIAG_TOKEN` | 诊断接口访问令牌 |
| `ALLOWED_ORIGINS` | API 允许访问的前端域名 |
| `MATCH_DATABASE_URL` / `DATABASE_URL` | 约球 PostgreSQL 连接 |
| `MATCH_MINIPROGRAM_SECRET` | 约球小程序微信登录 |
| `WECHAT_OFFICIAL_ACCOUNT_PROXY_URL` | 服务号固定 IP 代理地址 |
| `WECHAT_OFFICIAL_ACCOUNT_PROXY_SECRET` | 服务号代理密钥 |

## 9. 验收标准

1. 能说清楚每个平台负责什么。
2. 能说清楚每个端怎么登录。
3. 能说清楚管理后台、教练小程序、约球小程序、服务号、飞书分别怎么上线。
4. 不把教练小程序和约球小程序混淆。
5. 不把后台账号、教练身份、约球用户、学员服务号绑定身份混成一套。
6. 所有敏感密钥只出现在安全配置里，不进入代码和 PRD 明文。



## 10. PRD 先行门禁

任何涉及技术平台、登录、上线、环境变量、生产数据、外部通知的需求，开发前必须先更新本文件或对应页面 PRD。

| 场景 | 必须更新 |
|---|---|
| 新增平台或服务 | 平台清单、用途、环境变量、上线流程 |
| 修改登录方式 | 登录方案、账号来源、token、绑定/解绑规则、权限范围 |
| 修改部署方式 | 路由、构建、部署、回滚、验证步骤 |
| 修改生产数据写入 | 实例校验、批次、快照、线上 API、前端展示核对 |
| 修改微信/飞书/服务号 | 平台配置、密钥变量、发送规则、失败处理 |

验收：执行前必须通过 `15-PRD完整性检查清单.md` 的上线前检查。
