# FlowTennis PRD 文档库

> 版本：2026-07-01
> 状态：PRD 正本文档库。

## 使用方式

- `source/` 是 Markdown 正本。
- `site/` 是后续 HTML 分享版输出目录。
- 后续新增、修改、排查需求，优先按 `source/` 目录归档。
- 当前页面级 PRD 在 `source/08-具体需求/`，共覆盖 44 个页面 / 触点，并补充客户与线索标签规则 PRD。

## 正本规则

- `docs/prd/source/` 是对外交付和内部迭代的 PRD 正本。
- 旧 `docs/` 下的零散文档只作为历史迁移来源，不再作为复刻系统的必读依赖。
- 后续新增口径、字段、状态、页面需求、验收规则，必须先更新 PRD 目录内对应文件。
- 如果 PRD 外部旧文档和 PRD 冲突，以 PRD 为准。
- 交接给外部团队时，目标是只交付 PRD 目录也能 1:1 复刻系统。

## 查找规则

- 页面显示错了：查 `source/08-具体需求/`。
- 页面字段、按钮、状态、接口、验收不清：先查 `source/04-功能清单.md`，再进入对应页面 PRD。
- 字段含义不清：查 `source/06-字段与状态规则.md`。
- 数字口径不一致：查 `source/05-全平台数据口径.md`。
- 学员活跃、历史学员、在期学员、课包状态、付费方式、历史课时标签不清：查 `source/08-具体需求/01-管理后台/01-客户与线索/04-学员活跃与标签体系.md`。
- 流程不确定：查 `source/03-核心业务流程.md`。
- 技术架构、登录、上线流程不清：查 `source/07-技术架构与上线方案.md`。
- 表关系不清：查 `source/09-数据模型与表关系/`。
- 上线优先级不清：查 `source/12-Roadmap版本规划.md`。
- 只是一个想法或待排期：放 `source/13-需求池.md`。
- 为什么当时这么定：查 `source/14-变更记录与决策记录.md`。


## 更新门禁

- 后续任何需求、修复、字段、口径、页面、上线流程变更，必须先更新 `source/` 下对应 PRD。
- 更新完成后，用 `source/15-PRD完整性检查清单.md` 检查是否可以交给研发、测试或 AI 执行。
- 如果检查不通过，不能直接进入开发。
