## 一、阅读说明

为了避免文档过大，这份数据字典只覆盖：

- 真正驱动业务的核心表
- 会跨页面联动的关键字段
- 新人最容易搞混的字段

不重点展开的内容：

- 纯 UI 展示字段
- 临时搜索条件
- 非核心备注类字段的所有细枝末节

字段来源说明统一用这 4 类：

- `手填`：前端由人录入
- `自动生成`：后端创建时自动写入
- `快照复制`：从上游对象复制过来，保存当时状态
- `系统计算`：根据规则、流水或状态推导出来

## 二、全平台统一读模型字段

以下字段不是某个页面自己解释的字段，而是全平台统一口径。客户中心、教学中心、产品与定价、财务中心、经营分析、基础设置中只要涉及同一业务含义，都必须按这里的定义读取，不允许页面各自重写一套规则。

全平台指标计算口径以 [FlowTennis 全平台数据口径总表](/Users/shaobaolu/Desktop/FlowTennis/flowtennis-mgmt-main/docs/business-rules/FlowTennis全平台数据口径总表.md) 为准。本数据字典只解释核心表和字段，不替代指标公式。

### 1. 客户生命周期字段

权威读模型：

- `server/read-models/customer-lifecycle.js`
- 教学学员标签、最近上课、累计上课、课包状态等字段由 `server/read-models/platform-metrics.js` 的 `teachingStudentViews` 统一输出。
- `ft_student_teaching_summary` 这类摘要表只能作为轻量缓存；读取前必须做内容矛盾自检，不能只靠版本号判断可信。

前端统一访问器：

- `customerLifecycleRowsForRecord`
- `customerLifecycleByStudentId`
- `customerLifecycleByCourtId`
- `customerLifecycleByMembershipAccountId`
- `customerLifecycleSource`
- `customerLifecycleCampus`
- `customerLifecycleOwner`
- `customerLifecycleStudentStage`
- `customerLifecycleCourtStage`
- `customerLifecycleMembershipStatus`

| `source` | 标准来源 | 系统计算 | 是 | 筛选、渠道占比、转化分析 |
| `campus` | 标准客户归属校区 | 系统计算 | 是 | 页面筛选、排课默认、财务展示兜底 |
| `owner` | 标准客户负责人 | 系统计算 | 是 | 学员/线索归属、排课默认、转化分析 |
| `leadStage` | 线索阶段：新线索、跟进中、已约体验、已体验待成交、已成交、已流失 | 手填/系统计算 | 是 | 线索池、跟进、成交分析 |
| `dealType` | 成交类型/成交构成：课程、订场、订场会员、陪打；兼容历史值：会员、课程+订场、课程+会员、订场+会员、课程+订场+会员；标准展示统一为课程、订场、订场会员、陪打及组合，如订场+陪打、课程+订场+订场会员；成交类型包含课程/陪打时补齐学员身份，包含订场时补齐订场用户身份，包含订场会员时补齐会员账户身份 | 系统计算/兼容历史成交字段 | 是 | 线索池、成交统计、客户链路 |
| `customerType` | 类型：成人、青少年 | 手填/导入标准化 | 是 | 线索池、客户分层、经营分析 |
| `demandProduct` | 需求产品：私教课、小班课、专项课、订场、会员、陪打、约球、穿线、合作、其他 | 手填/导入标准化 | 是 | 线索池、需求分析、产品分析 |

硬规则：

1. 历史学员和在期学员不是两张客户事实表，是客户生命周期读模型的两个视图：历史学员看有效排课或上课事实，在期学员看课包余额或近 90 天正式课活跃。
2. 订场用户和会员管理不是两套客户解释，是 `courtStage` 和 `membershipStatus` 的两个视图。
3. 历史 `leadId/fromLeadId` 只能作为兼容别名，新链路必须写 `sourceLeadId`。
4. 页面如需展示或筛选来源、校区、负责人、学员阶段、订场阶段、会员状态，必须走统一访问器或后端统一读模型。
5. 线索阶段只回答“现在推进到哪里”，成交类型只回答“最后成交了什么”，不得再用人工 `是否转化` 字段作为主口径。
6. 历史 `consultType` 只能兼容映射到 `demandProduct`；历史 `conversionType` 只能兼容映射到 `dealType`；历史 `enrollAtRaw/formalSignupAt` 页面展示统一叫“成交时间”。
7. `lostReason` 页面展示统一叫“流失原因”；`formalCoach` 页面展示统一叫“成交教练”。
8. 学员活跃与标签字段必须按 `docs/prd/source/08-具体需求/01-管理后台/01-客户与线索/04-学员活跃与标签体系.md` 和全平台数据口径执行；页面不得自行拆分资源置换、赠课或 0 元正式课标签。
9. 线索成交自动补齐会员账户时，只补账户身份，不自动生成会员订单、储值收入、权益流水或财务流水。
10. `activityStatusLabel`、`detailRecentLessonDate`、`completedLessons`、`detailLessonRecordRows` 必须由教学统一读模型同时输出；不得出现最近上课或累计上课有值但活跃状态仍为 `从未正式上课`。
11. 教学摘要缓存如果出现未来日期、累计上课与明细矛盾、活跃状态与上课事实矛盾，必须回源读取 `schedule` / `entitlement_ledger` 等事实表。

## 4. `ft_purchases` 购买记录表

## 六、最重要的字段关系备忘

### 1. 真正的“源头字段”

- `students.id`
- `products.id`
- `packages.id`
- `purchases.id`
- `classes.id`
- `schedule.id`
- `courts.id`
- `membership_plans.id`
- `membership_orders.id`

### 2. 最重要的引用链

#### 教学链

- `packages.productId -> products.id`
- `purchases.studentId -> students.id`
- `purchases.packageId -> packages.id`
- `entitlements.purchaseId -> purchases.id`
- `classes.productId -> products.id`
- `plans.classId -> classes.id`
- `plans.studentId -> students.id`
- `schedule.classId -> classes.id`
- `schedule.entitlementId -> entitlements.id`
- `feedbacks.scheduleId -> schedule.id`

#### 会员链

- `membership_accounts.courtId -> courts.id`
- `membership_orders.membershipAccountId -> membership_accounts.id`
- `membership_orders.membershipPlanId -> membership_plans.id`
- `membership_benefit_ledger.membershipOrderRef -> membership_orders.id`
- `membership_benefit_ledger.membershipAccountId -> membership_accounts.id`
- `membership_account_events.membershipAccountId -> membership_accounts.id`

### 3. 最重要的“自动字段”

- `classNo`
- `className`
- `usedLessons`
- `remainingLessons`
- `validUntil`
- `status` 的一部分
- `createdAt / updatedAt`
- 会员账户周期字段
- 会员订单权益快照字段

## 七、给新人的一句话版本

如果你只记一句话：

`这个系统里，课时余额看 entitlement，扣课证据看 entitlement_ledger；会员当前状态看 membership_account，会员权益变化证据看 membership_benefit_ledger。`

如果你再多记一句：

`购买记录和会员订单都是“发生过一次交易”；权益账户和会员账户都是“当前剩下什么状态”。`
