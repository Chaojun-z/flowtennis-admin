## 2. Vercel Preview / staging 变量清单

### 2.1 必须独立配置

这些变量如果继续和生产混用，`staging` 仍然会打到生产链路。

| 变量 | 用途 | 当前仓库结论 |
| --- | --- | --- |
| `APP_ENV=staging` | 强制 Preview 按 staging 运行 | 已有规则，控制台需落实 |
| `DATA_ENV=staging` | 显式标记数据环境 | 已有模板，控制台需落实 |
| `TS_ENDPOINT` | staging TableStore 地址 | 缺真实值 |
| `TS_INSTANCE` | staging TableStore 实例名 | 缺真实值 |
| `ALIBABA_CLOUD_ACCESS_KEY_ID` | staging TableStore AK | 缺真实值 |
| `ALIBABA_CLOUD_ACCESS_KEY_SECRET` | staging TableStore SK | 缺真实值 |
| `JWT_SECRET` | staging 登录签名密钥 | 仓库支持独立，控制台需确认 |
| `MATCH_DATABASE_URL` | staging Postgres 连接串 | 仓库支持独立，控制台需确认 |
| `MATCH_DATABASE_SSL` | staging Postgres SSL | 仓库支持独立，控制台需确认 |

### 2.2 可以先沿用，但必须记录是否共用生产

这些不是当前 staging 挂起的主阻塞，但负责人必须知道是否还在共用生产。

| 变量 | 建议 |
| --- | --- |
| `WECHAT_MINIPROGRAM_APPID` | 如果 staging 仍用同一个正式小程序，可暂时共用；后续要标注“共用正式 AppID” |
| `WECHAT_MINIPROGRAM_SECRET` | 同上 |
| `MATCH_MINIPROGRAM_APPID` | 如果约球小程序未拆独立 staging，可暂时共用 |
| `MATCH_MINIPROGRAM_SECRET` | 同上 |
| `WECHAT_SCHEDULE_TEMPLATE_ID` | 如仍发正式模板消息，需明确记录风险 |
| `WECHAT_COURSE_REMINDER_TEMPLATE_ID` | 同上 |
| `MATCH_WECHAT_TEMPLATE_ID` | 同上 |
| `CRON_SECRET` | Preview 若启用定时入口，建议独立配置 |

### 2.3 非目标项

以下变量默认保持 `false`，这次不做功能接线：

- `ENABLE_DEFAULT_USER_BOOTSTRAP`
- `ENABLE_TABLE_BOOTSTRAP`
- `ENABLE_RUNTIME_TABLE_ENSURE`
- `ENABLE_DEFAULT_PRICE_PLAN_BOOTSTRAP`
- `ENABLE_MABAO_FINANCE_SEED_BOOTSTRAP`
- `ENABLE_IMPORTED_LEDGER_AUTO_REPAIR`
- `ALLOW_PRODUCTION_BOOTSTRAP_WRITES`
- `ALLOW_PRODUCTION_DATA_FOR_NON_PROD`

## 3. 首轮 staging 快照执行顺序

### 3.1 现在就能做

1. 准备 manifest  
   使用 [staging-data/manifests/staging-refresh.template.json](/Users/shaobaolu/Desktop/FlowTennis/flowtennis-mgmt-main/staging-data/manifests/staging-refresh.template.json)
2. 生成导出批次目录  
   `npm run staging-data:export`
3. 脱敏原始快照  
   `npm run staging-data:sanitize -- --input=<raw-json>`
4. 生成 staging 导入包和导入报告  
   `npm run staging-data:import -- --input=<sanitized-json>`

### 3.2 首轮正式闭环时再做

1. 把 4 个 TableStore staging 值填进 Vercel Preview / staging
2. 用真实 staging TableStore 凭据完成远端写入
3. 用 staging URL 更新小程序 `env.staging.js`
4. 去微信后台补合法 request 域名
5. 跑首轮联调验收

### 3.3 当前唯一核心外部阻塞

- 阿里云 staging TableStore 子账号与 4 个凭据值：
  - `TS_ENDPOINT`
  - `TS_INSTANCE`
  - `ALIBABA_CLOUD_ACCESS_KEY_ID`
  - `ALIBABA_CLOUD_ACCESS_KEY_SECRET`

## 5. Preview URL 与微信后台

### 5.1 Preview URL 一般长什么样

Vercel Preview 通常会给一条 `*.vercel.app` 的预览地址，常见形态是：

- `https://<project-name>-git-<branch-name>-<scope>.vercel.app`
- 或一条自动生成的 `https://<deployment-id>.vercel.app`

### 5.2 去哪里拿真实 Preview URL

后续不要猜地址，直接去：

1. Vercel 项目控制台
2. `Deployments`
3. 打开最新一次 Preview 部署
4. 复制页面显示的 `Visit` / `Domains` 地址

这条真实 URL 才能拿去填小程序 `env.staging.js` 和微信后台。

### 5.3 微信后台后续要补什么

至少补这 4 项：

1. 合法 `request` 域名
2. 如有图片/文件上传下载，还要补对应合法域名
3. 消息模板 / 订阅消息配置
4. 隐私保护指引相关配置
