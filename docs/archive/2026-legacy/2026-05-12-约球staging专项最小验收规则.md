# FlowTennis 约球 staging 专项最小验收规则

> 日期：2026-05-12  
> 线程：105 第二批约球 staging 专项验收最小补口  
> 目标：把约球专项验收从“有测试/有入口”推进到“有最小 staging 验收补口、可执行、可复用”的状态。  
> 边界：本规则只收口约球 staging 最小专项检查，不改财务桥主体，不做小程序 staging 真接线，不把真链路测试并入默认 gate。

---

## 1. 当前专项入口

命令：

- `npm run staging:ensure-match-minimal:check`

用途：

- 只做约球 staging 最小只读检查
- 输出 JSON 报表
- 默认不写入任何数据

当前口径：

- **不接入 `gate:staging`**
- 当前阶段明文口径：不接入 gate:staging
- 作为约球专项 staging 验收的独立补口入口保留

---

## 2. 本入口当前最小检查内容

### 2.1 约球后台读链前提

检查：

- staging `ft_users` 表是否存在
- `admin` 账号是否存在
- `admin` 是否处于 `active` 状态

原因：

- `/admin/matches` 当前只要求管理端身份即可读
- 如果连最小 admin 账号都不成立，就没有约球后台 staging 验收基础

### 2.2 约球后台页 SQL 读链前提

检查以下必需表是否存在：

- `match_users`
- `match_posts`
- `match_registrations`
- `match_bookings`
- `match_fee_records`
- `match_fee_splits`
- `match_operation_logs`

原因：

- `/admin/matches` 的最小后台页读链依赖这些表
- 缺表时，约球后台 staging 验收没有意义

### 2.3 仅作辅助观察的可选表

只报表，不作为当前最小失败条件单独升级：

- `match_attendance`
- `match_replacements`

原因：

- 它们不是约球后台列表最小读链的第一前提
- 但后续扩大专项验收时仍应保留观察

---

## 3. 本入口明确不检查的内容

以下内容继续留在专项 / 人工 / 半自动验收，不进入本入口：

1. 小程序 staging 真接线
2. 真实约球写链联调
3. `match-court-finance` 财务桥真实写回验证
4. `tests/match-real-link.test.js`

原因：

1. 这些项目依赖更真实的 staging 数据与 SQL 写入前提
2. 当前批次目标是最小补口，不是扩成完整约球验收体系
3. 不允许把环境依赖强、写入风险高的链路硬塞进默认或最小 staging 门禁

---

## 4. 与现有门禁的关系

### 已在默认本地门禁覆盖的约球保护

- `tests/match-production-guard.test.js`
- `tests/match-login-preview-access.test.js`

这两项继续走：

- `npm test`
- `npm run gate:local`

### 当前新增专项入口不做的事

- **不接入 `gate:staging`**
- 不拉更多约球测试进默认门禁
- 不让 `tests/match-real-link.test.js` 进入默认 gate

---

## 5. 建议执行顺序

当线程或总领导需要做约球 staging 专项验收时，建议顺序：

1. `npm run gate:local`
2. `npm run staging:ensure-match-minimal:check`
3. 再决定是否继续做更重的专项 / 人工 / 半自动联调

---

## 6. 下一步触发条件

只有在以下条件满足后，再考虑下一步：

1. 默认总闸门稳定全绿
2. 总领导明确要求推进约球 staging 专项更深一层补口

下一步候选：

1. 评估是否接入 `gate:staging`
2. 评估是否补约球后台页真实浏览/接口探针
3. 评估是否建设约球 staging 专项样本数据
