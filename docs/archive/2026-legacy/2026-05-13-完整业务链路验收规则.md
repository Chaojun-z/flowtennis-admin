# FlowTennis 完整业务链路验收规则

> 日期：2026-05-13  
> 目标：把“不能只测单点，必须测完整业务链路”固化成仓库统一规则。  
> 适用范围：后续所有执行线程、功能改动线程、验收回执线程。  
> 优先级：低于用户当前最新明确指令，高于普通临时口头提醒。

---

## 1. 这份规则解决什么问题

当前反复出现的问题不是“线程偶尔忘测”，而是默认验收口径过低：

1. 只验证代码改了
2. 只验证保存按钮点了没报错
3. 只验证单个接口返回成功
4. 没验证完整业务动作是否真的闭环

本规则就是为了把验收口径统一成：

`不是看单点是否成功，而是看完整业务动作是否跑通。`

---

## 2. 什么叫单点测试

单点测试指的是只证明某个局部动作成立，但没有证明用户真实业务流程可用。

常见例子：

1. 表单点击保存提示成功，但没刷新验证
2. 接口返回 `200`，但页面重新进入后数据没回显
3. 权限字段勾选成功，但真实账号操作时仍然能看到不该看的内容
4. 单元测试通过，但真实页面动作没走通

单点测试可以作为辅助证据，但不能单独作为“已完成 / 已通过 / 可验收”的依据。

---

## 3. 什么叫完整业务链路验收

完整业务链路验收指的是：按真实业务动作，从入口操作到结果落地，再到回看验证，至少形成一个闭环。

判断标准不是“某个函数运行了”，而是：

1. 用户能操作
2. 系统能保存或生效
3. 结果能被重新读取
4. 再次进入时状态一致

如果中间任何一段没验证，默认视为链路未闭环。

---

## 4. 默认硬规则

### 4.1 表单类需求默认必须验 4 步

任何新增、编辑、配置、资料修改类需求，默认至少验证：

1. 能填
2. 能保存
3. 刷新后能看见
4. 再次进入能回填

说明：

1. “能填”是指页面输入过程可完成，不是只看字段渲染出来。
2. “能保存”是指真实提交动作成功，不是只看前端按钮变灰。
3. “刷新后能看见”是指重新拉取数据后结果仍存在。
4. “再次进入能回填”是指重新打开同一对象时，之前保存值能正确回显。

### 4.2 权限类需求默认必须验 3 步

任何角色、菜单、按钮、字段权限、页面可见范围类需求，默认至少验证：

1. 权限配置
2. 权限生效
3. 权限撤销后失效

说明：

1. “权限配置”是指后台或配置入口确实完成设置。
2. “权限生效”是指目标账号真实操作时权限符合预期。
3. “权限撤销后失效”是指取消权限后，原先可用动作必须确实不可用。

### 4.3 其它业务需求的统一口径

凡是不属于纯静态文案、纯样式、纯只读展示的小改动，只要涉及真实业务动作，都必须至少写清：

1. 起点动作是什么
2. 中间关键动作是什么
3. 最终结果在哪里验证
4. 回看或二次进入时如何确认状态没丢

---

## 5. 汇报“测试通过”时必须写什么

以后线程汇报“测试通过”，必须明确区分下面三类证据：

1. 代码测试通过
2. 接口测试通过
3. 页面实操通过

并且必须写清：

1. 测了哪些业务动作
2. 没测哪些
3. 哪些是脚本/单测/接口测试结果
4. 哪些是页面实操结果

禁止使用下面这种模糊汇报：

1. “已测试通过”
2. “基本没问题”
3. “应该可以验收”
4. “保存成功了所以可以了”

---

## 6. 哪些话不能说

在未完成完整业务链路验证前，禁止汇报：

1. 已完成
2. 已通过
3. 可验收

如果当前只能证明局部成立，必须老实写成下面这类口径：

1. 已完成代码修改，但未完成完整链路验证
2. 已通过单测/接口测试，但未完成页面实操闭环
3. 受环境或账号限制，以下步骤尚未验证

## 8. 最终执行口径

以后本仓库默认口径统一为：

1. 单点测试不是验收通过
2. 代码改到不等于业务跑通
3. 完整业务动作闭环才叫完成验证
4. 没闭环就不能报“已完成 / 已通过 / 可验收”
