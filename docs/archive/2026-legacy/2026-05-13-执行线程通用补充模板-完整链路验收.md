# FlowTennis 执行线程通用补充模板（完整链路验收）

> 用途：给总领导或分派线程的人直接复制，避免每次重复手打“不要只测单点，要测完整链路”。  
> 日期：2026-05-13

---

## 最短可复制版

```text
本线程必须遵守完整业务链路验收规则，不得把单点测试当成验收通过。

默认要求：
1. 表单类需求必须验证：能填、能保存、刷新后能看见、再次进入能回填。
2. 权限类需求必须验证：权限配置、权限生效、权限撤销后失效。
3. 汇报“测试通过”时必须写清：测了哪些业务动作、没测哪些、属于代码测试通过还是页面实操通过。
4. 未完成完整业务链路验证，不得汇报“已完成 / 已通过 / 可验收”。

开工前先阅读：
1. AGENTS.md
2. docs/2026-05-13-完整业务链路验收规则.md
3. docs/2026-05-13-统一验收回执模板.md

结束时必须按统一验收回执模板提交结果。
```

## 标准版

```text
你这条线程除了本任务本身，还必须遵守 FlowTennis 仓库里的“完整业务链路验收规则”。

硬要求如下：

1. 不能把“代码改到了 / 按钮点通了 / 接口返回成功了”当成验收通过。
2. 只要任务触达真实业务动作，默认必须按完整业务闭环验证。
3. 表单类需求默认必须验 4 步：
   - 能填
   - 能保存
   - 刷新后能看见
   - 再次进入能回填
4. 权限类需求默认必须验 3 步：
   - 权限配置
   - 权限生效
   - 权限撤销后失效
5. 线程汇报“测试通过”时，必须明确写：
   - 测了哪些业务动作
   - 没测哪些
   - 哪些是代码测试 / 接口测试
   - 哪些是页面实操验证
6. 如果没有完成完整业务链路验证，不得汇报：
   - 已完成
   - 已通过
   - 可验收
7. 如因环境、账号、权限、样本限制导致无法验完，必须明确写阻塞项和未验证项。

本线程开工前先阅读：
1. AGENTS.md
2. docs/2026-05-13-完整业务链路验收规则.md
3. docs/2026-05-13-统一验收回执模板.md

本线程结束时，必须按统一验收回执模板交付验收结果。
```
