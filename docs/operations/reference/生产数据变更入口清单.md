# FlowTennis 生产数据变更入口清单

> 版本：2026-05-10  
> 目标：列清当前仓库内所有可能改动线上数据的入口，方便技术负责人建立发布、修复、审批、隔离机制。  
> 适用范围：`api/index.js`、`scripts/*`、启动初始化逻辑、约球同步逻辑。

---

## 1. 先看结论

当前线上数据不是只有“后台点保存”这一条写入口。

至少有 4 大类入口会改动真实数据：

1. 管理后台 API
2. 服务启动 / 初始化 / 自修复逻辑
3. 本地或服务器手工执行的修复 / 导入脚本
4. 其他业务域的联动写入

这就是为什么：

- 口头说“没碰财务”
- 实际线上财务还是变了

因为很多改动不是在“财务页面”发生，而是在：

- 课包写入
- 权益重算
- 排课扣课
- 订场历史修复
- 会员订单修复
- 启动时 bootstrap / repair

这些地方发生。

---

## 2. 风险分级说明

为了方便技术负责人快速判断，这里按 4 个等级分：

### `P0`

高危。默认就可能影响生产核心数据，或者影响面极大。

### `P1`

中高危。需要管理员操作，但会改动核心业务表。

### `P2`

中危。主要是常规业务写入，但会触发联动。

### `P3`

低危。一般是辅助写入、配置写入、单域写入。

---

## 7. 建议立刻建立的机制

### 7.1 发布机制

- 生产环境禁止 bootstrap / repair 自动写入
- 功能发布前必须跑财务快照对比
- 发布完成后必须跑核心数值验收

### 7.2 脚本机制

- 所有脚本默认 `dry-run`
- 写入前必须显式 `--write`
- 写入脚本必须带输出报告
- 写入脚本从主仓库挪到 `ops/` 独立目录

### 7.3 权限机制

- 财务相关写入口单独审批
- 会员修复脚本与教学修复脚本分流

---

## 8. 技术负责人一句话结论

当前生产数据写入口过多，而且很多不是通过“正常后台页面保存”发生的。  
如果不先把这些入口分级、关闸、隔离，后面无论怎么改功能，都会继续反复出现：

- 上线误伤数据
- 财务口径漂移
- 分支难合并
- 修一次好几天
