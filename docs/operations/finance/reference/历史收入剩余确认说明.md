# 历史收入剩余确认说明

## 结论

下一步主要还是我做。

你不需要写代码，也不需要自己导数据。你只需要在我整理出来的确认清单里，对系统不敢自动判断的历史记录做业务判断。

---

## 我接下来要做什么

1. 生成剩余确认清单
   - 把还没自动导入的历史收入分成两类：
     - 批量确认：系统大概知道是什么，但需要你确认规则。
     - 人工确认：系统看不出来，需要你判断。

2. 把清单做成人能看懂的格式
   - 每行保留原 Excel 信息：
     - 日期
     - 时间
     - 客户
     - 收入类型
     - 支付方式
     - 应收
     - 实收
     - 差价说明
     - 收款人
     - 备注
   - 同时给出系统建议。

3. 你确认后，我负责导入
   - 我会把确认结果转成系统记录。
   - 写入财务流水、课包流水、储值消费或审计留痕。
   - 导入后继续跑财务核查。

4. 最终目标
   - `npm run audit:financial` 继续保持 0 问题。
   - 实收、确认收入、待确认收入、课包余额、储值余额全部对上。

## 你需要做什么

你只需要看我后面给你的确认清单，按行或按组判断：

| 你要判断的问题 | 示例 |
|---|---|
| 这笔钱到底是什么业务 | 订场 / 私教课 / 小班 / 体验课 / 大众点评券 / 其他 |
| 这笔是不是已经收钱 | 微信收款 / 小程序 / 大众点评 / 储值扣款 / 免费 |

| 如果是免费、赠送、资源置换，是否只留痕不确认收入 | 是 / 否 |
| 如果系统匹配错了，你告诉我正确对象 | 改成某某学员 / 某某会员 |

你不需要回忆所有 1427 行。

已经自动处理的第一批已经完成并核查通过。你只需要看剩下系统不能 100% 确定的部分。

## 你确认时必须给我的内容

为了避免二次返工，我给你的清单不会只问一句“这是什么”。每条需要你确认的记录，我都会要求你按下面字段回答。

### A. 每条都必须确认

| 字段 | 你要回答什么 | 可选答案示例 |
|---|---|---|
| 业务归类 | 这笔到底属于什么业务 | 订场 / 私教课 / 小班课 / 体验课 / 大众点评券 / 储值充值 / 其他 |
| 收款口径 | 这笔是否真的收到钱 | 已收现金/微信/支付宝/小程序 / 大众点评已收 / 储值扣款 / 课包划扣 / 免费无收入 / 待补款 |
| 收入确认 | 这笔是否应该算历史收入 | 确认收入 / 只留痕不确认收入 / 暂不导入 |
| 关联对象 | 这笔应该挂到谁身上 | 学员姓名 / 订场会员姓名 / 临时历史客户 |
| 备注是否保留 | 原表备注是否有特殊含义 | 保留原备注 / 补充说明 |

### B. 如果是课包划扣，必须额外确认

| 字段 | 你要回答什么 |
|---|---|
| 学员是谁 | 必须明确到系统里的学员 |
| 扣哪个课包 | 如果学员有多个课包，必须说明扣哪个 |
| 扣几节 | 一般是 1 节；如果不是 1 节，要写清楚 |
| 是否正常扣费 | 正常扣课 / 免费上课不扣课 / 补偿课不扣课 |

### C. 如果是储值扣款，必须额外确认

| 字段 | 你要回答什么 |
|---|---|
| 订场会员是谁 | 必须明确到系统里的订场用户/会员 |
| 扣哪个储值账户 | 如果有 8 折/9 折或多个账户，要说明 |
| 扣款金额 | 按表里实收扣 / 需要改金额 |

### D. 如果是大众点评 + 微信补差，必须额外确认

| 字段 | 你要回答什么 |
|---|---|
| 大众点评券类型 | 体验课 / 订场券 / 小班券 / 其他 |
| 大众点评券金额 | 平台券对应多少钱 |
| 微信补差金额 | 微信另外补了多少钱 |
| 服务类型 | 课程 / 订场 / 小班 / 其他 |

### E. 如果是免费、赠送、资源置换、内部占用，必须额外确认

| 字段 | 你要回答什么 |
|---|---|
| 是否确认收入 | 一般选“不确认收入，只留痕” |
| 是否扣权益 | 扣课包/扣储值 / 不扣任何权益 |
| 原因 | 赠送 / 补偿 / 教练迟到 / 资源置换 / 内部占用 / 其他 |
