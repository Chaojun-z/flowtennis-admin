# 发布前自动门禁升级方案

> 审计日期：2026-06-14  
> 范围：只设计发布前门禁，不修改 CI，不修改 `package.json`，不降低测试断言。

## 1. 结论

当前已有 CI 门禁，但还不能真正阻断发布事故。

现状是：

1. `.github/workflows/ci-guard.yml` 只跑：
   - `npm test`
   - `npm run guard:finance`
2. `npm run guard:finance` 已能锁住固定财务基线 5 个数：
   - 总收入
   - 课包收入
   - 订场收入
   - 会员储值
   - 成交笔数
3. 当前没有独立的 release guard 命令。
4. 当前没有纳入 CI 的真实接口冒烟。
5. `tests/` 目录有 153 个 `.test.js`，但 `npm test` 只串了 93 个，仍有 60 个没有进入默认门禁。

所以发布前门禁应升级为：

```bash
npm test
npm run guard:finance
npm run guard:api-smoke
```

其中 `guard:api-smoke` 是后续新增命令，专门做 staging 或指定环境的只读接口冒烟。

## 2. 已审计文件

### 2.1 `package.json`

现有脚本：

```json
{
  "dev": "node scripts/dev-server.js",
  "test": "node tests/... 串行执行 93 个测试",
  "guard:finance": "node scripts/finance-regression.js",
  "snapshot:finance": "node scripts/create-finance-daily-snapshot.js",
  "validate:finance-operation": "node scripts/validate-finance-operation.js",
  "verify:finance-page": "node scripts/verify-finance-page-authenticated.js",
  "db:migrate:match": "node scripts/migrate-match-db.js",
  "test:match-real": "node tests/match-real-link.test.js"
}
```

问题：

1. 没有 `guard:release`。
2. 没有 `guard:api-smoke`。
3. `test:match-real` 没进 `npm test`，也没进 CI。
4. 部分高价值测试文件没有被 `npm test` 执行。

### 2.2 `.github/workflows/ci-guard.yml`

当前 CI：

```yaml
Run critical tests: npm test
Finance regression guard: npm run guard:finance
```

优点：

1. 已接入真实财务门禁。
2. 已禁止财务门禁退回占位步骤。
3. CI 使用 `TZ: Asia/Shanghai`。

缺口：

1. 没有接口冒烟。
2. 没有 release guard 汇总命令。
3. 没有 staging 发布前检查。
4. 没有明确检查线上 `/api/diag` 或 staging 目标实例。

### 2.3 `npm run guard:finance`

实际脚本：`node scripts/finance-regression.js`

读取：

1. `config/finance-baseline.v2.json`
2. `fixtures/finance/finance-regression-snapshot.v2.json`

当前锁定值：

| 指标 | 基线 |
|---|---:|
| 总收入 | 978638 |
| 课包收入 | 644600 |
| 订场收入 | 255038 |
| 会员储值 | 79000 |
| 成交笔数 | 1042 |

结论：

1. 这是固定代码门禁基线，不代表当天真实线上经营收入。
2. 它能防止财务算法和聚合口径被代码改坏。
3. 它不能替代线上接口冒烟、每日经营快照、真实页面验收。

### 2.4 当前是否有接口冒烟

没有纳入 release guard 的真实接口冒烟。

已有相关测试主要是源码断言或规则测试，例如：

1. `tests/match-api.test.js`：检查约球 API 规则、路由和源码结构，不是真实 HTTP 冒烟。
2. `tests/page-data-requirements.test.js`：检查前端 page-data 依赖配置，不是真实接口请求。
3. `tests/hot-table-cache.test.js`：检查 API 读取路径和缓存策略，不是真实接口请求。
4. `tests/api-error-path.test.js`：检查前端请求错误信息，不是真实接口请求。
5. `tests/match-real-link.test.js`：是真实数据库集成链路，但单独挂在 `test:match-real`，未进入 `npm test` 和 CI，且会写入测试数据，不适合作为默认只读发布冒烟。

## 3. 最小 release guard 命令组合

### 3.1 当前可立即使用的最小组合

在不改 `package.json` 的前提下，发布前手工执行：

```bash
npm test
npm run guard:finance
node tests/page-data-requirements.test.js
node tests/production-read-path-hotfix.test.js
node tests/memberships-page-data-regression.test.js
node tests/coach-page-data-hotfix.test.js
node tests/column-projection-read-path.test.js
node tests/permissions-rules.test.js
node tests/public-bypass-entry.test.js
node tests/full-refresh-guard.test.js
node tests/dataset-overwrite-guard.test.js
node tests/perf-regression-guard.test.js
```

这些补充测试当前没有进入 `npm test`，但和事故阻断直接相关。

### 3.2 后续应落地的标准组合

后续应新增一个统一命令：

```bash
npm run guard:release
```

内部顺序：

```bash
npm test
npm run guard:finance
npm run guard:api-smoke
```

设计原则：

1. `npm test` 管代码规则、页面结构、业务规则。
2. `npm run guard:finance` 管固定财务 5 数。
3. `npm run guard:api-smoke` 管真实接口是否能登录、能返回 JSON、无关键 `401 / 404 / 500`。

## 4. 哪些失败必须阻断发布

以下失败必须直接阻断发布：

1. `npm test` 任一测试失败。
2. `npm run guard:finance` 任一财务基线数字漂移。
3. CI workflow 没有真实执行 `npm test`。
4. CI workflow 没有真实执行 `npm run guard:finance`。
5. 接口冒烟登录失败。
6. `/api/diag` 返回的目标环境不是本次发布目标。
7. 任一必测接口返回 `500`。
8. 任一必测接口返回非 JSON。
9. 受保护接口在携带有效管理员 token 后仍返回 `401 / 403`。
10. 任一核心页面聚合接口返回 `404`。
11. `/api/page-data/finance` 缺少 `financeOverviewData`、`financeNormalizedRows`、`financeSettlementRows`。
12. `/api/page-data/courts` 缺少 `courts` 或 `students`。
13. `/api/page-data/memberships` 缺少 `membershipAccounts`、`membershipOrders`、`membershipBenefitLedger`。
14. `/api/page-data/purchases` 缺少 `purchases`、`entitlements`、`entitlementLedger`。
15. 约球后台接口 `/api/admin/matches` 返回挂起、非 JSON、`500` 或权限异常。
16. 检测到生产环境默认开启 bootstrap / repair 类高危写入。

不得用“本地能打开页面”替代这些阻断条件。

## 5. 哪些接口需要冒烟

接口冒烟只做只读请求，不写业务数据。

### 5.1 公共诊断接口

| 接口 | 目的 | 阻断条件 |
|---|---|---|
| `GET /api/diag` | 确认环境、TableStore 目标实例 | 非 JSON、500、目标实例不匹配 |
| `GET /api/match-diag` | 确认约球数据库诊断接口可用 | 非 JSON、500、泄露敏感连接串 |

### 5.2 登录接口

| 接口 | 目的 | 阻断条件 |
|---|---|---|
| `POST /api/auth/login` | 确认管理员能登录并拿 token | 401、403、500、无 token |

账号密码必须来自 CI/Vercel Secret，不得写进代码或文档。

### 5.3 管理后台核心 page-data

| 接口 | 目的 | 必查字段 |
|---|---|---|
| `GET /api/page-data/finance` | 财务总览、收入流水、已入账流水 | `financeOverviewData`、`financeNormalizedRows`、`financeSettlementRows` |
| `GET /api/page-data/courts` | 订场用户首屏与累计消费 | `campuses`、`students`、`courts` |
| `GET /api/page-data/memberships` | 会员账户、订单、权益流水 | `membershipAccounts`、`membershipOrders`、`membershipBenefitLedger` |
| `GET /api/page-data/purchases` | 购买、权益、核销流水 | `purchases`、`packages`、`students`、`entitlements`、`entitlementLedger` |
| `GET /api/page-data/plans` | 学习计划和课包关系 | `students`、`classes`、`plans`、`schedule`、`entitlements` |
| `GET /api/page-data/workbench` | 教练工作台 | `students`、`classes`、`schedule`、`feedbacks`、`stats` |
| `GET /api/page-data/coaches` | 教练列表轻接口 | `coaches` |

### 5.4 高频普通接口

| 接口 | 目的 |
|---|---|
| `GET /api/students` | 学员列表快路读取 |
| `GET /api/schedule` | 排课列表 |
| `GET /api/courts` | 订场用户列表 |
| `GET /api/purchases` | 购买记录 |
| `GET /api/entitlements` | 课包余额 |
| `GET /api/membership-accounts` | 会员账户 |
| `GET /api/membership-orders` | 会员订单 |

### 5.5 约球接口

| 接口 | 目的 |
|---|---|
| `GET /api/admin/matches` | 约球后台列表 |
| `GET /api/admin/matches/settings` | 约球配置 |
| `GET /api/admin/matches/finance-daily?date=<当天>` | 约球财务日报 |

## 6. 哪些测试应该进入 release guard

### 6.1 必须保留的现有默认测试

`npm test` 里的现有 93 个测试应全部保留，不降低断言。

其中必须继续作为阻断项的重点包括：

1. 财务：`finance-*`、`court-finance.test.js`
2. 课包权益：`entitlement-rules.test.js`、`package-*`、`purchase-drawer-view.test.js`
3. 排课：`schedule-*`
4. 订场：`court-*`
5. 会员：`membership-*`
6. 性能/读取路径：`hot-table-cache.test.js`、`page-load-strategy.test.js`
7. 生产安全：`init-production-safety.test.js`、`production-request-init-guard.test.js`
8. CI 自检：`ci-guard-workflow.test.js`

### 6.2 应补进 release guard 的现有测试

以下测试当前不在 `npm test`，但应进入 release guard：

```bash
node tests/page-data-requirements.test.js
node tests/production-read-path-hotfix.test.js
node tests/memberships-page-data-regression.test.js
node tests/coach-page-data-hotfix.test.js
node tests/column-projection-read-path.test.js
node tests/permissions-rules.test.js
node tests/public-bypass-entry.test.js
node tests/full-refresh-guard.test.js
node tests/dataset-overwrite-guard.test.js
node tests/perf-regression-guard.test.js
node tests/secondary-index-guard.test.js
node tests/court-account-guard-switches.test.js
node tests/court-account-read-model-guard.test.js
node tests/court-account-hidden-mode-performance-guard.test.js
node tests/login-timeout-hotfix.test.js
```

原因：

1. 它们覆盖生产读取路径、聚合接口、权限、缓存、性能和登录超时。
2. 这些正是历史事故高发区。
3. 它们是只读断言测试，适合进发布前门禁。

### 6.3 不建议直接放进默认 release guard 的测试

以下测试或脚本类测试不建议默认进入 release guard：

1. `tests/match-real-link.test.js`
2. 各类 `repair-*`、`apply-*`、`audit-*` 修数脚本测试

原因：

1. `match-real-link.test.js` 会连接真实或指定 Postgres，并写入/清理测试数据。
2. 修数类测试更适合独立运维门禁，不应混进普通功能发布。

但可以单独设计：

```bash
npm run guard:ops
npm run test:match-real
```

只在约球后端或运维修数发布时触发。

## 7. 后续实现优先级

### P0：先补真正接口冒烟

新增只读脚本：

```bash
node scripts/release-api-smoke.js
```

再挂成：

```bash
npm run guard:api-smoke
```

必须支持：

1. `RELEASE_GUARD_BASE_URL`
2. `RELEASE_GUARD_ADMIN_USER`
3. `RELEASE_GUARD_ADMIN_PASSWORD`
4. `RELEASE_GUARD_EXPECTED_TS_INSTANCE`

默认目标应为 staging，不应默认打生产。

### P1：新增统一 release guard 命令

新增：

```bash
npm run guard:release
```

内部串：

```bash
npm test
npm run guard:finance
npm run guard:api-smoke
```

CI 后续只调用 `npm run guard:release`，避免 CI 和本地发布前命令不一致。

### P2：把高价值漏测补进默认门禁

先补进和事故阻断直接相关的测试：

1. page-data 聚合接口结构
2. production 读取路径
3. 会员 page-data
4. 权限与 public bypass
5. 登录超时
6. 缓存和性能保护

### P3：区分普通发布、约球发布、运维修数发布

建议拆 3 类门禁：

```bash
npm run guard:release
npm run guard:match
npm run guard:ops
```

不要把写数据库的真实联调测试塞进普通发布默认门禁。

### P4：staging 发布后再做线上只读复核

发布到 staging 后，必须跑：

```bash
npm run guard:api-smoke
```

正式生产发布后，只允许跑只读复核：

1. `/api/diag`
2. `/api/page-data/finance`
3. `/api/page-data/courts`
4. `/api/page-data/memberships`
5. `/api/admin/matches`

不得在生产发布后自动执行写入类测试。

## 8. 最小落地版本

如果只做一个最小版本，建议这样落地：

```bash
npm test
npm run guard:finance
node tests/page-data-requirements.test.js
node tests/production-read-path-hotfix.test.js
node tests/memberships-page-data-regression.test.js
node tests/permissions-rules.test.js
npm run guard:api-smoke
```

这组能覆盖：

1. 已有业务规则。
2. 固定财务基线。
3. 生产读取路径。
4. 会员/财务/订场核心聚合接口结构。
5. 登录和真实接口是否可用。

这才算能阻断事故的发布前门禁。
