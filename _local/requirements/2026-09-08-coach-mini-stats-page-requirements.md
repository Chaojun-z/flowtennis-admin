# 教练端小程序「课时统计」页面需求文档

> 版本：v1.2（开发确认版）
> 日期：2026-09-08
> 来源：基于 WorkBuddy 需求稿整理，已按 FlowTennis 现有小程序 Tab、管理端统一口径和排课字段修订
> 交付对象：Codex 开发

---

## 1. 需求背景

教练端小程序目前已有 4 个底部 Tab：`工作台 / 我的课表 / 我的学员 / 我的班次`。

本次不新增第 5 个 Tab，而是把现有第 4 个「我的班次」替换为「统计」。

「统计」页面用于让教练快速查看自己在不同时间范围内的已完成课时：

1. 本周、本月、本年、全部时间分别上了多少课时。
2. 每天、每月、每年的课时变化趋势。
3. 不同课程类型的课时占比。
4. 可回看对应时间范围内的上课明细。

本页面只做统计展示，不新增排课、消课、反馈、课酬、收入等操作。

---

## 2. 页面入口与范围

### 2.1 页面入口

教练端小程序当前底部 Tab 保持 4 个：

1. 工作台
2. 我的课表
3. 我的学员
4. 统计

其中前 3 个 Tab 保持不动，只把第 4 个「我的班次」替换成「统计」。

页面标题：`统计`

开发约束：

1. 不新增第 5 个底部 Tab。
2. 不改变前 3 个 Tab 的文案、顺序和现有交互。
3. 原 `shifts / 我的班次` 入口废弃，替换为 `stats / 统计`。
4. 当前小程序是 `pages/schedule/schedule` 内部自定义 Tab，不是 `app.json` 原生 tabBar；实现时应按现有结构局部替换。

### 2.2 数据范围

只展示当前登录教练本人的上课记录。

教练识别必须复用系统现有教练匹配逻辑：

1. 优先匹配 `coachId`。
2. 兼容匹配 `coach / coachName`。
3. 教练姓名别名、是否带“教练”后缀，按现有 `sameCoachName / buildCoachRefs / getCoachScheduleRowsForUser` 口径处理。

禁止前端用姓名字符串自行筛选教练数据。

## 3. 统计口径

### 3.1 平台统一口径

本页面必须和管理端使用同一个课时统计口径。

权威来源：

1. 管理端教练工作台 / 教练相关统计中使用的已完成课时口径。
2. 后端排课有效状态口径 `effectiveScheduleStatus(schedule, now)`。
3. 全平台数据口径总表中的 `COACH_LESSON_HOURS`。
4. 后端共享读模型 `buildCoachCompletedLessonStats(...)`。

开发要求：

1. 小程序统计页不能自己重新解释“什么算已完成课时”。
2. 如现有函数未导出给新接口复用，应先抽出共享后端读模型，再让管理端和小程序共用。
3. 同一教练、同一时间范围下，小程序总课时必须等于管理端同口径结果。
4. 禁止出现“管理端一个数，小程序另一个数”的情况。

### 3.2 核心展示口径

页面只展示一个核心口径：`课时`。

不展示“共 X 节课”“上课节次”等第二口径，避免教练理解混乱。

### 3.3 总课时计算

总课时 = 当前筛选范围内所有有效上课记录的课时数求和。

单条记录课时数取值规则：

1. 优先按课程实际时长折算：`endTime - startTime` 换算小时数。
2. 如果已有管理端标准化课时字段 `durationHours / hours`，优先使用该标准化结果。
3. 如历史数据存在 `lessonCount` 且大于实际时长，按管理端兼容逻辑取较大值，避免老数据低估。
4. 如果时间和标准化课时都无法计算，则兜底为 `1`。

开发时应复用后端共享读模型 `buildCoachCompletedLessonStats(...)`，避免小程序前端重新写一套计算。

注意：

1. 本页统计的是教练课时量，不是排课记录数量。
2. 不能用 `list.length` 当总课时。
3. 管理端若调整课时计算规则，小程序应自动跟随共享口径变化。

### 3.4 有效上课记录

只统计已经完成的课程。

有效条件：

1. 排课没有取消。
2. 课程结束时间已经过去。
3. 系统有效状态为 `已结束` 或展示状态为 `已下课`。

必须复用现有 `effectiveScheduleStatus(schedule, now)` 状态口径。

不计入：

1. `已取消` 排课。
2. 未来课程。
3. 正在进行但尚未结束的课程。

### 3.5 与管理端其他口径的边界

管理端可能存在用于排班、产能、财务或课酬的其他指标。

本页面只绑定“教练已完成课时”口径，不绑定以下口径：

1. 排班占用课时。
2. 未来已排课课时。
3. 课酬结算课时。
4. 收入、已入账、未入账金额。
5. 班次总课时、班次剩余课时。

如果管理端页面名称或文案存在歧义，开发前以本 PRD 为准：本页统计的是教练本人已完成教学课时。

### 3.6 时间口径

按课程 `startTime` 所在日期归属统计周期。

周维度从周一开始，到周日结束。

日期比较使用后端统一计算结果，前端只展示后端返回的数据。

## 6. 时间维度与切换

### 6.1 时间维度

Tab 项：

1. 周
2. 月
3. 年
4. 全部

默认选中：`周`

切换 Tab 时：

1. 重置到当前周期。
2. 重新拉取总课时、类型列表、趋势图、明细。
3. 明细展开状态重置为默认状态。

### 6.2 日期范围显示

| 维度 | 范围文案 | 左右切换 |
|---|---|---|
| 周 | `2026.09.07 - 09.13` | 上一周 / 下一周 |
| 月 | `2026.09` | 上一月 / 下一月 |
| 年 | `2026` | 上一年 / 下一年 |
| 全部 | `全部时间` | 不显示左右箭头 |

到达未来边界时，右箭头置灰不可点。

### 6.3 自定义时间

本版不把「自定义」作为主流程。

如后续需要，可在统计页右上角增加筛选入口，但第一版先不做，避免页面变重。

## 7. 总课时卡片

展示当前筛选范围内的总课时。

示例：

```text
总课时
18 课时
私教课 10课时 · 小班课 4课时 · 体验课 2课时 · 其他 2课时
```

说明：

1. 大数字只展示课时。
2. 小字也展示课时，不展示节次。
3. 小字课程类型只做快速概览。
4. 课程类型课时相加必须等于总课时。

---

## 8. 课程类型列表

### 8.1 目标

让教练知道当前时间范围内主要上的是什么课。

### 8.2 展示方式

第一版使用类型列表，不做环形图、饼图或复杂图表。

优先保证：

1. 类型名称准确。
2. 课时数准确。
3. 占比准确。
4. 小屏不拥挤。
5. 与现有小程序卡片风格一致。

类型列表行格式：

```text
私教课   10课时   56%
小班课    4课时   22%
体验课    2课时   11%
其他      2课时   11%
```

### 8.3 课程类型口径

课程类型列表必须使用管理端教练统计同一归类口径。

第一版统计图和顶部概览只展示管理端同口径的粗分类：

1. 体验课
2. 私教课
3. 小班课
4. 专项课
5. 陪打
6. 其他

归类规则：

1. 后端复用管理端教练统计的 `normalizeCoachCourseType(row)` 口径。
2. `大师课` 按管理端现有口径归入 `小班课`。
3. `体验课 / 私教体验课`、`体验课 / 小班体验课` 在统计列表中统一归入 `体验课`。
4. `小班课 / 单次`、`小班课 / 训练营`、`小班课 / 随到随学`、`小班课 / 亲子课` 统一归入 `小班课`。
5. 如果管理端后续新增统一分类，小程序跟随后端返回，不在前端写死。

明细中可以展示更细的课程类型，但统计汇总必须按上面的管理端粗分类。

明细展示类型取值优先级：

1. `standardCourseType`
2. `courseTypeLabel`
3. `courseType`

不要在小程序前端自行归类课程类型。

### 8.4 类型颜色

颜色应与管理端排课页课程类型颜色保持一致。

如当前没有可复用配置，第一版可在后端返回 `color`，前端只消费后端颜色。

未知类型使用兜底色。

## 9. 课时趋势图

趋势图展示当前时间范围内的课时变化。

| 当前 Tab | 统计粒度 | X 轴 |
|---|---|---|
| 周 | 按天 | 周一到周日 |
| 月 | 按天 | 当月 1 日到最后一天 |
| 年 | 按月 | 1 月到 12 月 |
| 全部 | 按年 | 每一年 |

统计值统一为课时数。

全部时间规则：

1. 数据跨多年时，按年聚合。
2. 如果只有一年数据，按月聚合。

## 10. 上课明细

### 10.1 明细行格式

每条上课记录一行。

```text
14:00-15:00  王同学  顺义马坡 · 3号场  私教课
```

字段说明：

1. 时间：`startTime / endTime`
2. 学员：优先展示 `studentSummary`，其次 `studentName`
3. 地点：优先展示统一后的 `campusName + venueText`，校区外展示 `externalVenueName + externalCourtName`
4. 类型：展示统一课程类型
5. 课时：如明细中需要展示，只展示 `X课时`

### 10.2 明细分组

| 当前 Tab | 分组方式 | 默认状态 |
|---|---|---|
| 周 | 按日期分组 | 全部展开 |
| 月 | 按日期分组 | 全部展开 |
| 年 | 按月份分组 | 默认折叠 |
| 全部 | 按年份分组 | 默认折叠 |

分组标题右侧显示该组课时数，例如：

```text
9.08  3课时
```

或：

```text
2026年  128课时
```

禁止显示“X节”。

### 10.3 排序

明细默认按日期从近到远展示。

同一天内按上课开始时间从早到晚展示。

## 11. 数据接口建议

### 11.1 读模型要求

新增统计能力前，先建立或复用一个后端共享读模型。

建议命名：

```text
server/read-models/coach-completed-lesson-stats.js
```

读模型职责：

1. 接收排课、教练、用户、学员、校区等数据。
2. 按当前登录教练过滤。
3. 按管理端同口径过滤有效已完成课程。
4. 按管理端同口径计算课时。
5. 返回总课时、课程类型列表、趋势图、明细分组。

管理端和小程序后续如都要展示这个指标，应复用同一读模型，不能各自计算。

### 11.2 接口路径

建议新增：

```text
GET /page-data/coach-stats
```

原因：

1. 教练端小程序现有核心页面已使用 `/page-data/workbench`。
2. 统计页属于页面读模型，放在 `/page-data` 更符合现有项目结构。
3. 后端统一聚合，前端不要自行分页后再计算统计。
4. 接口内部必须调用共享读模型，不能在路由里临时拼统计逻辑。

### 11.3 请求参数

```text
view=week|month|year|all
startDate=YYYY-MM-DD
endDate=YYYY-MM-DD
page=1
pageSize=50
detailGroup=可选，展开年/月分组时使用
```

说明：

1. `week / month / year` 可由后端根据当前日期和偏移量计算，也可由前端传明确起止日期。
2. 第一版建议前端传明确 `startDate / endDate`，后端只负责校验和统计。
3. `all` 不传日期时代表全部已完成课程。

### 11.4 返回结构


### 11.5 对账要求

同一教练、同一日期范围，以下数据必须一致：

1. 小程序统计页总课时。
2. 管理端同口径教练已完成课时。
3. 后端共享读模型单测结果。

如果三者不一致，不允许上线。

## 12. 字段映射

### 12.1 排课来源

事实源：`ft_schedule`

后端应复用管理端已有排课口径和共享统计读模型，而不是直接把原始数据库字段丢给小程序。

### 12.2 关键字段

| 页面含义 | 优先字段 / 规则 |
|---|---|
| 排课 ID | `id` |
| 开始时间 | `startTime` |
| 结束时间 | `endTime` |
| 教练 | `coachId` + `coach / coachName`，按现有教练匹配 |
| 学员 | `studentSummary`，兜底 `studentName / studentNames` |
| 校区 | `campusName`，兜底 `campus` 转展示名 |
| 场地 | `venueText`，兜底 `venue` |
| 校区外地点 | `externalVenueName + externalCourtName` |
| 课程类型 | `standardCourseType`，兜底 `courseTypeLabel / courseType` |
| 汇总课程类型 | 管理端 `normalizeCoachCourseType(row)` 同口径 |
| 明细课程类型 | `standardCourseType`，兜底 `courseTypeLabel / courseType` |
| 课时 | 管理端已完成课时口径，当前复用 `buildCoachCompletedLessonStats(...)` |
| 状态 | `effectiveScheduleStatus(schedule, now)` |

## 13. 下拉刷新

启用小程序原生下拉刷新：

```json
{
  "enablePullDownRefresh": true
}
```

下拉刷新后：

1. 按当前筛选条件重新拉取统计页数据。
2. 刷新完成后调用 `wx.stopPullDownRefresh()`。
3. 明细展开状态重置为默认状态。

## 14. 空态与边界

### 14.1 无数据

当前范围无有效上课记录时：

1. 总课时显示 `0课时`。
2. 类型列表显示空态。
3. 趋势图显示空坐标或空态。
4. 明细显示 `该时间段暂无上课记录`。

### 14.2 小数课时

支持 `0.5` 这类小数课时。

展示规则：

1. 整数展示 `1课时`。
2. 小数最多保留 1 位，例如 `1.5课时`。

### 14.3 取消课

取消课不出现在总课时、类型列表、趋势图、明细中。

### 14.4 未来课

未来课不出现在统计页中。

如今天有一节课已经结束，另一节课还没结束，只统计已结束的那一节。

## 15. 第一版不做

为控制开发范围，第一版不做以下内容：

1. 不展示“上课节次”。
2. 不展示课时收入、薪酬、课酬。
3. 不做跨教练对比。
4. 不做运营端统计。
5. 不做自定义时间筛选。
6. 不做环形图、饼图或复杂图表点击钻取。
7. 不做导出。

## 16. 验收标准

1. 小程序底部仍然只有 4 个 Tab：`工作台 / 我的课表 / 我的学员 / 统计`。
2. 前 3 个 Tab 的文案、顺序、功能不变。
3. 原「我的班次」Tab 已替换为「统计」。
4. 统计页只展示当前登录教练本人的数据。
5. 周、月、年、全部切换后，总课时、类型列表、趋势图、明细全部联动刷新。
6. 总课时按管理端已完成课时同一口径计算。
7. 同一教练、同一日期范围，小程序总课时必须等于管理端同口径总课时。
8. 页面不出现“共 X 节课”“X节”等第二统计口径。
9. 已取消课程不计入任何模块。
10. 未结束课程不计入任何模块。
11. 课程类型列表使用管理端教练统计同一归类口径，不在前端写死。
12. 周/月趋势按天统计，年趋势按月统计，全部时间按年统计；只有一年数据时按月统计。
13. 明细中的学员、地点、课程类型、课时显示准确。
14. 年/全部明细默认折叠，展开后显示对应明细。
15. 下拉刷新可重新拉取数据，并恢复默认展开状态。

## 17. 开发提醒

1. 不要改动排课、权益、财务事实数据。
2. 不要新增独立业务口径。
3. 不要让小程序前端基于分页明细自行计算总课时。
4. 新增接口应放在现有 `api/index.js` 统一入口和 `server/page-data/` 结构下，不能新增 `api/*.js`。
5. 若管理端现有课时函数不方便复用，先抽共享读模型，再接小程序。
6. 需要补充最小测试，覆盖：
   - 第 4 个 Tab 替换为统计；
   - 前 3 个 Tab 不变；
   - 管理端同口径课时计算；
   - 取消课排除；
   - 未结束课程排除；
   - 当前教练数据隔离；
   - 课程类型按管理端同口径归类；
   - 小数课时展示；
   - 小程序结果与共享读模型结果一致。
